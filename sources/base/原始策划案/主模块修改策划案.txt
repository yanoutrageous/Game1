# 《灰尾回收 / 五四三二一》G5.1 模块修改策划案

## 黑币、物资、背包容量与结算规则 P1

> 文档定位：局内资产、背包容量、装备状态、消耗品、Buff、藏品、结算与规则接口的阶段性修改策划案
> 适用阶段：Godot G5.1 / RunInventory 与 Settlement P1
> 当前原则：不填写正式数值；本案只确定规则、字段、边界、接口和后续扩展方向
> 核心目标：建立一套可运行、可扩展、不过度耦合的搜打撤资产规则层

---

## 0. 修改背景

当前项目已经具备扫雷式地图、房间探索、宝箱、怪物、事件占位、撤离、结果展示等基础灰盒流程。后续如果继续直接增加事件、宝箱、战斗奖励和局外内容，很容易出现以下问题：

1. 每个房间自己写一套奖励规则；
2. 每个事件自己处理金币、物品、Buff、仓库；
3. 背包、仓库、失败结算和局外金币互相耦合；
4. 后续新增诅咒、托运、保险、抽奖、跨局 Buff 时需要大改旧逻辑；
5. “事件房”概念过大，难以承载商人房、诅咒房、抽奖房、规则房等具体玩法。

因此本阶段要做的不是单纯“背包系统”或“经济系统”，而是建立：

> **默认规则接口 + 可插拔特殊规则 + 局内资产账本 + 结算规则边界。**

---

## 1. 模块目标

### 1.1 当前阶段目标

本模块需要支持：

1. 黑币 / 金币二层货币；
2. 可扩展货币标识；
3. 物品独立化；
4. 背包容量与物品重量；
5. 装备穿戴 / 背包状态；
6. 消耗品当局清空；
7. 成功撤离全背包带出；
8. 失败按容量抢救；
9. Buff / Debuff 独立持续；
10. 藏品七档稀有度；
11. “唯一”档抽奖藏品；
12. 房间基础类型与 Encounter 内容拆分；
13. 默认规则接口与特殊规则接入机制；
14. 结算面板与仓库数据出口。

### 1.2 当前阶段不做

本阶段暂不做：

1. 正式数值平衡；
2. 完整装备强化；
3. 完整图鉴研究；
4. 遗物修复完整系统；
5. 黑市委托完整系统；
6. 大量抽奖池；
7. 高难地图门票；
8. 复杂动作战斗；
9. 真实美术迁移；
10. 完整商店经济平衡。

## 2. 最高设计原则：默认规则接口 + 特殊规则接入

### 2.1 原则说明

所有系统都应有一套默认规则。默认规则保证游戏在没有特殊事件、Buff、装备、地图规则时也能正常运行。

但默认规则不得写死为唯一规则。后续特殊事件、Buff、Debuff、装备、地图模式、房间内容、局外系统可以读取并改写默认结果。

### 2.2 默认规则示例

默认规则包括：

1. 开宝箱获得默认奖励；
2. 击败怪物获得默认战斗奖励；
3. 成功撤离时背包物品全部带出；
4. 失败时按失败容量抢救物品；
5. 黑币成功后转为金币；
6. 黑币失败默认丢失；
7. 消耗品本局结束清空；
8. Buff 按持续规则结算；
9. 装备穿戴时生效，不穿戴时占背包容量。

### 2.3 特殊规则示例

特殊规则可以来自：

1. 商人房；
2. 诅咒房；
3. 祭坛房；
4. 抽奖房；
5. 托运房；
6. 规则房；
7. Buff；
8. Debuff；
9. 装备；
10. 地图模式；
11. 局外保险；
12. 局外天赋；
13. 任务 / 委托。

特殊规则示例：

1. 某诅咒使宝箱奖励翻倍，但开箱增加压力；
2. 某保险提高失败抢救容量；
3. 某托运规则让指定物品无视失败容量带出；
4. 某装备降低藏品重量；
5. 某 Debuff 降低黑币转金币比例；
6. 某地图模式提高商人价格；
7. 某规则房让怪物掉落提高，但怪物强度提高。

## 3. 房间与 Encounter 修改

### 3.1 基础房间类型

地图层继续保留稳定基础房型：

1. 普通房；
2. 雷房；
3. 怪物房；
4. 宝箱房；
5. 事件类房；
6. 撤离房；
7. 出生点。

基础房型主要用于：

1. 地图生成；
2. 小地图显示；
3. 房间互斥；
4. 扫雷数字关系；
5. 基础图标；
6. 房间状态记录。

### 3.2 “事件房”定位修改

“事件房”不再作为最终具体房间名称，只保留为内部上层标签或旧文档兼容称呼。

后续具体内容应拆为：

1. 商人房；
2. 诅咒房；
3. 祭坛房；
4. 抽奖房；
5. 托运房；
6. 情报房；
7. 治疗房；
8. 规则房；
9. NPC 房；
10. 工作台房；
11. 研究房；
12. Boss 房。

### 3.3 Encounter 层

进入房间后触发的具体内容应由 Encounter 承载。

示例：

```text
room_type = event_like
encounter_type = merchant
tags = ["event_like", "merchant", "trade"]
```

```text
room_type = event_like
encounter_type = curse
tags = ["event_like", "curse", "high_risk"]
```

```text
room_type = chest
encounter_type = chest_basic
tags = ["loot", "container"]
```

### 3.4 房间与规则边界

房间不应直接写死复杂规则。

错误方向：

```text
宝箱房固定：开箱不加压力，只给物品。
```

推荐方向：

```text
开宝箱行为读取当前规则环境：
- 默认宝箱掉落规则；
- 当前地图 Modifier；
- 当前 Buff / Debuff；
- 当前诅咒；
- 当前装备效果；
- 当前事件链状态。
```

最终结果由当前规则环境共同决定。

## 4. 货币系统修改

### 4.1 货币类型

本案采用二层核心货币：

| 货币 | 定位              |
| -- | --------------- |
| 黑币 | 局内 / 封锁区非正式流通货币 |
| 金币 | 局外可流通货币         |

不再使用“待结算币 / 安全结算币 / 全局结算币”三币制。

### 4.2 黑币规则

黑币定位：

1. 局内获得；
2. 局内可消费；
3. 搜索、宝箱、怪物、部分事件可产出；
4. 成功撤离后按规则转为金币；
5. 失败时默认丢失；
6. 特殊规则可保护、转换、扣除或污染黑币。

黑币世界观解释：

> 黑币是封锁区内流通的非正式报酬凭证，未带出前不被公司认可。只有成功撤离或通过特殊渠道清洗后，才可转为可流通金币。

### 4.3 金币规则

金币定位：

1. 局外长期货币；
2. 可用于局外商店、保险、托运、初始消耗品、抽奖、外观、遗物修复、图鉴研究等；
3. 可被部分局内事件显式调用；
4. 普通搜索、普通宝箱、普通怪物不应稳定大量直接产出金币；
5. 特殊事件可以直接产出金币，但必须有明确限制、风险、次数或代价。

### 4.4 货币扩展接口

后续新增货币不应重写系统，而应作为货币标识扩展。

未来可能存在：

1. 黑市凭证；
2. 研究券；
3. 污染结晶；
4. 委托印记；
5. 抽奖券；
6. 特殊地图门票。

所有货币均应具有：

1. currency_id；
2. display_name；
3. scope；
4. can_gain_in_run；
5. can_spend_in_run；
6. can_persist_to_meta；
7. settlement_rule。

## 5. 物品系统修改

### 5.1 物品独立化

每个物品都是独立对象，不再把“零件”作为唯一物资。

物品至少需要以下规则字段：

1. item_id；
2. display_name；
3. item_type；
4. rarity；
5. weight；
6. value_state；
7. base_value；
8. tags；
9. can_sell；
10. can_store；
11. can_equip；
12. can_consume；
13. is_unique；
14. source；
15. visual_only。

### 5.2 物品大类

当前阶段建议支持：

1. 藏品 / 回收物；
2. 装备；
3. 消耗品；
4. 特殊物；
5. 抽奖外观 / 视觉藏品。

后续可扩展：

1. 任务物；
2. 样本；
3. 遗物；
4. 未鉴定物；
5. 诅咒物；
6. 黑市委托物；
7. 地图门票材料。

## 6. 背包容量规则

### 6.1 基础规则

局内背包采用容量制。

规则：

1. 背包有总容量；
2. 所有实体物品都有重量；
3. 黑币、金币、Buff、Debuff 不占背包容量；
4. 消耗品占背包容量；
5. 未穿戴装备占背包容量；
6. 已穿戴装备不占背包容量；
7. 藏品 / 回收物 / 特殊物按重量占容量；
8. 背包满时需要提示或进入处理流程。

### 6.2 背包满处理

当前 P1 可先采用：

```text
背包容量不足时，无法拾取，并显示提示。
```

后续再扩展：

1. 丢弃物品；
2. 替换物品；
3. 自动排序；
4. 按重量排序；
5. 按价值排序；
6. 标记保护物；
7. 低价值自动丢弃规则；
8. 特殊装备扩大背包容量。

---

## 7. 装备规则

### 7.1 装备状态

装备不区分“初始装备”和“局内获得装备”的基础作用。所有装备只根据当前状态处理。

| 状态  | 是否生效 | 是否占背包容量 |
| --- | ---: | ------: |
| 已穿戴 |    是 |       否 |
| 在背包 |    否 |       是 |

### 7.2 装备穿戴规则

规则：

1. 装备穿戴时生效；
2. 装备未穿戴时不生效；
3. 装备未穿戴时占背包容量；
4. 已穿戴装备不占背包容量；
5. 成功撤离时，已穿戴装备与背包装备均可带出；
6. 失败时，已穿戴装备与背包装备均进入失败抢救规则；
7. 特殊规则可保护装备、锁定装备、禁止卸下装备或改变装备重量。

### 7.3 装备扩展接口

后续可加入：

1. equipment_slot；
2. equip_group；
3. carry_group；
4. equip_effects；
5. cursed_equipment；
6. cannot_remove；
7. protected_on_failure；
8. break_on_failure；
9. insurance_allowed；
10. repair_required。

### 7.4 同类装备限制

后续可以设置：

1. 同类装备不可同时穿戴；
2. 同类装备不可同时携带；
3. 某类装备只能携带一个；
4. 某些装备互斥。

这些规则不应写死在装备系统里，应由装备标签和规则接口处理。

## 8. 消耗品规则

### 8.1 基础规则

所有消耗品均视为当局资源。

规则：

1. 消耗品可以从局外带入；
2. 消耗品可以在局内获得；
3. 消耗品占背包容量；
4. 消耗品使用后消失；
5. 无论成功撤离还是失败，未使用消耗品默认清空；
6. 消耗品默认不进入仓库；
7. 特殊规则可允许部分消耗品带回、转化、返还或保留。

### 8.2 设计目的

该规则用于：

1. 降低仓库复杂度；
2. 鼓励玩家在局内使用消耗品；
3. 让局外购买消耗品成为“本局投资”；
4. 避免玩家长期囤积药品和扫描道具；
5. 让消耗品与藏品 / 装备 / 回收物区分开。

---

## 9. Buff / Debuff 规则

### 9.1 基础规则

Buff 和 Debuff 统一视为状态效果。

规则：

1. Buff 可以是正面；
2. Debuff 可以是负面；
3. 每个 Buff / Debuff 独立存在；
4. 每个 Buff / Debuff 有自己的持续规则；
5. Buff / Debuff 默认不属于物资；
6. Buff / Debuff 默认不进入仓库；
7. Buff / Debuff 可以跨局；
8. Buff / Debuff 可以相互作用，但相互作用由事件或规则读取触发，不写死在 Buff 系统里。

### 9.2 持续类型

可预留以下持续类型：

1. current_run：仅当前局；
2. run_count：持续若干局；
3. trigger_count：触发若干次后消失；
4. until_removed：直到被指定事件移除；
5. permanent_flag：长期状态，慎用。

### 9.3 跨局 Buff 示例

示例仅表示规则，不代表数值：

1. 当前 Buff 持续 2 局，本局结束后剩余 1 局；
2. 某 Debuff 持续 3 局，每次进入商人房时影响交易；
3. 某 Buff 持续 1 局，下一局宝箱出现额外视觉提示；
4. 某诅咒直到进入研究房解除。

## 10. 藏品、稀有度与抽奖规则

### 10.1 藏品七档制

当前藏品稀有度由四档扩展为七档。

暂定结构：

| 档位 | 暂名 | 说明             |
| -: | -- | -------------- |
|  1 | 普通 | 常见藏品 / 回收物     |
|  2 | 良好 | 稍高价值藏品         |
|  3 | 稀有 | 稀有藏品           |
|  4 | 珍贵 | 高价值藏品          |
|  5 | 异常 | 与异常规则、图鉴或研究相关  |
|  6 | 传说 | 高难或稀有内容来源      |
|  7 | 唯一 | 抽奖或特殊来源，偏外观与收藏 |

名称后续可调整，本阶段只确定七档结构。

### 10.2 “唯一”档规则

唯一档暂定为最高档。

规则：

1. 暂名“唯一”；
2. 主要通过抽奖获得；
3. 可进入仓库；
4. 可进入图鉴；
5. 不可出售；
6. 不影响主线；
7. 不提供局内数值收益；
8. 不提供永久战斗成长；
9. 不作为主线、地图、任务、研究的必需条件；
10. 主要价值是视觉、收藏、展示和个性化。

### 10.3 抽奖规则

抽奖只提供藏品、外观、视觉特效类内容。

允许内容：

1. 服装；
2. 探索特效；
3. 走路特效；
4. 仓库展示物；
5. 头像 / 标识；
6. 图鉴收藏项；
7. 视觉类唯一藏品。

禁止内容：

1. 主线必需物；
2. 局内数值强化；
3. 永久战斗力提升；
4. 强制成长资源；
5. 影响地图通关的核心能力。

### 10.4 价值状态

“未判断价值”不作为稀有度档位，而作为价值状态。

预留 value_state：

1. known_value；
2. unknown_value；
3. unidentified；
4. no_market_value；
5. cursed_value；
6. appraisal_required。

该字段可用于后续鉴定、研究房、工作台房、商人估价、图鉴研究。

## 11. 成功撤离规则

### 11.1 基础规则

成功撤离时：

1. 背包内所有非消耗品进入仓库；
2. 已穿戴装备进入仓库或已拥有装备列表；
3. 未穿戴装备随背包进入仓库；
4. 藏品 / 回收物进入仓库；
5. 特殊物按自身规则进入仓库或结算；
6. 黑币按成功规则转为金币；
7. 金币直接保留；
8. 消耗品默认清空；
9. Buff / Debuff 按持续规则结算；
10. 抽奖唯一档进入仓库 / 图鉴，不可出售。

### 11.2 成功带出原则

成功撤离不需要选择带出容量。

成功撤离等于：

```text
背包全带出 + 已穿戴装备带出 + 黑币结算 + 金币保留。
```

### 11.3 特殊规则接入

特殊规则可改变成功结算：

1. 某诅咒导致部分黑币无法兑换；
2. 某托运规则让物品提前视为带出；
3. 某 Buff 让特定标签物品额外复制或转化；
4. 某 Debuff 让特定物品在撤离时破损；
5. 某地图规则降低黑币兑换比例。

这些规则必须通过规则接口读取，不应写死在成功结算本体里。

---

## 12. 失败结算规则

### 12.1 基础规则

失败时：

1. 黑币默认丢失；
2. 金币保留；
3. 消耗品默认清空；
4. Buff / Debuff 按持续规则结算；
5. 背包内非消耗品进入失败抢救池；
6. 已穿戴装备进入失败抢救池；
7. 玩家在失败容量内选择可保留物品；
8. 已保留物品进入仓库；
9. 未保留物品丢失；
10. 被托运或被保护物品按特殊规则处理。

### 12.2 失败容量

失败不再长期使用“保留 1 件”的规则，而采用容量规则。

基础描述：

```text
失败时，可在失败抢救容量内选择部分物品带回。
```

具体容量数值【数值待定】。

### 12.3 可抢救对象

默认可抢救：

1. 藏品；
2. 回收物；
3. 装备；
4. 特殊物；
5. 抽奖外观类物品；
6. 唯一档藏品。

默认不可抢救：

1. 消耗品；
2. 黑币；
3. 当前局临时 Buff；
4. 已触发的一次性效果。

特殊规则可改变可抢救对象。

### 12.4 特殊规则接入

失败结算可被以下规则影响：

1. 安全箱；
2. 托运；
3. 保险；
4. 装备保护；
5. 天赋；
6. 诅咒；
7. 地图模式；
8. 商人服务；
9. Buff / Debuff；
10. 局外系统。

示例：

```text
保险：失败容量增加。
托运：指定物品不占失败容量带回。
诅咒：装备无法进入失败抢救池。
特殊装备：失败时优先保护一个藏品。
```

## 13. 仓库规则

### 13.1 仓库定位

仓库用于保存成功撤离或失败抢救后留下的物品。

仓库不应只服务当前版本，还应为后续图鉴、研究、遗物修复、商店、任务、成就、黑市委托预留出口。

### 13.2 当前规则

当前阶段仓库至少需要记录：

1. item_id；
2. 数量；
3. 是否唯一；
4. 是否已图鉴登记；
5. 是否可出售；
6. 是否可装备；
7. 是否为外观；
8. 来源记录；
9. value_state；
10. tags。

### 13.3 当前阶段不做

当前阶段暂不做：

1. 完整仓库 UI；
2. 批量出售；
3. 装备强化；
4. 遗物修复；
5. 图鉴研究；
6. 黑市委托；
7. 藏品套装效果；
8. 高级筛选和排序。

但数据结构应预留后续接入。

## 14. 事件类房间与资产规则

### 14.1 事件类房间原则

事件类房间不再作为单一模块实现。

每个具体房间可以有自己的规则：

1. 商人房有交易规则；
2. 诅咒房有风险代价规则；
3. 祭坛房有献祭规则；
4. 抽奖房有外观抽奖规则；
5. 托运房有带出保护规则；
6. 情报房有扫描和信息规则；
7. 规则房有本局 Modifier 规则。

### 14.2 共享规则

具体事件房间不互相耦合，但共享资产语义：

1. 黑币；
2. 金币；
3. 物品；
4. 背包容量；
5. 装备状态；
6. 消耗品；
7. Buff / Debuff；
8. 仓库；
9. 失败容量；
10. 结算日志。

### 14.3 事件结果要求

每个事件选项必须明确：

1. 消耗什么；
2. 产出什么；
3. 是否影响黑币；
4. 是否影响金币；
5. 是否影响物品；
6. 是否影响背包；
7. 是否影响装备；
8. 是否影响 Buff / Debuff；
9. 是否影响压力；
10. 是否影响地图规则；
11. 是否影响结算；
12. 是否跨局持续。

## 15. 默认规则接口要求

### 15.1 行为读取规则

所有关键行为在结算前必须读取当前规则环境。

关键行为包括：

1. 搜索；
2. 开宝箱；
3. 击败怪物；
4. 进入事件类房间；
5. 使用消耗品；
6. 装备穿戴 / 卸下；
7. 获得黑币；
8. 获得金币；
9. 获得藏品；
10. 抽奖；
11. 成功撤离；
12. 失败结算；
13. 仓库写入。

### 15.2 规则来源

规则来源包括：

1. 默认规则；
2. 当前房间 Encounter；
3. 当前事件选项；
4. 当前 Buff；
5. 当前 Debuff；
6. 当前装备；
7. 当前地图模式；
8. 当前局 Modifier；
9. 局外系统；
10. 任务 / 委托；
11. 后续 Mod / 编辑器内容。

### 15.3 禁止项

禁止：

1. 把特殊事件结果写死到房间类型中；
2. 把特殊装备规则写死到背包系统中；
3. 把抽奖逻辑写死到金币系统中；
4. 把失败保护写死到仓库系统中；
5. 让 UI 直接修改资产状态；
6. 让具体事件绕过日志和结算记录；
7. 让普通房间稳定大量直接产出局外金币。

## 21. 总结

本模块的核心不是单纯增加背包或金币，而是建立一套可扩展的搜打撤资产规则层。

最终设计原则是：

> 默认规则保证游戏可运行；
> 特殊规则提供后续扩展空间；
> 房间只提供触发入口；
> Encounter 承载具体内容；
> 资产语义保持统一；
> 黑币、金币、物品、装备、消耗品、Buff、仓库和结算都允许被规则读取和改写，但不能被写死在单个房间或单个 UI 中。

该模块完成后，后续商人房、诅咒房、抽奖房、托运房、规则房、任务、图鉴、遗物修复和局外成长都能在不重构核心资产系统的前提下逐步接入。
