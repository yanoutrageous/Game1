\# 《灰尾回收 / 五四三二一》物品资产模型与内容映射规则策划案



\## 规则层草案 v0.1



> 文档定位：定义游戏中“通用资产、实体物品、外观解锁、记录解锁”的底层边界，明确物品主类型、物品规则字段、资产事件流通、系统映射关系。

> 适用范围：仓库、出发探索、结算报告、历史战绩、图鉴、研究、抽奖、任务、委托、藏品展示、失败抢救、物品流通。

> 当前原则：本案只定义底层资产与物品规则，不定义具体数值、概率、图标、美术、正式文案、具体物品清单。



\---



\## 0. 核心定位



物品不是仓库的附属内容，而是整个游戏的底层资产语言。



仓库、抽奖、任务、委托、结算、历史战绩、图鉴、研究、出发探索都不应各自定义一套物品规则。它们应读取同一套底层资产模型，并通过事件驱动完成资产流通。



核心原则：



```text

1\. 仓库只读取当前拥有物，不定义物品本体。

2\. 物品通过资产事件流通，不由各系统直接互相写入。

3\. 通用资源、实体物品、外观解锁、记录解锁必须分开。

4\. Policy 决定规则，Tag 只辅助筛选、展示、跳转和记录。

5\. 默认规则稳定存在，特殊规则通过接口接入。

6\. 各系统可通过资产、事件、跳转发生关联，但不互相嵌入功能本体。

```



一句话定位：



> 物品系统负责定义“游戏中实体资产是什么，以及它们如何在各系统之间流通”。



\---



\## 1. 资产与物品的边界



游戏中玩家可以获得、消耗、解锁、记录、展示的内容统称为资产，但不是所有资产都是物品。



资产分为四类：



```text

通用资产 / 资源

实体物品

外观解锁

记录与功能解锁

```



\---



\## 2. 通用资产 / 资源



通用资产不是实体物品，不进入仓库，不占背包。



它们通常表现为账户数值、次数、凭证、经验、消耗额度或系统权限。



\### 2.1 当前通用资产范围



包括：



```text

黑币

金币

抽奖券

凭证

服务券

委托凭据

研究点 / 研究经验

资历经验

未来新增货币

未来新增局外资产

```



\### 2.2 黑币



黑币是局内 / 封锁区流通资源。



规则：



```text

局内获得。

成功撤离后按规则转化为金币。

失败时默认丢失。

特殊规则可以影响黑币保护、转化、部分保留或额外损失。

```



黑币不是仓库物品。



\### 2.3 金币



金币是局外通用资源。



规则：



```text

可由黑币成功带出转化获得。

可由任务、委托、成就、事件、补偿等来源获得。

可用于申领、服务、抽奖、商店等局外消耗。

```



金币不是仓库物品。



\### 2.4 抽奖券



抽奖券是局外资产，不是实体物品。



来源可以包括：



```text

金币主动转化

任务奖励

成就奖励

活动奖励

特殊补偿

```



用途：



```text

用于抽奖系统消耗。

不占背包。

不进入仓库。

不作为局内实体带入。

```



\### 2.5 凭证 / 服务券 / 委托凭据



这类内容按表现形式判断：



```text

若只是账户数值、次数、权限或消耗额度，则归入通用资产。

若是局内可获得、可带回、可丢失、可进入仓库的实体，则归入特殊物。

```



当前默认：



```text

服务券：通用资产。

委托凭据：通用资产。

特殊实体凭据：特殊物。

```



\### 2.6 研究相关资产



研究系统当前仅作为后续可扩展接口保留。



若未来存在“研究点 / 研究经验 / 研究货币”，且其无实体、不占背包、不进入仓库，则视为通用资产。



若未来存在“研究样本 / 异常材料 / 实体研究物”，且其可带回、可丢失、可入仓库，则视为特殊物。



注意：



```text

资历经验不能默认等同于研究资源。

回收资历和研究系统可以有关联，但不应完全绑定。

```



\---



\## 3. 实体物品



实体物品是可以进入仓库、背包、出勤配置、结算报告或历史战绩的对象。



当前主类型为：



```text

装备

消耗品

藏品

特殊物

```



不作为主类型的内容：



```text

唯一

外观

抽奖物

任务物

委托物

样本

未判断价值

图鉴条目

研究解锁

```



对应处理方式：



| 内容    | 推荐处理              |

| ----- | ----------------- |

| 唯一    | 藏品的一种特殊稀有档 / 特殊种类 |

| 外观    | 外观解锁，不进仓库物品分类     |

| 抽奖物   | 来源为抽奖，不是物品主类型     |

| 任务物   | 特殊物 + 任务相关标签      |

| 委托物   | 特殊物或藏品 + 委托来源     |

| 样本    | 特殊物 + 样本标签        |

| 未判断价值 | 预留识别状态，不作为当前玩法重点  |

| 图鉴条目  | 记录，不是物品           |

| 研究解锁  | 功能解锁，不是物品         |



\---



\## 4. 物品主类型



\### 4.1 装备



装备是可影响局内能力的实体物品。



默认规则：



```text

可进入仓库。

可带入出勤。

可装备。

已穿戴时生效。

已穿戴时不占背包。

在背包中不生效，且占背包。

成功撤离后带回仓库。

失败时进入抢救 / 丢失规则。

通常可出售，特殊装备例外。

可进入图鉴。

```



装备需要定义：



```text

装备部位

装备效果

是否可穿戴

是否占背包

穿戴后是否占背包

是否可出售

是否可抢救

是否进图鉴

```



当前暂不展开：



```text

耐久

随机词条

强化

改造

镶嵌

套装

品质成长

```



这些作为后续装备系统扩展接口保留。



\---



\### 4.2 消耗品



消耗品是局外影响局内的肉鸽投入资源。



默认规则：



```text

仓库中的消耗品表示局外补给库存。

可从仓库或申领系统加入出勤。

加入出勤后，进入本局并成为本局资源。

本局结束后默认全部清空。

局内获得的普通消耗品也在本局结束后默认清空。

特殊规则可以改变清空结果。

```



该规则的设计目的：



```text

让消耗品成为出发前投资与风险博弈。

带少了，局内压力更高。

带多了，未使用也可能被清空。

投入补给本身是一次出勤决策。

```



必须提示玩家：



```text

本局携带消耗品将在本局结束后默认清空。

```



结算报告中也应提示：



```text

本局携带消耗品已清空。

局内获得消耗品已清空。

特殊保留规则：有 / 无。

```



预留特殊保留接口：



```text

作业许可保留

服务保留

特殊容器保留

事件奖励保留

装备效果保留

特殊规则保留

```



建议字段：



```text

end\_run\_policy = 默认清空

preserve\_policy = 无 / 许可保护 / 服务保护 / 物品保护 / 特殊规则

```



\---



\### 4.3 藏品



藏品是长期收集物，也是局内带出后进入局外资产体系的重要物品类型。



默认规则：



```text

可进入仓库。

可进入图鉴。

在局内占背包重量。

默认不可带入下一局。

默认不可装备。

默认不可使用。

成功撤离后带回仓库。

失败时进入抢救 / 丢失规则。

普通藏品可出售。

唯一藏品不可出售。

普通藏品允许重复获得。

普通藏品现阶段允许堆叠。

```



普通藏品堆叠规则：



```text

仓库中可按数量堆叠显示。

堆叠用于减少管理复杂度，并支持出售操作。

堆叠不抹除历史来源记录。

```



例如：



```text

仓库：旧怀表 ×3

历史战绩：

\- 第 12 局带回旧怀表 ×1

\- 第 17 局带回旧怀表 ×2

```



\### 4.4 唯一藏品



唯一不是独立主类型。



唯一是藏品的一种特殊稀有档或特殊种类。



固定规则：



```text

唯一仍属于藏品。

唯一不可出售。

唯一可进入仓库。

唯一可进入图鉴。

唯一可进入收藏展示。

唯一可拥有特殊展示接口。

唯一可附属外观或展示内容。

唯一不提供局内数值收益。

唯一不作为主线必需内容。

唯一不作为地图、任务、通关硬门槛。

```



唯一数据表现：



```text

main\_type = 藏品

rarity = 唯一

sell\_policy = 不可出售

deploy\_policy = 不可带入

display\_policy = 可特殊展示

codex\_ref = 有

```



唯一重复获得 / 溢出补偿当前不展开，只预留接口：



```text

unique\_duplicate\_policy = 无 / 阻止重复 / 转化资源 / 转化抽奖券 / 转化特殊奖励

```



\---



\### 4.5 特殊物



特殊物是当前用于承载尚未稳定成独立主类型的实体规则物。



它是扩展接口，不是垃圾桶分类。



特殊物可能包括：



```text

任务相关物

样本

钥匙

异常碎片

事件物

研究材料

Boss 记录物

地图规则物

特殊凭据实体

未来新增物品类型的过渡形态

```



特殊物必须具备明确的：



```text

sub\_type

关联系统

policy

来源

用途

结算规则

```



例如：



```text

main\_type = 特殊物

sub\_type = 样本

related\_system = 研究

```



未来如果某类特殊物数量足够多、规则足够稳定，可以升级为独立主类型。



升级原则：



```text

如果仅是名称和分类变化，可由特殊物子类型升级为主类型。

如果默认规则发生变化，必须同步更新默认规则矩阵。

不能只改标签而忽略 policy。

```



\---



\## 5. 外观解锁



外观不进入仓库物品主类型。



外观建议独立为：



```text

CosmeticDefinition

CosmeticUnlock

```



规则：



```text

外观不占背包。

外观不进入出勤配置。

外观不提供局内数值。

外观不显示在仓库分类中。

外观由收藏 / 外观系统管理。

人物脚下小按钮进入外观配置。

唯一藏品可以附属解锁外观。

```



仓库中可以在对应藏品详情中显示：



```text

附属外观已解锁 → 前往外观配置

```



但仓库不管理外观穿戴。

\## 6. 记录与功能解锁



记录与功能解锁不是物品。



包括：



```text

图鉴条目

任务进度

成就

研究解锁

作业许可

历史战绩

回收资历

Buff / Debuff 记录

```



\### 6.1 图鉴



图鉴只查看，不提供能力。



图鉴读取：



```text

发现状态

拥有状态

触发状态

图鉴文案

世界观补充

```



图鉴不管理物品库存。



\### 6.2 研究



研究当前仅保留为后续功能解锁接口。



当前不定义具体研究玩法。



研究可以未来读取：



```text

研究点

研究经验

研究样本

功能解锁条件

特殊物关联

```



但研究不应默认等同于资历系统。



\### 6.3 作业许可



作业许可是可解锁 / 可启用的功能权限，不是物品。



它可以影响：



```text

出发探索可用项

本局规则

消耗品保留

情报服务

背包规则

撤离规则

事件选项

```



但不进入仓库。

\## 7. Policy 与 Tag



\### 7.1 Policy



Policy 是底层规则字段，用于决定真实行为。



建议包括：



```text

sell\_policy

deploy\_policy

equip\_policy

use\_policy

stack\_policy

settlement\_policy

end\_run\_policy

display\_policy

codex\_policy

research\_policy

duplicate\_policy

```



示例：



```text

sell\_policy = 不可出售

deploy\_policy = 不可带入

end\_run\_policy = 清空

settlement\_policy = 成功入仓 / 失败可抢救

```



\### 7.2 Tag



Tag 用于辅助展示、筛选、来源记录和跳转提示。



标签可以包括：



```text

唯一

任务相关

研究相关

图鉴相关

展示相关

抽奖获得

委托奖励

事件获得

Boss 掉落

可展示

不可出售

新增

未查看

已查看

已收藏

已锁定

```



原则：



```text

Policy 决定行为。

Tag 辅助查看。

状态记录当前拥有情况。

事件记录资产流通过程。

```



禁止仅靠标签决定核心规则。

\### 8.1 建议字段

```text
显示名称
```


\## 9. 物品实例层



物品定义不等于玩家当前拥有状态。



玩家拥有物品应使用：



```text

```



\### 9.1 实例 / 堆叠字段



```text

当前位置

是否锁定

是否加入出勤

耐久

绑定状态

```



其中耐久、随机词条、绑定状态当前仅为扩展字段，不作为当前核心玩法。



\### 9.2 当前位置



当前位置可以包括：



```text

仓库

已穿戴

出勤配置

本局背包

局内临时

已消耗

已丢失

已出售

已转化

```



\### 9.3 堆叠规则



当前建议：



```text

普通消耗品：可堆叠。

普通藏品：可堆叠。

装备：默认不堆叠，建议实例化。

唯一藏品：不按普通堆叠处理。

特殊物：视具体规则决定。

```

\## 11. 资产事件流通规则



资产流通应通过事件完成。



系统之间不应直接调用彼此的内部功能。



\### 11.1 事件分层



当前阶段不需要定义过细事件，但需要预留二级接口。



建议采用：



```text

一级事件类型

二级动作

来源系统

上下文

扩展载荷

```



一级事件类型：



```text

物品变化事件

资源变化事件

解锁 / 记录事件

```



二级动作：



```text

获得

消耗

丢失

转化

出售

入仓

清空

抢救

装备

卸下

加入出勤

移出出勤

解锁

完成

记录

```



来源系统：




\### 11.3 事件粒度原则



当前不必过细，但不能写死。



规则：



```text

当前使用一级事件 + 二级动作即可。

未来可把某些事件拆成独立二级接口。

```

\## 12. 资产流通示例



\### 12.1 抽奖获得唯一藏品



```text

玩家消耗金币或抽奖券

↓

抽奖系统生成结果

↓

资源变化事件：消耗金币 / 抽奖券

↓

物品变化事件：获得唯一藏品

↓

解锁事件：图鉴条目解锁 / 展示内容解锁 / 附属外观解锁

↓

仓库显示新增藏品

↓

图鉴显示新增条目

↓

收藏 / 外观系统显示新增展示内容

```



仓库不执行抽奖。



\---



\### 12.2 成功撤离带回藏品



```text

局内获得藏品

↓

成功撤离

↓

结算规则处理

↓

物品变化事件：藏品入仓

↓

资源变化事件：黑币转金币

↓

解锁事件：图鉴新增

↓

结算报告展示本局结果

↓

历史战绩保存当局快照

```



历史战绩不依赖当前仓库状态。



\---



\### 12.3 带入消耗品后结算清空



```text

局外消耗品加入出勤

↓

进入本局

↓

本局结束

↓

默认规则：清空未使用消耗品

↓

物品变化事件：消耗品清空

↓

结算报告提示清空结果

```



若存在特殊保留规则：



```text

特殊规则接入

↓

修改结算结果

↓

生成保留 / 入仓事件

```

\## 14. 内容映射表建议



物品内容不建议做成一张巨表。建议采用多 Sheet 表。



\### A. 物品定义主表



记录每个物品的静态定义。



\### B. 默认规则矩阵



记录装备、消耗品、藏品、特殊物的默认处理方式。



\### C. 标签字典



记录所有可用标签及含义。



标签类型：



```text

来源标签

功能关系标签

展示标签

管理状态标签

```



\### D. 系统映射表



记录每个系统读取哪些字段、不负责哪些功能。



\### E. 物品实例状态表



记录玩家当前拥有状态。

工程实现阶段再细化。



\### F. 资产事件表



记录资产变化事件。

工程实现阶段再细化。

\## 15. 禁止项



为避免后续系统混乱，明确禁止：



```text

1\. 不把唯一做成独立物品主类型。

2\. 不把外观放进仓库分类。

3\. 不把抽奖来源做成物品类型。

4\. 不把任务物默认做成主类型。

5\. 不把未判断价值做成完整系统，当前只保留识别状态。

6\. 不让仓库执行抽奖、研究、任务、委托、图鉴本体功能。

7\. 不让历史战绩依赖当前仓库状态。

8\. 不把所有规则都写成标签；核心规则必须是 policy。

9\. 不让任务、委托、抽奖直接改仓库 UI。

10\. 不让图鉴、研究、收藏展示重复持有物品数据。

11\. 不让消耗品默认带回，除非特殊规则明确保留。

12\. 不让特殊物成为无规则归属的垃圾桶分类。

```

\## 16. 当前已确认规则



```text

1\. 抽奖券是局外资产，不是物品。

2\. 服务券、委托凭据等若无实体，则视为局外资产。

3\. 研究相关内容当前仅作为接口保留。

4\. 研究资源若无实体，则归资产；研究样本若为实体，则归特殊物。

5\. 资历经验不能和研究资源完全绑定。

6\. 特殊物是占位型扩展主类型，未来可拆出新主类型。

7\. 消耗品带入后，本局结束默认全部清空。

8\. 消耗品可通过特殊规则保留，但默认不保留。

9\. 普通藏品允许堆叠，以支持出售和管理。

10\. 唯一藏品仍是藏品，不可出售，不按普通堆叠处理。

11\. 唯一溢出补偿暂不接入，只预留接口。

12\. 资产事件当前不必过细，但必须支持未来二级扩展。

```

\## 17. 最低验收标准



物品资产模型完成基础规则后，应满足：



```text

1\. 能区分通用资产、实体物品、外观解锁、记录解锁。

2\. 能定义装备、消耗品、藏品、特殊物四类实体物品。

3\. 能明确唯一属于藏品，不是独立主类型。

4\. 能明确外观不进入仓库物品分类。

5\. 能通过 policy 表达出售、带入、装备、使用、结算规则。

6\. 能通过 tag 支持筛选、展示、来源和跳转。

7\. 能区分物品定义和玩家物品实例。

8\. 能支持消耗品带入后默认清空。

9\. 能支持普通藏品堆叠与出售。

10\. 能通过资产事件记录获得、丢失、消耗、转化、入仓等流转。

11\. 能支撑结算报告与历史战绩。

12\. 能支撑仓库读取当前拥有物。

13\. 能支撑图鉴、研究、抽奖、任务、委托读取各自映射。

14\. 能支持默认规则 + 特殊规则接入。

15\. 能预留未来新增主类型、二级事件和特殊系统扩展。

```

\## 18. 待确认事项



后续仍需确认：



```text

1\. 稀有度正式分级。

2\. 是否所有藏品都有重量。

3\. 藏品堆叠上限。

4\. 普通藏品出售价格规则。

5\. 重复藏品是否有额外处理。

6\. 唯一藏品是否允许重复获得。

7\. 唯一重复获得的补偿规则。

8\. 特殊物的初始子类型清单。

9\. 样本是否未来会独立成主类型。

10\. 研究系统是否存在实体样本玩法。

11\. 研究点是否作为独立资源。

12\. 服务券 / 委托凭据是否全都按资源处理。

13\. 失败抢救容量如何计算。

14\. 保险 / 托运是否修改 settlement\_policy。

15\. 消耗品保留接口由哪些系统提供。

16\. 装备是否未来需要耐久。

17\. 装备是否未来支持随机词条。

18\. 历史战绩保留资产事件到什么粒度。

19\. 图鉴是否记录“曾经拥有”和“当前拥有”两种状态。

20\. 物品内容映射表是否先以 Excel / 多 Sheet 形式维护。

```

\## 19. 总结



当前物品资产模型的核心结论是：



```text

通用资产不是物品。

外观不是仓库物品。

图鉴和研究不是物品。

实体物品分为装备、消耗品、藏品、特殊物。

特殊物是可扩展占位主类型。

唯一是藏品的一种。

消耗品带入本局后默认清空。

普通藏品允许堆叠与出售。

资产通过事件流通。

各系统只读取自己的投影。

```



该模型建立后，可以支撑：



```text

仓库

出发探索

结算报告

历史战绩

图鉴

研究

抽奖

任务

委托

唯一藏品

失败抢救

消耗品清空

黑币转金币

未来新增货币与物品类型扩展

```
