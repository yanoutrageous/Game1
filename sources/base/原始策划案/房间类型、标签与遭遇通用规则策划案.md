# 《灰尾回收 / 五四三二一》房间类型、标签与遭遇通用规则策划案

## 独立策划案

---

## 0. 文档定位

本案用于定义局内地图中“房间”的基础类型、标签字段、行为策略、局内状态、遭遇挂接、掉落承载、特殊进入、重复触发与结算输出规则。

本案承接以下已确认系统：

1. 地图本体与生成规则；
2. 局内流程与状态流转规则；
3. 局内背包、掉落、丢弃、拾取、黑币与结算接口；
4. 出发探索中的本局配置；
5. 物品资产模型；
6. 结算报告；
7. 长期系统中的目标、图鉴、研究、资历、收藏等记录系统。

本案不讨论：

1. 具体事件文本；
2. 具体怪物数值；
3. 具体装备数值；
4. 具体消耗品数值；
5. 具体宝箱奖励表；
6. 具体商人商品表；
7. 具体美术表现；
8. 具体 UI 图标；
9. 具体按钮文案；
10. 具体音效和演出。

本案主要解决以下问题：

```text
1. 房间基础类型如何定义；
2. 标签字段如何接入房间、遭遇、物品等内容；
3. 标签与 Policy、State 的边界如何划分；
4. 房间与 Encounter 如何解耦；
5. 各基础房型默认如何触发、搜索、清理、掉落、回传；
6. 重复触发、重复奖励、重复推进目标如何避免混乱；
7. 房间处理结果如何统一输出给 RunResult；
8. 当前版本需要实现哪些，哪些只作为后续接口。
```

---

## 1. 总体设计原则

### 1.1 房间是地图节点

房间是地图上的基础节点，用于承载：

1. 地图生成；
2. 小地图显示；
3. 雷数计算；
4. 房间状态；
5. 是否可进入；
6. 是否可回传；
7. 是否已探索；
8. 是否已搜索；
9. 是否已清理；
10. 是否已耗尽；
11. 是否存在遭遇内容；
12. 是否存在地面掉落。

房间不直接负责长期仓库、长期图鉴、长期任务、长期研究等系统写入。

---

### 1.2 Encounter 是具体玩法内容

Encounter 是玩家进入或交互房间后真正处理的内容。

例如：

```text
怪物房 = 基础房型
具体怪物战斗 = Encounter

事件房 = 基础房型
商人 / 祭坛 / 规则房 / 回收终端 = Encounter

宝箱房 = 基础房型
普通宝箱 / 陷阱宝箱 / 条件宝箱 = Encounter

撤离格 = 基础房型
普通撤离 / 条件撤离 / 异常撤离 = Encounter
```

当前阶段采用：

```text
一个房间 = 一个基础房型 + 一个主要 Encounter
```

后续预留：

```text
附加 Encounter
隐藏 Encounter
条件 Encounter
连锁 Encounter
多阶段 Encounter
```

---

### 1.3 基础房型保持互斥

当前阶段，一个地图格子只拥有一个基础房型。

例如，一个格子不应同时是：

```text
雷房 + 宝箱房
怪物房 + 事件房
撤离格 + 宝箱房
```

后续若需要复合体验，应通过以下方式扩展：

```text
1. 标签；
2. Encounter；
3. 附加状态；
4. 条件触发；
5. 地图事件变更；
6. 高难 modifier；
7. 特殊规则房。
```

基础房型互斥可以降低以下系统复杂度：

1. 小地图显示；
2. 雷数计算；
3. 房间进入；
4. 回传判定；
5. 清理状态；
6. 掉落归属；
7. 结算记录；
8. 调试工具。

---

### 1.4 标签用于分类，Policy 决定行为，State 记录状态

本案采用四层结构：

```text
基础类型 Type：这个对象是什么；
标签 Tags：这个对象有什么可筛选、可匹配、可归类的特征；
策略 Policy：这个对象真实如何运作；
状态 State：本局内这个对象已经发生了什么。
```

例如：

```text
room_type = event

tags = [
  "function.trade",
  "function.sell",
  "repeat.repeatable",
  "system.designated_service"
]

policies = {
  repeat_interaction_policy = "repeatable",
  repeat_reward_policy = "transaction_based",
  sell_policy = "allowed",
  pressure_policy = "none_on_revisit"
}

state = [
  "explored",
  "available_for_interaction"
]
```

标签不能单独承担复杂行为判断。

例如，“重复”必须拆开：

```text
是否可重复交互；
是否可重复奖励；
是否可重复推进目标；
是否可重复生成掉落；
是否可重复增加压力。
```

## 2. 基础房型

当前阶段基础房型建议如下：

```text
出生点
普通房
雷房
怪物房 / 战斗房
宝箱房
事件房
撤离格
Boss 房
特殊规则房
```

### 2.1 出生点

出生点是本局开始房间。

规则：

1. 出生点本身不是雷房；
2. 出生点开局即为已探索；
3. 出生点可作为回传目标；
4. 出生点可显示雷数或基础地图信息；
5. 普通模式不保证出生点周围安全；
6. 普通模式不保证出生点到撤离点存在安全路径；
7. 教学、评委、特殊地图可启用额外保护规则。

建议标签：

```text
system.spawn
trigger.start
return.allowed
risk.safe_self
```

---

### 2.2 普通房

普通房是基础探索房间。

规则：

1. 可进入；
2. 可显示周围雷数；
3. 可搜索；
4. 可生成搜索收益；
5. 可承载普通掉落；
6. 默认搜索后进入已搜索或已耗尽状态；
7. 可作为回传目标；
8. 可作为路径节点。

建议标签：

```text
function.basic
function.search
reward.black_coin_source
system.path_node
```

默认 Policy：

```text
search_policy = "search_once"
repeat_interaction_policy = "none"
loot_policy = "search_generated"
return_policy = "allowed_after_explored"
```

---

### 2.3 雷房

雷房是核心风险房间。

规则：

1. 雷房计入扫雷数字；
2. 进入雷房时触发风险；
3. 触发后记录为已触发或已确认；
4. 雷房本身不作为普通收益房；
5. 雷房可能导致损失、失败、压力变化或特殊事件；
6. 雷房触发结果输出至 RunResult；
7. 雷房是否可在触发后搜索由后续具体规则决定。

建议标签：

```text
risk.mine
risk.high
trigger.enter
system.mine_counted
```

默认 Policy：

```text
entry_trigger_policy = "trigger_on_enter"
search_policy = "disabled_by_default"
repeat_interaction_policy = "once"
failure_policy = "by_mine_result"
return_policy = "by_room_state"
```

---

### 2.4 怪物房 / 战斗房

怪物房是战斗 Encounter 的入口。

规则：

1. 进入后触发或展示战斗 Encounter；
2. 进入后房间变为已探索；
3. 击败怪物后房间变为已清理；
4. 未清理状态下不建议作为可回传目标；
5. 已清理后可作为普通已探索房处理；
6. 默认怪物不刷新；
7. 特殊地图、事件、高难条件可改写刷新规则；
8. 战斗奖励进入 GroundLoot 或局内背包；
9. 怪物掉落不直接进入长期仓库。

建议标签：

```text
function.combat
risk.high
reward.monster_drop
codex.monster_related
objective.combat_related
```

默认 Policy：

```text
entry_trigger_policy = "trigger_on_enter"
clear_policy = "clear_after_victory"
repeat_interaction_policy = "once"
repeat_reward_policy = "once"
loot_policy = "monster_drop"
return_policy = "allowed_after_cleared"
```

---

### 2.5 宝箱房

宝箱房是收益房间。

规则：

1. 进入房间后显示宝箱或宝箱 Encounter；
2. 玩家交互后开启；
3. 宝箱默认只开启一次；
4. 宝箱奖励进入 GroundLoot 或局内背包；
5. 宝箱奖励不直接进入长期仓库；
6. 宝箱开启后进入已开启 / 已耗尽状态；
7. 宝箱可被事件、地图、难度、高难条件改写。

建议标签：

```text
function.loot
reward.item_source
reward.collection_source
repeat.once
trigger.interact
```

默认 Policy：

```text
entry_trigger_policy = "reveal_on_enter"
open_policy = "manual_interact"
repeat_interaction_policy = "once"
repeat_reward_policy = "once"
loot_policy = "generate_once"
search_policy = "optional_after_open"
```

---

### 2.6 事件房

事件房是所有事件类 Encounter 的基础承载。

事件类 Encounter 可包括：

```text
商人
回收终端
祭坛
规则房
治疗房
工作台
赌博 / 骰子事件
诅咒事件
撤离线索事件
地图变更事件
研究相关事件
托运 / 保险接口
抽奖接口
```

当前阶段，商人、回收终端、规则房等先归入事件房，通过标签和 Policy 区分，不单独作为基础房型。

规则：

1. 事件房进入后根据 Encounter 配置触发；
2. 事件可以一次性，也可以重复；
3. 是否重复交互由 Encounter Policy 决定；
4. 是否重复奖励由 Encounter Policy 决定；
5. 是否推进目标由 Encounter Policy 决定；
6. 事件结果可影响地图、背包、黑币、目标、压力、图鉴、掉落；
7. 事件结果必须写入 RunLog；
8. 地图变更必须写入 MapMutationLog。

建议标签：

```text
function.event
trigger.enter
trigger.interact
system.encounter_host
```

默认 Policy：

```text
entry_trigger_policy = "by_encounter"
repeat_interaction_policy = "by_encounter"
repeat_reward_policy = "by_encounter"
pressure_policy = "by_encounter"
loot_policy = "by_encounter"
```

---

### 2.7 撤离格

撤离格是成功结束本局的房间。

规则：

1. 撤离格可被发现；
2. 撤离格可被接入；
3. 撤离格进入可撤离状态后，玩家可确认撤离；
4. 撤离需要确认；
5. 撤离确认展示背包物、黑币、目标状态、消耗品清空提示；
6. 撤离后输出 RunResult；
7. 撤离成功后进入结算报告；
8. 撤离格是否存在条件、收费、限次、异常等变体，由后续接口扩展。

建议标签：

```text
function.evacuation
system.run_end
trigger.interact
objective.extract_related
```

默认 Policy：

```text
entry_trigger_policy = "reveal_on_enter"
evacuation_policy = "manual_confirm"
repeat_interaction_policy = "until_used"
reward_policy = "none"
settlement_policy = "success_on_confirm"
```

---

### 2.8 Boss 房

Boss 房作为独立基础房型预留。

规则：

1. Boss 房可视为高危战斗房的特殊类型；
2. Boss 房可有锁门规则；
3. Boss 房可拥有特殊进入条件；
4. Boss 房可推进主目标、高难目标、图鉴、成就；
5. Boss 房可拥有特殊掉落；
6. Boss 房完整规则后续单独展开。

当前版本可以只预留字段，不实现完整 Boss 流程。

建议标签：

```text
function.boss
function.combat
risk.extreme
objective.major_related
codex.boss_related
reward.rare_source
```

默认 Policy：

```text
entry_policy = "by_unlock_or_generation"
lock_policy = "special"
clear_policy = "clear_after_boss_victory"
return_policy = "by_boss_state"
```

---

### 2.9 特殊规则房

特殊规则房用于承载改变本局规则的房间。

可能效果包括：

1. 改变地图信息可信度；
2. 产生污染区；
3. 修改回传规则；
4. 修改搜索规则；
5. 修改雷数显示；
6. 修改事件触发；
7. 修改撤离条件；
8. 修改怪物刷新；
9. 修改掉落规则。

当前版本只作为预留房型。

建议标签：

```text
function.rule
system.map_modifier
risk.rule_change
trigger.enter
trigger.interact
```

默认 Policy：

```text
rule_modifier_policy = "by_encounter"
repeat_interaction_policy = "by_encounter"
map_mutation_policy = "record_required"
```

## 3. 标签系统 Tag Layer

### 3.1 标签系统定位

标签系统用于：

1. 内容分类；
2. 内容筛选；
3. 地图生成匹配；
4. UI 轻量展示；
5. 调试工具筛选；
6. 目标监听；
7. 研究需求；
8. 掉落池匹配；
9. 高难 modifier 选择；
10. 图鉴归类；
11. 仓库 / 申领筛选；
12. 后续内容扩展。

标签不是强行为规则本身。
真实行为由 Policy 决定。

---

### 3.2 标签适用对象

标签字段应预留给：

```text
房间
Encounter
装备
消耗品
藏品
特殊物
目标 / 委托
研究项目
图鉴条目
掉落池
奖励池
高难 modifier
地图规则
事件结果
```

当前阶段优先落地：

```text
房间
Encounter
物品
```

其它对象先预留字段，不要求填完整内容。

---

### 3.3 标签命名规范

内部标签使用稳定 ID，不使用中文作为内部主键。

推荐格式：

```text
namespace.tag_id
```

示例：

```text
function.trade
function.sell
repeat.once
repeat.repeatable
effect.scan
context.map
target.adjacent_room
risk.mine
reward.item_source
objective.related
```

中文名称只作为显示名或策划备注。

---

### 3.4 标签命名空间

建议基础命名空间如下：

```text
function.*      功能类
trigger.*       触发方式
repeat.*        重复规则
effect.*        效果类型
context.*       使用场景
target.*        目标对象
risk.*          风险关联
reward.*        收益来源
trade.*         交易关联
source.*        来源关联
system.*        系统关联
objective.*     目标关联
codex.*         图鉴关联
research.*      研究关联
settlement.*    结算关联
debug.*         调试标签
```

---

### 3.5 标签字典字段

标签字典建议字段：

```text
tag_id
display_name
tag_group
description
allowed_targets
is_player_visible
is_deprecated
replacement_tag
debug_note
```

说明：

1. tag_id 是内部稳定 ID；
2. display_name 是显示名称；
3. tag_group 是标签分组；
4. allowed_targets 限制该标签可挂在哪些对象上；
5. is_player_visible 决定是否允许展示给玩家；
6. is_deprecated 用于后续废弃；
7. replacement_tag 用于迁移；
8. debug_note 用于策划和程序沟通。

## 4. Policy 行为规则层

Policy 决定真实行为。
标签只能辅助分类，不能独立决定复杂行为。

### 4.1 房间 Policy

房间 Policy 建议包括：

```text
entry_policy
entry_trigger_policy
search_policy
return_policy
loot_policy
pressure_policy
clear_policy
lock_policy
repeat_interaction_policy
repeat_reward_policy
repeat_progress_policy
repeat_pressure_policy
repeat_loot_policy
settlement_policy
codex_policy
objective_policy
map_mutation_policy
```

---

### 4.2 entry_policy

定义房间如何进入。

可选：

```text
normal_adjacent
special_entry
teleport_allowed
airdrop_allowed
locked
condition_required
```

---

### 4.3 entry_trigger_policy

定义进入后是否触发内容。

可选：

```text
trigger_on_enter
reveal_on_enter
manual_interact
by_encounter
no_trigger
```

---

### 4.4 search_policy

定义是否可搜索。

可选：

```text
disabled
search_once
repeatable_search
conditional_search
after_clear
after_open
by_encounter
```

---

### 4.5 return_policy

定义是否可回传。

可选：

```text
disabled
allowed_after_explored
allowed_after_cleared
blocked_until_clear
by_room_state
by_modifier
```

---

### 4.6 loot_policy

定义如何生成掉落。

可选：

```text
none
search_generated
generate_once
monster_drop
event_generated
transaction_based
by_encounter
```

---

### 4.7 repeat 系列 Policy

重复相关必须拆开：

```text
repeat_interaction_policy
repeat_reward_policy
repeat_progress_policy
repeat_pressure_policy
repeat_loot_policy
```

可选：

```text
none
once
repeatable
conditional
cooldown
persistent
event_driven
transaction_based
by_encounter
```

原则：

```text
可重复交互 ≠ 可重复奖励
可重复奖励 ≠ 可重复推进目标
可重复查看 ≠ 可重复生成掉落
```

## 7. GroundLoot / RoomLootContainer

### 7.1 定义

RoomLootContainer / GroundLoot 表示物品当前存在于本局某个房间中，但尚未进入玩家背包，也没有进入长期仓库。

---

### 7.2 来源

GroundLoot 可来自：

```text
搜索
宝箱
怪物掉落
事件奖励
玩家主动丢弃
背包替换
特殊房间
目标相关生成
```

---

### 7.3 规则

1. 地面物不属于背包；
2. 地面物不属于长期仓库；
3. 玩家拾取后才进入局内背包；
4. 成功撤离后才可能入仓；
5. 本局结束未拾取默认丢失；
6. 地面物需要随 active run 存档；
7. 地面物可在小地图 / 展开地图中显示轻量标记；
8. 目标物丢在地上可能导致目标失败；
9. 黑币不作为可主动丢弃的地面物处理。

---

### 7.4 GroundLoot 字段

建议字段：

```text
loot_container_id
room_id

item_instance_id
quantity
source_type
source_id
is_player_dropped
is_pickable
drop_policy
pickup_policy
expire_policy
visibility_state
target_related
created_step
updated_step
```

## 8. 特殊进入方式

### 8.1 entry_mode

局内进入方式包括：

```text

airdrop
jump
forced_move
event_move
retreat_move
return
```

### 8.2 默认规则

1. 普通移动 = 相邻进入；
2. 特殊进入 = 道具、事件、怪物、地图规则、高难条件提供；
3. 进入未知房默认触发房间；
4. 远程扫描不触发房间；
5. 回传已探索房不触发新内容；
6. 强制移动到未知房默认视为正式进入；
7. 强制移动到已探索房默认不触发新内容；
8. 特殊事件可覆盖默认规则，但必须写入 source_policy。

## 13. 最低验收标准

当前阶段最低验收标准：

1. 房间有基础房型；
2. 基础房型保持互斥；
3. 房间有 tags 字段；
4. 房间有 policy 字段；
5. 房间有 state 字段；
6. Encounter 有 tags 和 policy；
7. 普通房可搜索；
8. 宝箱房可生成掉落；
9. 怪物房可生成掉落；
10. 事件房可触发 Encounter；
11. 商人 / 回收终端可作为事件类 Encounter；
12. 撤离格可触发撤离确认；
13. GroundLoot 可承载掉落和丢弃物；
14. 回传只允许到合法已探索 / 已清理房间；
15. 特殊进入方式有字段预留；
16. 标签能被调试工具显示；
17. 标签不替代强字段和 Policy；
18. 房间结果能输出到 RunResult。

---

## 14. 总结

本案确立以下核心规则：

1. 房间是地图节点；
2. Encounter 是具体玩法内容；
3. 基础房型当前保持互斥；
4. 标签用于分类、筛选、内容池、UI、调试和系统匹配；
5. Policy 决定真实行为；
6. State 记录本局状态；
7. 当前阶段采用一个房间挂一个主要 Encounter；
8. GroundLoot 承载地面掉落、怪物掉落、宝箱奖励、事件奖励和主动丢弃物；
9. 特殊进入方式必须预留；
10. 标签系统可扩展到装备、消耗品、藏品、特殊物、目标、研究、图鉴、掉落池和高难 modifier；
11. 当前只做轻量 Tag Layer，不把所有行为改成标签驱动；
12. 房间与 Encounter 结果统一输出到 RunResult，由结算报告处理最终入仓、丢失、记录和长期写回。
