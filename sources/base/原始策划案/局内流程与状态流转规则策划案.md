# 《灰尾回收 / 五四三二一》局内流程与状态流转规则策划案

## 独立策划案

---

## 0. 文档定位

本案用于定义玩家进入一局探索后的完整局内流程，包括本局初始化、地图探索、扫描、标记、房间进入、房间处理、搜索、战斗遭遇、事件触发、宝箱开启、掉落、拾取、丢弃、背包、黑币、目标推进、撤离、失败、放弃与结算输出。

本案承接以下系统：

1. 出发探索：提供地图、难度、带入物、本局目标、背包上限等开局配置；
2. 地图本体：提供地图结构、房间状态、小地图、扫描层、标记层、污染层、回传等规则；
3. 物品资产模型：提供装备、消耗品、藏品、特殊物、通用资产等分类；
4. 结算报告：接收本局结果并处理入仓、丢失、目标结果、历史战绩；
5. 长期系统：接收目标、图鉴、研究、资历、成就、收藏等长期记录变化。

本案不讨论：

1. 具体数值；
2. 具体怪物数值；
3. 具体事件文本；
4. 具体奖励数量；
5. 具体价格；
6. 正式文案；
7. 正式 UI 美术；
8. 具体操作按键；
9. 具体移动端 / 手柄交互方案。

---

## 1. 局内流程核心定位

局内流程是玩家在一张本局地图中围绕信息、风险、收益、背包和撤离进行连续决策的过程。

局内流程的核心体验由三部分组成：

1. 扫雷式信息判断：玩家根据已知数字、扫描结果、标记、污染区和房间状态判断风险；
2. 搜打撤式收益压力：玩家获得物品和黑币后，必须撤离或接受失败 / 放弃后果；
3. 肉鸽式局内变化：装备、消耗品、事件、高难目标、地图状态和压力变化会改变本局决策。

基础循环为：

```text
查看信息
→ 判断风险
→ 移动 / 扫描 / 使用物品 / 回传
→ 进入或处理房间
→ 获得收益或承受损失
→ 更新地图、背包、目标和压力
→ 继续探索 / 撤离 / 失败 / 放弃
→ 结算
```

---

## 2. 局内整体流程

一局探索的完整流程如下：

1. 接收出发探索配置；
2. 初始化本局地图；
3. 初始化玩家局内状态；
4. 初始化局内背包和带入物；
5. 初始化本局目标；
6. 进入出生房；
7. 显示当前房间与小地图；
8. 玩家进行探索、扫描、标记、搜索、使用消耗品、处理房间；
9. 触发房间遭遇；
10. 获得、拾取、丢弃、出售或消耗局内物品；
11. 推进目标、图鉴、压力、地图状态；
12. 玩家找到并使用撤离点，或失败，或主动放弃；
13. 生成 RunResult；
14. 进入结算报告；
15. 结算报告写回仓库、目标、历史战绩、图鉴、研究、资历等系统。

局内流程不直接把奖励写入长期仓库。
局内流程只记录本局状态，最终由结算报告决定哪些内容入仓、转化、丢失、清空或保留记录。

## 3. 本局初始化

### 3.1 输入来源

局内初始化读取出发探索生成的本局启动配置。

配置内容包括：

1. 地图类型；
2. 难度；
3. 地图规则；
4. 本局目标 / 委托；
5. 高难委托条件；
6. 带入装备；
7. 带入消耗品；
8. 带入特殊物；
9. 背包上限；
10. 长期解锁状态；
11. 研究影响；
12. 后续许可接口；
13. 其它本局 modifier。

### 3.2 初始化对象

进入局内后创建或恢复：

1. TruthMap；
2. KnownMap；
3. ScanLayer；
4. MarkMap；
5. RunMapState；
6. InfoReliabilityLayer；
7. 当前房间；
8. 局内背包；
9. RoomLootContainer / GroundLoot；
10. 本局待结算黑币；
11. 本局带入装备状态；
12. 本局带入消耗品状态；
13. 本局目标状态；
14. 协议 / 封锁压力；
15. 局内事件日志；
16. 地图变更日志；
17. 图鉴临时发现记录；
18. 本局操作记录。

### 3.3 出生房

出生房在本局开始时成为当前房间。

出生房规则：

1. 出生房本身不是雷房；
2. 出生房为已探索状态；
3. 出生房可显示当前地图基础信息；
4. 出生房可作为回传目标；
5. 普通模式不保证出生房周围安全；
6. 普通模式不保证出生点到撤离点存在安全路径；
7. 教学、评委、特殊地图可启用额外保护规则。

## 4. 玩家基础行动

局内玩家可执行的基础行动包括：

1. 查看当前房间；
2. 查看小地图；
3. 打开展开地图；
4. 查看目标状态；
5. 查看背包；
6. 查看待结算收益；
7. 标记房间；
8. 取消标记；
9. 使用消耗品；
10. 扫描房间；
11. 进入相邻房间；
12. 通过特殊方式进入非相邻房间；
13. 回传到已探索房间；
14. 搜索当前房间；
15. 处理房间遭遇；
16. 拾取物品；
17. 丢弃物品；
18. 替换物品；
19. 在指定功能区出售物品；
20. 接入或使用撤离点；
21. 放弃当前探索。

不同状态下可用行动不同。
战斗、事件选择、撤离确认、失败演出、结算中应锁定部分行动。

## 5. 移动与进入方式

### 5.1 默认进入方式

默认进入方式为相邻进入。

规则：

1. 玩家默认从当前房间进入相邻房间；
2. 相邻关系由地图拓扑决定；
3. 矩形地图使用矩形邻接规则；
4. 蜂窝地图使用蜂窝邻接规则；
5. 特殊地图使用自定义邻接规则；
6. 默认进入未知房间视为正式探索；
7. 正式探索会触发该房间内容。

### 5.2 特殊进入方式

局内必须预留非相邻进入方式。

特殊进入方式包括：

1. teleport：传送；
2. airdrop：空降；
3. jump：跳格；
4. forced_move：强制移动；
5. event_move：事件移动；
6. retreat_move：撤退移动；
7. return：回传 / 快速回访。

特殊进入来源可以包括：

1. 消耗品；
2. 装备；
3. 事件；
4. 怪物效果；
5. 陷阱；
6. 高难委托；
7. 地图规则；
8. 研究解锁；
9. 后续系统。

### 5.3 特殊进入字段

每种进入方式需要定义：

1. entry_mode；
2. entry_source；
3. target_rule；
4. 是否允许进入未知房；
5. 是否允许进入已扫描房；
6. 是否允许进入已探索房；
7. 是否触发房间内容；
8. 是否增加协议 / 封锁压力；
9. 是否揭示目标房间；
10. 是否触发雷房；
11. 是否触发事件；
12. 是否触发怪物遭遇；
13. 是否可被污染区影响；
14. 目标非法时如何处理；
15. 失败时如何处理。

### 5.4 默认处理建议

1. 相邻进入未知房间：触发房间；
2. 空降 / 传送到未知房间：默认触发房间；
3. 远程扫描：只产生扫描信息，不触发房间；
4. 回传到已探索房间：不触发新内容；
5. 强制移动：由来源策略决定是否触发房间；
6. 撤退移动：由战斗或事件规则决定是否触发房间。

## 6. 扫描、探索与回传

### 6.1 扫描

扫描不是探索。

扫描来源：

1. 消耗品；
2. 装备；
3. 事件；
4. 地图规则；
5. 研究解锁；
6. 本局目标提示；
7. 特殊房间。

扫描可以产生：

1. 雷险信息；
2. 房间倾向；
3. 撤离线索；
4. 目标线索；
5. 怪物活动提示；
6. 宝箱 / 事件提示；
7. 信息可信度提示。

扫描不会：

1. 触发房间；
2. 触发事件；
3. 触发战斗；
4. 触发雷房；
5. 开启宝箱；
6. 允许回传；
7. 增加协议压力；
8. 将房间标记为已探索。

### 6.2 探索

探索指玩家正式进入房间。

探索会：

1. 更新当前位置；
2. 将房间标记为已探索；
3. 揭示房间基础信息；
4. 触发该房间基础内容；
5. 可能增加协议 / 封锁压力；
6. 可能推进目标；
7. 可能生成图鉴临时记录；
8. 更新小地图和展开地图。

### 6.3 回传 / 快速回访

回传是展开地图中的便利操作。

规则：

1. 只能回传到已探索或已清理房间；
2. 未知房间不能回传；
3. 已扫描但未探索房间不能回传；
4. 回传不揭示新房间；
5. 回传不触发新事件；
6. 回传不触发战斗；
7. 回传不触发雷房；
8. 回传不增加协议 / 封锁压力；
9. 回传默认不进行全局路径寻路校验；
10. 回传检查目标房间状态；
11. 回传检查当前玩家状态。

禁止回传状态：

1. 战斗中；
2. 怪物攻击判定中；
3. 陷阱演出中；
4. 事件选择中；
5. 撤离确认中；
6. 结算中；
7. 当前地图规则禁用回传；
8. 目标房间被封锁；
9. 高难委托限制回传；
10. 特殊事件临时禁用回传。

## 7. 房间处理标准流程

每个房间统一采用四阶段流程：

```text
到达 → 观察 → 处理 → 离开
```

### 7.1 到达

到达时执行：

1. 更新当前位置；
2. 房间进入已探索状态；
3. 显示房间场景；
4. 显示房间基础信息；
5. 检查房间是否触发内容；
6. 更新小地图；
7. 写入局内日志。

### 7.2 观察

观察阶段显示：

1. 房间类型；
2. 雷数；
3. 是否可搜索；
4. 是否有事件；
5. 是否有怪物；
6. 是否有宝箱；
7. 是否有掉落物；
8. 是否可交易；
9. 是否可撤离；
10. 是否目标相关；
11. 是否受污染；
12. 是否被封锁；
13. 是否已清理；
14. 是否已耗尽。

### 7.3 处理

处理阶段可执行：

1. 搜索；
2. 开宝箱；
3. 战斗；
4. 事件选择；
5. 商人交易；
6. 回收终端交易；
7. 拾取掉落物；
8. 丢弃物品；
9. 替换物品；
10. 接入撤离点；
11. 使用消耗品；
12. 触发目标条件。

### 7.4 离开

离开阶段可选择：

1. 进入相邻房间；
2. 使用特殊进入方式；
3. 回传到已探索房间；
4. 继续处理当前房间未完成内容；
5. 撤离；
6. 放弃探索。

## 8. 房间类型流程

### 8.1 普通房

普通房是基础探索空间。

可能操作：

1. 查看雷数；
2. 搜索；
3. 拾取掉落；
4. 发现线索；
5. 作为回传节点；
6. 作为路径节点。

普通房搜索后可进入已搜索或已耗尽状态。

### 8.2 雷房

雷房是风险房。

进入雷房可能导致：

1. 损失；
2. 失败；
3. 协议 / 封锁压力变化；
4. 特殊事件触发；
5. 历史记录；
6. 进入结算。

雷房触发后进入已触发或已确认状态。

### 8.3 宝箱房

宝箱房是收益房。

流程：

1. 进入房间；
2. 发现宝箱；
3. 选择开启；
4. 生成奖励；
5. 奖励进入 RoomLootContainer 或直接进入局内背包；
6. 宝箱进入已开启状态；
7. 房间进入已搜索 / 已耗尽状态。

宝箱奖励不直接进入长期仓库。

### 8.4 事件房

事件房触发 Encounter。

流程：

1. 进入房间；
2. 触发事件；
3. 显示事件选项；
4. 玩家选择；
5. 产生事件结果；
6. 更新地图、背包、目标、压力、图鉴或记录；
7. 事件进入已触发、已完成、可重复或持续状态。

事件可一次性，也可重复，具体由 Encounter repeat policy 决定。

### 8.5 怪物房 / 战斗房

怪物房是战斗 Encounter 的入口。

流程：

1. 进入房间；
2. 生成或读取 Encounter；
3. 进入战斗；
4. 战斗成功则怪物清理；
5. 战斗失败则按失败规则处理；
6. 怪物掉落进入 GroundLoot 或局内背包；
7. 推进目标、图鉴、成就、压力记录。

怪物房默认清理后不刷新怪物。
特殊规则可改写刷新策略。

### 8.6 商人 / 回收终端

商人 / 回收终端是指定功能区。

允许：

1. 购买；
2. 出售；
3. 回收；
4. 处理部分特殊物；
5. 触发交易型事件。

禁止：

1. 代替普通背包自由出售；
2. 绕过结算直接入仓；
3. 修改长期仓库本体而不走事件流。

商人 / 回收终端可重复访问，交易内容是否刷新后续单独定义。

### 8.7 撤离点

撤离点是成功结束本局的核心节点。

状态：

1. 未发现；
2. 已发现；
3. 已接入；
4. 可撤离；
5. 撤离确认；
6. 已使用。

撤离时应进入确认流程。

确认信息包括：

1. 当前背包物；
2. 当前待结算黑币；
3. 当前目标状态；
4. 消耗品清空提示；
5. 撤离后进入结算提示。

撤离确认后进入结算报告。

## 9. Encounter 重复触发规则

房间状态与 Encounter 状态分离。

房间已探索，不代表内部所有 Encounter 都不可再次触发。

### 9.1 repeat_policy

每个 Encounter 应定义 repeat_policy：

1. once：只触发一次；
2. repeatable：可重复触发；
3. conditional：满足条件后可重复；
4. cooldown：冷却后可重复；
5. persistent：持续存在；
6. event_driven：由其它事件刷新。

### 9.2 重复交互与重复奖励分离

必须区分：

1. 是否可重复交互；
2. 是否可重复奖励；
3. 是否重复推进目标；
4. 是否重复推进成就；
5. 是否重复增加压力；
6. 是否重复生成掉落。

字段建议：

1. repeat_interaction_policy；
2. repeat_reward_policy；
3. repeat_progress_policy；
4. repeat_pressure_policy；
5. repeat_loot_policy。

规则：

```text
可重复交互 ≠ 可重复奖励
```

示例：

1. 商人：可重复交互，交易受资源和库存限制；
2. 普通宝箱：一次性触发，一次性奖励；
3. 规则房：可重复查看，不重复奖励；
4. 赌博事件：可重复，但需要成本或风险；
5. 特殊事件：可由事件或条件刷新。

## 10. 搜索流程

### 10.1 搜索定位

搜索回答：

```text
当前房间是否还有可回收、可发现、可触发、可拾取的内容？
```

搜索可产出：

1. 物品；
2. 黑币；
3. 特殊物；
4. 线索；
5. 图鉴发现；
6. 目标进度；
7. 事件；
8. 风险；
9. 压力变化。

### 10.2 可搜索房间

当前建议：

1. 普通房可搜索；
2. 宝箱房可开启或搜索；
3. 事件房处理后可视情况搜索；
4. 怪物房清理后可搜索；
5. 商人 / 回收终端不以搜索为主；
6. 撤离点不以搜索为主；
7. 雷房后续是否可搜索单独定义。

### 10.3 搜索状态

房间搜索状态包括：

1. 未搜索；
2. 已搜索；
3. 已耗尽；
4. 可再次搜索；
5. 条件搜索。

普通房默认搜索后耗尽。
事件、特殊地图、研究、目标可以改写搜索规则。

## 11. 局内掉落与 RoomLootContainer

### 11.1 定义

RoomLootContainer / GroundLoot 表示物品当前存在于本局某个房间中，但尚未进入玩家背包，也未进入长期仓库。

### 11.2 产生来源

GroundLoot 可来自：

1. 宝箱；
2. 怪物掉落；
3. 事件奖励；
4. 搜索结果；
5. 玩家主动丢弃；
6. 特殊房间；
7. 目标奖励；
8. 后续规则。

### 11.3 生命周期

标准生命周期：

```text
掉落生成
→ 进入当前房间 GroundLoot
→ 玩家拾取
→ 进入局内背包
→ 成功撤离
→ 结算入仓
```

未拾取生命周期：

```text
掉落生成
→ 进入 GroundLoot
→ 玩家未拾取
→ 本局结束
→ 默认丢失
```

丢弃生命周期：

```text
玩家主动丢弃
→ 进入当前房间 GroundLoot
→ 本局内可重新拾取
→ 本局结束未拾取则丢失
```

### 11.4 地图显示

小地图显示：

1. 房间有未拾取物的轻量标记。

展开地图显示：

1. 未拾取物数量；
2. 大类；
3. 是否目标相关；
4. 是否玩家丢弃；
5. 是否高价值提示。

房间详情显示：

1. 具体物品；
2. 数量；
3. 是否可拾取；
4. 是否目标相关；
5. 是否玩家丢弃；
6. 是否即将失效。

---

## 12. 主动丢弃

### 12.1 允许丢弃内容

默认允许丢弃：

1. 普通装备；
2. 普通消耗品；
3. 普通藏品；
4. 可丢弃特殊物。

前提：

1. 未锁定；
2. 非唯一；
3. 非关键目标物；
4. 非不可丢弃 policy；
5. 非黑币 / 待结算收益。

### 12.2 不允许或强确认丢弃

默认不允许或强确认：

1. 唯一藏品；
2. 目标关键物；
3. 锁定物；
4. 不可丢弃特殊物；
5. 黑币 / 待结算收益；
6. 正在结算保护中的物品；
7. 系统标记不可丢弃物品。

### 12.3 丢弃后规则

丢弃后：

1. 物品进入当前房间 GroundLoot；
2. 本局内可重新拾取；
3. 小地图 / 展开地图可显示未拾取物；
4. 本局结束未重新拾取则默认丢失；
5. 未在背包内的丢弃物不参与撤离入仓；
6. 丢弃目标关键物可能导致目标失败。

---

## 13. 拾取与背包满处理

### 13.1 拾取流程

拾取流程：

1. 玩家选择拾取；
2. 系统检查是否可拾取；
3. 系统检查背包容量；
4. 容量足够则进入背包；
5. 容量不足则进入背包满处理。

### 13.2 背包满处理

背包满时提供：

1. 放弃拾取；
2. 丢弃已有物品后拾取；
3. 替换已有物品；
4. 标记稍后来取。

替换不是单一操作，实际应拆为：

```text
DropItemEvent
PickupItemEvent
```

即：

1. 旧物从背包移出；
2. 旧物进入当前房间 GroundLoot；
3. 新物进入背包；
4. 背包容量刷新；
5. 地图掉落状态刷新；
6. 结算记录可追踪。

---

## 14. 怪物掉落

怪物掉落不直接进入长期仓库。

### 14.1 标准流程

```text
击败怪物
→ 生成掉落
→ 掉落进入当前房间 GroundLoot
→ 玩家拾取
→ 进入局内背包
→ 成功撤离后入仓
```

### 14.2 可选快捷流程

为优化体验，可允许部分怪物掉落直接尝试进入背包。

流程：

1. 击败怪物；
2. 生成掉落；
3. 检查背包容量；
4. 容量足够则进入背包；
5. 容量不足则进入拾取 / 替换界面。

无论采用哪种方式，都不能直接进入长期仓库。

---

## 15. 黑币 / 待结算收益

### 15.1 定位

黑币是本局待结算收益。

黑币不是仓库物品。
黑币不占普通背包。
黑币不允许主动丢弃。
黑币不能在地面暂存为安全资产。

### 15.2 获得来源

黑币可来自：

1. 搜索；
2. 宝箱；
3. 怪物；
4. 事件；
5. 目标；
6. 商人交易；
7. 特殊房间；
8. 后续规则。

### 15.3 结算

成功撤离后：

1. 黑币按成功规则处理；
2. 可转化为安全资源或进入结算收益。

失败或放弃后：

1. 默认丢失；
2. 或按失败保底 / 抢救规则处理；
3. 当前不讨论具体转化比例。

---

## 16. 目标物与关键物

### 16.1 目标物类型

目标物可以是：

1. 普通物品；
2. 普通藏品；
3. 特殊物；
4. 样本；
5. 事件产物；
6. 怪物掉落物；
7. 记录型目标物；
8. 房间状态目标。

### 16.2 目标物丢弃

目标关键物默认不可出售。
目标关键物丢弃需要强确认。
若本局结束时目标关键物未被带出或未满足目标要求，则目标失败或未完成。

### 16.3 目标物出售

默认禁止目标关键物进入普通出售流程。

若某个目标允许出售目标物作为完成方式，必须由目标定义单独声明。

---

## 17. 局内出售

### 17.1 普通背包禁止出售

局内普通背包不允许自由出售。

### 17.2 合法出售场景

允许出售的局内功能区：

1. 商人；
2. 回收终端；
3. 特殊事件；
4. 后续合法交易房。

### 17.3 地面物出售

默认只能出售背包内物品。
地面物默认不能直接出售。

后续可扩展：

1. 回收终端回收当前房间地面物；
2. 特殊事件处理地面物。

当前版本不建议默认开放，以降低交易逻辑复杂度。

---

## 18. 强制移动与特殊移动

### 18.1 来源

强制移动可来自：

1. 事件；
2. 怪物；
3. 陷阱；
4. 污染区；
5. 特殊地图；
6. 高难委托；
7. 消耗品副作用；
8. 后续系统。

### 18.2 处理规则

强制移动需要定义：

1. 目标房间规则；
2. 是否允许未知房；
3. 是否触发房间；
4. 是否触发雷房；
5. 是否增加压力；
6. 是否可抵抗；
7. 目标非法时如何处理。

建议：

1. 强制移动到已探索房间：默认不触发新内容；
2. 强制移动到未知房间：默认视为正式进入并触发房间；
3. 特殊事件可指定不触发，但必须有 source_policy。

---

## 19. 协议 / 封锁压力

协议 / 封锁压力是地图级状态。

可能受以下行为影响：

1. 探索未知房；
2. 搜索；
3. 开宝箱；
4. 战斗；
5. 触发事件；
6. 触发雷房；
7. 接入撤离点；
8. 完成本局目标；
9. 使用特殊消耗品；
10. 高难委托 modifier。

协议 / 封锁压力可能影响：

1. 撤离提示；
2. 怪物出现；
3. 事件风险；
4. 污染区；
5. 地图状态；
6. 结算记录。

每次变化应进入 RunLog。

---

## 20. 本局目标推进

本局目标由出发探索目标页选择，并随 RunStartConfig 进入局内。

目标可监听：

1. 进入指定房间；
2. 搜索指定内容；
3. 获得指定物品；
4. 击败指定怪物；
5. 触发指定事件；
6. 成功撤离；
7. 不使用某类物品；
8. 在高难条件下完成；
9. 放弃；
10. 失败。

目标状态包括：

1. 未开始；
2. 进行中；
3. 已完成；
4. 已失败；
5. 已放弃；
6. 结算中确认。

最终完成 / 失败应在结算报告中确认。

---

## 21. 成功、失败、放弃

### 21.1 成功撤离

成功条件：

1. 玩家在可撤离状态下确认撤离。

成功后：

1. 进入结算报告；
2. 背包物品按成功规则处理；
3. 黑币按成功规则处理；
4. 目标按完成情况结算；
5. 消耗品按本局结束规则处理；
6. 历史战绩记录成功。

### 21.2 普通失败

普通失败来源：

1. 雷房；
2. 战斗失败；
3. 事件失败；
4. 协议 / 封锁压力失败；
5. 特殊规则失败。

失败后：

1. 进入结算报告；
2. 物品按失败 / 抢救规则处理；
3. 黑币默认丢失或按保底规则处理；
4. 目标一般失败或未完成；
5. 消耗品清空；
6. 历史战绩记录失败。

### 21.3 放弃 / 中止

放弃入口：

1. 局内暂停 / 设置页；
2. 出发探索 active run 状态。

放弃后：

1. 进入结算报告；
2. 结果为放弃 / 中止；
3. 不算成功撤离；
4. 不计入死亡 / 被击败类失败；
5. 局内背包物默认不入仓；
6. 地面物默认不入仓；
7. 黑币默认不转化；
8. 消耗品清空；
9. 目标一般未完成或失败；
10. 历史战绩记录放弃。

---

13. 是否撤离；
14. 带入装备；

16. 消耗品使用记录；

## 26. 总结

本案将局内流程定义为：

> 玩家在地图信息、房间内容、背包容量、掉落物、黑币收益、本局目标和撤离压力之间进行连续决策的过程。

核心规则：

1. 默认移动是相邻进入，但特殊进入方式必须预留；
2. 扫描不等于探索；
3. 回传只用于已探索房，不触发新内容；
4. 房间流程采用到达、观察、处理、离开；
5. Encounter 是否重复由 repeat policy 控制；
6. 地面掉落和房间掉落必须由 RoomLootContainer 承载；
7. 主动丢弃进入当前房间 GroundLoot；
8. 黑币是待结算收益，不允许主动丢弃；
9. 局内普通背包不允许自由出售；
10. 出售只能在指定功能区；
11. 物品只有在结算后才真正入仓；
12. 成功、失败、放弃都输出 RunResult；
13. 结算报告读取 RunResult，不重新解析局内流程。
