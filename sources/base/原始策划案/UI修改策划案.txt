# 《灰尾回收 / 五四三二一》G9 UI 信息架构与出勤界面改造策划案

## 1. 文档定位

本文档用于规划 Godot 正式版后续 UI 结构，基于当前已有出勤准备 UI 方案进行调整，并结合后续可能加入的地图、任务、图鉴、成就、角色制、个人穿搭、背景切换、面板收放、快速跳转等需求，建立一套可扩展、可减法、可逐步实现的 UI 信息架构。

本案不是完整 UI 美术终稿，也不是一次性实现所有系统的开发清单。当前目标是：

> 在保留现有出勤界面风格与交互基础的前提下，重构 UI 信息层级，预留长期系统与角色系统接口，并确保后续可以根据实际游玩反馈做 UI 减法。

---

## 2. 当前 UI 基础

当前原型 UI 已经形成较清晰的出勤准备界面基础：

* 左侧：角色与地牢入口背景；
* 顶部：后勤仓库、后勤申领、出勤配置、回收资历、天赋等按钮；
* 中央：当前功能面板，例如天赋列表；
* 右侧：出勤准备 / 局内效果摘要；
* 右下：确认出发按钮。

该结构的优点是：

1. 出勤氛围明确；
2. 角色、基地、装备、天赋、确认出发形成了较强的“出发前准备”语义；
3. 右侧摘要面板有助于玩家快速理解当前配置结果；
4. 中央大面板适合承载仓库、天赋、配置等细节内容。

当前主要问题是：

1. 顶部五个按钮不足以承载后续地图、任务、图鉴、成就等内容；
2. 出勤准备类内容与长期系统类内容混在同一层，会导致界面逐渐臃肿；
3. 右侧摘要信息仍不够系统，后续装备、消耗品、Buff、背包、风险、任务目标都可能需要汇总；
4. 中央面板信息密度较高，长期展开会遮挡背景与角色表现；
5. 未来角色制、穿搭、地图主题背景切换等功能需要提前预留入口；
6. 玩家需要快速跳转常用功能，不能被多层菜单反复打断。

---

## 3. 总体设计原则

### 3.1 出勤页不是全系统总入口

当前出勤界面应定位为：

> 出发探索前的准备与确认页面。

它不应承载所有长期系统。地图、仓库、出勤配置、天赋等与“本次出发”直接相关的功能可以留在该页；任务、图鉴、成就、回收资历、研究等长期系统应拆入独立的长期系统入口。

### 3.2 先做扩展骨架，后续再做 UI 减法

当前阶段应先保证：

* 入口可扩展；
* 面板可替换；
* 摘要可配置；
* 背景可主题化；
* 快速跳转可用；
* 角色入口可预留；
* 长期系统可独立成页。

后续根据真实游玩反馈，再减少不常用入口、折叠低频信息、简化右侧摘要、隐藏低价值按钮。

### 3.3 高频前置，低频收纳

UI 信息分层建议：

* 高频：出发探索、地图、仓库、出勤配置、天赋、确认出发；
* 中频：任务追踪、角色选择、个人穿搭、图鉴入口、回收资历；
* 低频：成就、研究、历史统计、完整档案、完整 MetaProgress 系统。

### 3.4 摘要常驻，细节按需展开

右侧摘要面板用于展示“当前配置结果”，中央面板用于展示“当前系统细节”。

例如：

* 右侧显示：装备、消耗品、背包容量、局内效果、风险提示；
* 中央显示：天赋树、装备列表、仓库内容、地图选择、申领内容等。

这样玩家不需要频繁来回点击，也能理解当前出勤状态。

### 3.5 UI 应对接 G8.2 协议

后续 UI 不应直接读取或修改核心状态，而应遵守当前 G8.2 内核协议：

* UI 发送玩家意图：走 Command / CommandResult；
* UI 读取状态：走 QueryFacade / ViewModel / snapshot；
* UI 展示结算解释：消费 EventLog / TransactionLog；
* UI 不直接修改 Ledger、TruthMap、RunContext 内部状态；
* Debug UI 必须保持 dev-only 或折叠。

---

## 4. 三层 UI 信息架构

后续 UI 规划为三类主要页面：

1. 主界面；
2. 出发探索界面；
3. 长期系统界面。

---

# 5. 主界面设计

## 5.1 页面定位

主界面是玩家进入游戏后的第一层入口，负责分流玩家当前意图。

主界面不承载大量细节，只负责回答：

> 玩家现在想做什么？

## 5.2 主界面一级入口

主界面建议保留三个大入口：

1. 出发探索；
2. 长期系统；
3. 设置。

### 出发探索

进入出勤准备与局内探索相关流程。

包含：

* 地图选择；
* 后勤仓库；
* 后勤申领；
* 出勤配置；
* 天赋；
* 角色 / 穿搭入口；
* 确认出发。

### 长期系统

进入长期成长、档案、任务、图鉴、成就、研究等页面。

包含：

* 任务；
* 图鉴；
* 成就；
* 回收资历；
* 研究；
* 历史统计；
* 章节进度。

### 设置

进入游戏设置、操作设置、音频、画面、语言、辅助功能等页面。

---

## 5.3 主界面快速跳转

为了降低点击负担，主界面应保留一个小型快速跳转区。

建议快捷入口：

* 最近地图；
* 任务追踪；
* 仓库；
* 图鉴；
* 继续上次配置。

该区域用于减少高频玩家的路径长度，但不应抢占一级入口视觉权重。

## 5.4 主界面信息构成

推荐布局：

* 左上：游戏标题与版本标识；
* 左中：基地背景 / 角色站位；
* 左下：玩家信息、等级、金币、特殊货币；
* 右侧：三个大入口按钮；
* 右下：快速跳转；
* 底部：小提示或当前公告。

## 5.5 主界面后续可减法项

后续可根据体验删减或折叠：

* 公告；
* 玩家资源详细显示；
* 快速跳转数量；
* 背景动态元素；
* 继续上次配置入口。

---

# 6. 出发探索界面设计

## 6.1 页面定位

出发探索界面是玩家出发前的核心准备页面。

它负责回答：

> 我这次要去哪？带什么？有什么局内效果？是否确认出发？

该页面应保留较强的仪式感和战前准备感。

---

## 6.2 顶部入口

出发探索页顶部只放与本次出发强相关的功能。

建议顶部一级页签：

1. 地图；
2. 后勤仓库；
3. 后勤申领；
4. 出勤配置；
5. 天赋。

这些页签共同服务“本次出发”。

不建议将任务、图鉴、成就放在该顶部页签中。它们应进入长期系统页，或通过小型快捷入口访问。

---

## 6.3 左侧角色区域

左侧角色区域保留当前人物与基地入口视觉。

后续预留：

* 角色选择；
* 个人穿搭；
* 当前角色名称；
* 当前角色职业 / 特性；
* 当前角色出勤状态；
* 装备外观预览；
* 地图主题背景联动。

角色选择与个人穿搭不建议放在顶部页签中，而应直接附着在左下角角色区域。

原因：

> 角色是“我是谁”，不是“我要打开哪个系统”。

---

## 6.4 中央主面板

中央主面板承载当前页签的细节内容。

例如：

### 地图页

展示：

* 当前地图；
* 地图尺寸；
* 难度；
* 雷房数量；
* 撤离点数量；
* 推荐配置；
* 风险等级；
* 地图主题；
* 可选地图列表。

### 后勤仓库页

展示：

* 仓库物品；
* 装备；
* 消耗品；
* 藏品；
* 可携带物；
* 筛选与排序；
* 当前带入状态。

### 后勤申领页

展示：

* 可申领补给；
* 消耗品；
* 初始工具；
* 免费 / 付费申领；
* 每日补给；
* 限制条件。

### 出勤配置页

展示：

* 已装备物；
* 已携带消耗品；
* 背包容量；
* 安全箱 / 保险 / 托运预留；
* 当前出勤限制；
* 推荐配置。

### 天赋页

展示：

* 当前天赋点；
* 天赋列表；
* 等级；
* 升级消耗；
* 局内效果；
* 可用 / 不可用状态。

---

## 6.5 中央面板收放

中央主面板应支持收起与展开。

### 展开状态

用于查看细节内容。

适合：

* 配置装备；
* 查看天赋；
* 选择地图；
* 查看仓库；
* 申领物品。

### 收起状态

用于降低视觉压力。

收起后应保留：

* 当前页签名称；
* 当前页简要摘要；
* 展开把手；
* 右侧出勤摘要；
* 确认出发按钮。

建议表现方式：

* 面板底部增加机械把手；
* 使用“拉上 / 放下”式动效；
* 不完全消失，而是收成一条状态栏；
* 后续可根据玩家偏好记住上次状态。

---

## 6.6 右侧出勤摘要

右侧摘要是出发探索页的核心信息区域。

它负责回答：

> 当前配置最终会带来什么结果？

建议分为四组。

### A. 携带装备

显示：

* 防具；
* 工具；
* 罗盘 / 扫描器；
* 背包；
* 武器或探索器具；
* 装备加成简写。

### B. 携带消耗品

显示：

* 止血贴；
* 扫描道具；
* 临时护符；
* 炸药 / 陷阱工具；
* 空槽位；
* 数量。

### C. 背包与资源

显示：

* 当前容量 / 最大容量；
* 黑币初始状态；
* 金币消耗；
* 是否超重；
* 是否缺少必需品；
* 是否有保险 / 托运。

### D. 局内效果总览

显示：

* 生命上限；
* 移动速度；
* 扫描范围；
* 背包容量；
* 战利品品质；
* 物理减伤；
* 怪物逃跑时间；
* 消耗品效果；
* 地图推荐程度。

### E. 风险与限制

显示：

* 当前地图危险等级；
* 配置缺口；
* 当前任务目标；
* 推荐路线；
* 是否允许出发；
* blocked reason。

---

## 6.7 确认出发按钮

确认出发按钮应保持明显、稳定、强视觉权重。

状态建议：

* 可出发；
* 缺少地图；
* 缺少必要配置；
* 背包超重；
* 任务条件未满足；
* 当前配置有风险但允许出发；
* 当前配置被锁定。

点击后进入出发确认弹窗或直接进入局内，具体根据后续流程决定。

---

## 6.8 出发页快速跳转

出发页可以保留一个小型快速跳转区，但不应抢占顶部主页签。

建议快捷入口：

* 地图；
* 仓库；
* 出勤配置；
* 后勤申领；
* 任务追踪。

如果界面过满，该快捷区可折叠或只保留图标。

---

## 6.9 出发页后续可减法项

后续可根据测试删减：

* 右侧装备图标详细数量；
* 顶部页签数量；
* 快速跳转；
* 中央面板默认展开；
* 左侧角色入口数量；
* 局内效果明细；
* 风险图标数量。

---

# 7. 长期系统界面设计

## 7.1 页面定位

长期系统界面负责承载与本次出发无直接关系、但与玩家长期成长和资料积累相关的内容。

它负责回答：

> 我长期获得了什么？还差什么？下一步目标是什么？

---

## 7.2 长期系统顶部页签

建议页签：

1. 任务；
2. 图鉴；
3. 成就；
4. 回收资历；
5. 研究。

可后续扩展：

* 遗物修复；
* 黑市；
* 历史统计；
* 邮件；
* 赛季 / 挑战；
* 章节。

---

## 7.3 左侧玩家概览

左侧保留长期进度概览。

建议显示：

* 玩家头像；
* 探险者编号；
* 资历等级；
* 当前章节；
* 长期经验进度；
* 总任务完成数；
* 总成就完成数；
* 图鉴收集数；
* 已解锁区域；
* 天赋总等级。

---

## 7.4 中央内容区

中央显示当前页签内容。

### 任务页

显示：

* 进行中；
* 可领取；
* 已完成；
* 每日任务；
* 周常任务；
* 主线委托；
* 研究任务；
* 追踪按钮；
* 奖励说明。

### 图鉴页

显示：

* 藏品图鉴；
* 怪物图鉴；
* 雷房图鉴；
* 事件图鉴；
* 地图模式图鉴；
* 已发现 / 未发现；
* 线索与解释。

### 成就页

显示：

* 进度成就；
* 技术成就；
* 撤离成就；
* 收藏成就；
* 压力成就；
* 高难挑战；
* 奖励状态。

### 回收资历页

显示：

* 资历等级；
* 下一等级奖励；
* 永久属性加成；
* 解锁记录；
* 历史探索数据。

### 研究页

显示：

* 研究项目；
* 材料需求；
* 解锁内容；
* 已完成研究；
* 后续科技树。

---

## 7.5 右侧长期摘要

长期系统右侧摘要应区别于出发页摘要。

它不显示本次出勤装备，而显示长期进度。

建议显示：

* 当前资历等级；
* 下一等级奖励；
* 永久加成；
* 当前追踪目标；
* 当前章节目标；
* 快捷入口；
* 邮件 / 任务刷新提醒。

---

## 7.6 长期系统快速跳转

长期系统内也应支持快速跳转，但应限于长期内容。

建议快捷入口：

* 每日任务；
* 周常任务；
* 当前追踪；
* 图鉴缺口；
* 邮件；
* 研究项目。

---

## 7.7 长期系统后续可减法项

后续可根据使用频率减少：

* 右侧永久加成明细；
* 快捷入口数量；
* 任务分类数量；
* 左侧统计项；
* 章节说明；
* 研究入口显示位置。

# 8. 快速跳转设计

## 8.1 是否需要快速跳转

需要。

如果希望玩家游玩方便，必须支持快速跳转。尤其当系统数量增加后，玩家不应每次都层层返回主界面。

快速跳转的作用是：

* 减少重复路径；
* 方便高频玩家；
* 保留主层级清晰度；
* 避免把所有入口平铺在同一页。

---

## 8.2 快速跳转原则

快速跳转应遵守：

1. 不替代主信息架构；
2. 不抢一级入口视觉权重；
3. 只放高频入口；
4. 可配置 / 可折叠；
5. 支持最近访问；
6. 支持返回上一级；
7. 支持一键回到确认出发。

---

## 8.3 推荐快速跳转类型

### 主界面快速跳转

* 最近地图；
* 任务追踪；
* 仓库；
* 图鉴；
* 继续上次配置。

### 出发页快速跳转

* 地图；
* 仓库；
* 出勤配置；
* 后勤申领；
* 当前任务。

### 长期系统快速跳转

* 每日任务；
* 周常任务；
* 当前追踪；
* 图鉴缺口；
* 邮件；
* 研究项目。

---

# 9. 背景主题切换

## 9.1 设计目标

背景可根据当前地图或场景主题变化，以增强出发感和世界感。

例如：

* 废弃矿坑；
* 地牢深处；
* 污染区；
* 森林神殿；
* 实验室；
* 黑暗遗迹。

---

## 9.2 分阶段实现

### 第一阶段：主题切换

先做轻量主题切换。

可切换：

* 灯光色调；
* 背景旗帜；
* 局部装饰；
* 面板边框色；
* 右侧地图图标；
* 中央标题装饰；
* 粒子 / 雾效。

### 第二阶段：完整背景切换

等 UI 结构稳定后，再考虑整张背景切换。

原因：

* 整背景切换需要较高图层组织；
* 需要控制遮挡关系；
* 需要确保角色与 UI 不冲突；
* 需要更多美术成本。

## 9.3 当前建议

# 12. UI 与 G8.2 协议对齐

后续 UI 实现必须遵守：

1. UI 只发 Command，不直接改核心状态；
2. UI 只读 QueryFacade / ViewModel；
3. UI 使用 CommandResult 展示 blocked reason；
4. ResultPanel 消费 EventLog / TransactionLog；
5. Debug UI 与正式 UI 分离；
6. 快速跳转不绕过系统状态检查；
7. 角色 / 地图 / 出勤配置变更应通过正式接口产生可追踪结果。

# 15. 验收方向

当前 UI 策划案落地时，应至少满足：

1. 主界面能清晰分流：出发探索 / 长期系统 / 设置；
2. 出发探索页只承载出发相关功能；
3. 长期系统页承载任务 / 图鉴 / 成就 / 资历 / 研究；
4. 出发页右侧有常驻出勤摘要；
5. 中央面板支持未来收放；
6. 左侧角色区预留角色选择 / 个人穿搭；
7. 快速跳转存在但不抢主层级；
8. 后续可隐藏 / 折叠 / 移动入口；
9. UI 不绕过 G8.2 协议；
10. 文档明确哪些内容后置，避免阶段失控。

---

# 16. 总结

本轮 UI 改造的核心不是一次性做完整 UI，而是建立正确的信息架构。

最终方向是：

> 主界面负责分流，出发页负责本次出勤，长期系统页负责成长与档案。
> 高频内容前置，低频内容收纳。
> 摘要常驻，细节展开。
> 接口预留完整，默认显示克制。
> 后续允许根据实际游玩反馈做 UI 减法。

当前建议先按三页结构推进：主界面、出发探索、长期系统。
后续再基于真实运行体验，逐步简化入口、折叠信息、强化快捷跳转，并形成正式 UI 版本。
