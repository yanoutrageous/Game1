\# 《灰尾回收 / 五四三二一》长期系统整合与资产接口规则策划案



\## 规则层与信息架构草案 v0.1



> 文档定位：定义长期系统的信息架构、模块边界、目标系统整合方式、个人资历与历史战绩、抽奖与收藏 / 外观、仓库与资产接口、红点提示与资产事件流通规则。

> 适用范围：长期系统、目标系统、图鉴、研究、个人资历、历史战绩、抽奖、收藏 / 外观、仓库跳转、结算报告后续提示、资产事件流通。

> 当前原则：本案只确定产品结构、模块边界和资产接口；具体数值、奖励概率、正式文案、UI 美术、完整数据表后续另定。



\---



\## 0. 核心定位



长期系统是玩家局外长期目标、记录、解锁、履历、抽奖、收藏展示的统一入口。



它不负责本局出勤配置，不负责仓库完整管理，不负责局内结算，不负责直接开始探索。



一句话定位：



> 长期系统负责“玩家长期在追什么、记录了什么、解锁了什么、展示了什么”。



长期系统应做到：



```text

入口简洁

路径清楚

功能边界明确

允许跳转

禁止重复内嵌其它系统本体

```



核心原则：



```text

1\. 一级入口保持克制，避免长期系统变成大杂烩。

2\. 模块可以共享资产事件、红点、奖励、跳转规则。

3\. 模块本体不能互相侵入。

4\. 任务、成就、委托可归入目标系统，但生命周期与失败规则独立。

5\. 历史战绩归入个人资历，并作为核心分组之一。

6\. 仓库保持独立资产页，不并入长期系统核心模块。

7\. 抽奖与收藏 / 外观并列，不互相包含。

8\. 所有奖励与资产变化通过事件流通，不由页面直接写入其它系统。

```

\## 1. 长期系统一级结构



长期系统一级入口建议收束为六个模块：



```text

目标

图鉴

研究

个人资历

抽奖

收藏 / 外观

```



\### 1.1 一级模块说明



| 一级模块    | 内部内容                                    | 核心职责               |

| ------- | --------------------------------------- | ------------------ |

| 目标      | 任务 / 成就 / 委托记录                          | 行为目标、进度、完成、奖励、挑战记录 |

| 图鉴      | 地图 / 怪物 / 藏品 / 装备 / 消耗品 / 事件 / 规则 / 世界观 | 全游戏内容资料库，只查看       |

| 研究      | 功能解锁接口                                  | 管理或展示未来功能解锁入口      |

| 个人资历    | 资历等级 / 历史战绩 / 数据统计 / 里程碑 / 称号 / 徽章      | 玩家长期履历与身份展示        |

| 抽奖      | 抽奖池 / 消耗 / 结果入口                         | 独立抽取功能             |

| 收藏 / 外观 | 唯一展示 / 外观配置 / 展示内容                      | 已拥有展示内容管理          |



\### 1.2 不作为长期系统一级入口的内容



以下内容不建议作为长期系统一级入口：



```text

仓库

出发探索

申领

出勤配置

作业许可启用

结算报告

完整商店

完整外观快捷按钮

```



其中：



```text

仓库 = 独立资产管理页

出发探索 = 本局准备中心

结算报告 = 当局结束后的即时结果反馈

历史战绩 = 个人资历下的核心分组

```

\## 2. 信息架构原则



长期系统应优先按玩家理解组织，而不是把工程模块全部裸露给玩家。



\### 2.1 简洁原则



一级入口不宜过多。

推荐保持在 5–7 个之间。



当前建议：



```text

目标 / 图鉴 / 研究 / 个人资历 / 抽奖 / 收藏外观

```



\### 2.2 路径清楚原则



玩家应能快速判断：



```text

想看任务、成就、委托相关 → 目标

想看资料、世界观、遇到过什么 → 图鉴

想看功能解锁 → 研究

想看战绩、等级、统计、称号 → 个人资历

想抽取内容 → 抽奖

想换外观、看展示物 → 收藏 / 外观

想看当前拥有物 → 仓库

```



\### 2.3 边界不破坏原则



允许：



```text

跳转

有限弹窗查看

红点提示

来源标记

奖励预览

```



禁止：



```text

在目标页完整管理仓库

在仓库页完整展开图鉴

在图鉴页执行研究

在抽奖页管理外观配置

在历史战绩中修改当前仓库

在长期系统中直接配置本局出勤

```

\## 3. 目标系统



目标系统整合任务、成就、委托记录。



它们的本质都是：



> 行为驱动利益。



即：



```text

玩家行为

↓

条件判断

↓

进度变化

↓

完成或失败

↓

奖励、记录、展示或消失

```



\### 3.1 目标系统包含内容



```text

任务

成就

委托记录 / 委托类型说明

```



\### 3.2 共用内容



任务、成就、委托可以共用以下底层逻辑：



```text

条件定义

进度记录

完成判断

奖励发放

红点提示

资产事件产出

历史记录

可见性状态

领取状态

```



建议通用字段：



```text

objective\_id

objective\_type

display\_name

description

condition\_id

progress\_state

completion\_state

reward\_bundle

visibility\_state

claim\_state

lifecycle\_policy

failure\_policy

source\_system

```



其中：



```text

objective\_type = task / achievement / commission

```



\### 3.3 任务



任务是长期引导或阶段目标。



特点：



```text

长期存在

多数一次性

用于新手引导、阶段推进、系统解锁引导

未完成不会消失

可提供明确奖励

```



任务适合奖励：



```text

金币

抽奖券

基础物品

功能提示

图鉴条目补充

研究入口提示

少量局外资产

```



任务不应成为所有系统的强制入口。



\### 3.4 成就



成就是长期挑战和记录。



特点：



```text

长期存在

一次性完成

可以隐藏

可以半隐藏

偏挑战、收藏、展示

不应阻断主线

```



成就可分为：



```text

普通成就

隐藏成就

半隐藏成就

高难成就

收藏成就

Boss 成就

特殊失败成就

撤离成就

```



成就适合奖励：



```text

称号

徽章

外观

抽奖券

展示物

少量资源

唯一藏品，特殊情况下

```



成就不建议奖励关键功能解锁或主线必需内容。



\### 3.5 委托



委托是单局目标。



特点：



```text

出发探索中选择

本局有效

未完成则消失或失败

完成后进入结算报告

历史战绩记录本局委托结果

```



长期系统中可以展示：



```text

委托类型说明

委托完成记录

委托统计

委托相关成就

委托相关任务

```



长期系统中不应直接接取本局委托。



委托奖励可以包括：



```text

金币

抽奖券

普通藏品

特殊物

局外资产

委托专属记录

```



\### 3.6 目标系统与资产事件



目标系统不直接修改仓库、资源账户或外观库。



正确流程：



```text

目标完成

↓

目标完成事件

↓

奖励发放事件

↓

ResourceEvent / ItemEvent / UnlockEvent

↓

仓库 / 资源账户 / 图鉴 / 收藏 / 个人资历读取变化

```

\## 4. 图鉴



图鉴是全游戏内容资料库。



图鉴负责：



```text

记录发现

记录拥有

记录触发

展示规则说明

补充世界观

补充文案

帮助玩家回顾内容

```



图鉴不负责：



```text

提供能力

修改物品

执行研究

领取奖励

配置出勤

抽奖

出售物品

```



\### 4.1 图鉴覆盖范围



图鉴可以覆盖：



```text

地图

地图模式

房间

怪物

Boss

藏品

唯一藏品

装备

消耗品

特殊物

事件

商人

诅咒

祭坛

规则变化

Buff / Debuff

组织

角色

世界观档案

```



\### 4.2 图鉴显示规则



图鉴不应一开始全部显示。



建议状态：



```text

未发现

已遇到

已拥有

已触发

已补全

```



显示原则：



```text

未发现内容可隐藏、显示问号或模糊轮廓。

已遇到内容显示基础信息。

已拥有内容显示完整基础信息。

已补全内容显示完整文案与世界观。

```



\### 4.3 图鉴与其它系统的接口



图鉴可以跳转：



```text

仓库：查看当前是否拥有相关物

历史战绩：查看首次发现或获得来源

收藏 / 外观：查看展示内容

研究：查看是否有相关解锁入口

```



但图鉴本身只查看，不执行外部系统功能。

\## 5. 研究



研究当前作为功能解锁接口保留。



本阶段不定义完整研究玩法，不定义研究数值循环，不定义制造、鉴定、修复等复杂系统。



\### 5.1 研究定位



研究负责或预留：



```text

功能解锁

系统解锁

地图 / 模式 / 规则解锁

作业许可解锁

申领内容解锁

图鉴补充入口

特殊物关联入口

```



研究不负责：



```text

完整图鉴

完整仓库

物品出售

抽奖

任务管理

委托接取

出勤配置

资历等级本体

```



\### 5.2 研究与资历关系



研究不等同于资历经验。



建议关系：



```text

个人资历可以解锁研究入口或研究栏目。

研究可以拥有独立资源或条件。

研究点 / 研究经验若存在，是研究系统资产。

资历经验是个人资历资产。

二者不默认互通。

```



\### 5.3 研究与物品关系



若未来存在研究样本：



```text

无实体研究点 → 通用资产

实体研究样本 → 特殊物

```



研究可以读取特殊物关联，但不应管理仓库库存。

\## 6. 个人资历



个人资历是玩家长期履历中心，而不只是等级条。



它回答：



```text

我玩了多少局？

我成功撤离过多少次？

我最高难度到哪里？

我完成了哪些代表性战绩？

我当前资历等级是多少？

我获得了哪些称号 / 徽章？

我在哪些地图表现最好？

我是否完成过特殊委托 / Boss / 高价值回收？

```



\### 6.1 个人资历内部结构



建议分组：



```text

资历等级

历史战绩

数据统计

里程碑

称号 / 徽章

资历奖励

```



其中，历史战绩是核心分组之一。



\### 6.2 资历等级



资历等级负责展示玩家长期进度和身份。



可显示：



```text

当前资历等级

资历经验

下一等级需求

已获得资历奖励

下一阶段奖励

解锁过的权限

```



资历奖励优先提供：



```text

功能解锁

作业许可解锁

申领权限

地图 / 难度入口

称号

徽章

展示内容

```



不建议以大量永久数值成长为主。

\## 7. 历史战绩



历史战绩归入个人资历，并作为个人资历的核心分组。



历史战绩记录每一局探索的结果快照。



\### 7.1 历史战绩定位



历史战绩负责：



```text

保存每局结果

回顾每局表现

记录成功 / 失败 / 放弃

记录带回 / 丢失 / 清空 / 转化

记录委托完成状态

记录图鉴新增

记录唯一藏品获得

记录关键事件

提供长期统计依据

```



历史战绩不负责：



```text

修改仓库

重新结算奖励

重新领取物品

修改图鉴

修改任务

修改当前局状态

```



\### 7.2 历史战绩记录内容



可记录：



```text

探索编号

日期 / 时间

地图模式

难度

区域

结果：成功 / 失败 / 放弃 / 特殊结束

出勤配置摘要

委托状态

带回物品

丢失物品

清空物品

抢救物品

黑币转金币

获得金币

击败怪物

触发事件

开启宝箱

搜索次数

新增图鉴

完成目标

获得唯一藏品

资历变化

```



\### 7.3 历史战绩快照原则



历史战绩记录当时快照，不依赖当前仓库状态。



例如：



```text

某局带回旧怀表。

后来玩家出售旧怀表。

历史战绩仍显示该局曾带回旧怀表。

仓库则显示当前不再拥有。

```



\### 7.4 历史战绩筛选与排序



可支持：



```text

按时间

按地图

按难度

按成功 / 失败

按委托完成

按获得唯一

按带回价值

按击败 Boss

按探索时长

按特殊事件

```

\## 8. 抽奖



抽奖是长期系统中的独立模块。



它与收藏 / 外观有关联，但不是收藏 / 外观的子功能。



\### 8.1 抽奖定位



抽奖负责：



```text

消耗金币、抽奖券或其它局外资产

生成抽取结果

产出藏品、唯一藏品、外观解锁、展示内容等

播放结果展示

写入资产事件

```



抽奖不负责：



```text

仓库管理

收藏配置

外观穿戴

图鉴完整查看

主线推进

局内数值强化

地图通关门槛

```



\### 8.2 抽奖产物



抽奖可以产出：



```text

普通藏品

唯一藏品

外观解锁

展示内容

徽章

结算背景

其它非数值收藏内容

```



抽奖不应产出：



```text

主线必需物

强制成长

关键通关能力

局内数值核心收益

不可替代功能入口

```



\### 8.3 抽奖与资产事件



正确流程：



```text

玩家消耗金币 / 抽奖券

↓

抽奖系统生成结果

↓

ResourceEvent：消耗资源

↓

ItemEvent / UnlockEvent：获得藏品 / 唯一 / 外观 / 展示内容

↓

仓库 / 图鉴 / 收藏 / 外观 / 历史记录读取变化

```



仓库不执行抽奖。

收藏 / 外观不执行抽奖。

图鉴不执行抽奖。



\---



\## 9. 收藏 / 外观



收藏 / 外观负责已拥有展示内容的查看、展示和配置。



\### 9.1 收藏 / 外观定位



收藏 / 外观负责：



```text

角色外观配置

帽子 / 服装配置

探索视觉特效

结算展示背景

展示位

唯一藏品特殊展示

徽章 / 称号展示

收藏组查看

```



收藏 / 外观不负责：



```text

抽奖

仓库物品管理

图鉴完整查看

出勤配置

局内数值成长

主线推进

```



\### 9.2 唯一藏品与收藏展示



唯一仍是藏品。



唯一可以：



```text

进入仓库

进入图鉴

进入收藏展示

拥有特殊展示接口

附属外观或展示内容

```



仓库显示唯一藏品本体。

收藏 / 外观显示其展示内容或附属外观。

二者有关联，但不是同一系统。



\### 9.3 外观配置入口



外观配置入口可以来自：



```text

主菜单角色脚边小按钮

出发探索角色脚边小按钮

收藏 / 外观页

唯一藏品详情跳转

抽奖结果跳转

```



但外观配置本体归收藏 / 外观系统。



\---



\## 10. 仓库与资产管理接口



仓库不并入长期系统核心一级模块。



仓库是独立资产管理页。



\### 10.1 仓库定位



仓库负责：



```text

查看当前拥有物

显示数量

显示重量

显示估值

显示稀有度

显示新增标记

显示是否可出勤

显示是否可出售

显示是否唯一

筛选、排序、搜索

轻量操作

跳转其它系统

```



仓库不负责：



```text

抽奖

任务

成就

委托

研究

图鉴本体

外观配置

历史战绩

结算报告

```



\### 10.2 长期系统与仓库关系



长期系统可以跳转仓库，但不内嵌仓库。



示例：



```text

目标奖励物品 → 仓库新增红点

抽奖获得藏品 → 跳转仓库查看

图鉴条目 → 跳转仓库查看当前拥有状态

历史战绩物品记录 → 跳转仓库或图鉴

唯一展示 → 跳转仓库查看藏品本体

```



\### 10.3 仓库新增提示



仓库通过：



```text

红点

新增标记

最近获得筛选

未查看状态

```



承接结算、抽奖、任务、委托等系统产出的物品变化。



仓库不弹出结算报告。

\## 11. 资产事件与奖励流通



长期系统内所有奖励、资产变化、解锁变化均应通过事件流通。



\### 11.1 事件类型



建议保留：



```text

ResourceEvent

ItemEvent

UnlockEvent

HistoryRecordEvent

ObjectiveEvent

```



\### 11.2 事件来源



事件来源可以包括：



```text

任务

成就

委托

抽奖

结算

历史战绩

图鉴

研究

个人资历

系统补偿

活动

```



\### 11.3 奖励流通原则



任何模块发放奖励时，不直接写其它系统 UI。



正确流程：



```text

模块完成条件

↓

生成奖励事件

↓

写入资源 / 物品 / 解锁 / 历史记录

↓

对应系统读取变化

↓

红点或新增标记提示玩家

```



\### 11.4 RewardBundle



目标、成就、委托、抽奖、资历奖励等都可以使用奖励包概念。



奖励包可包含：



```text

金币

抽奖券

凭证

装备

消耗品

藏品

唯一藏品

特殊物

外观解锁

图鉴补充

称号

徽章

作业许可解锁

研究入口解锁

```



奖励包不直接决定系统 UI，奖励包只描述资产变化请求。

\## 12. 红点与提示规则



红点提示应统一管理，避免长期系统成为红点地狱。



\### 12.1 允许红点



允许红点的情况：



```text

目标可领取

任务完成

成就完成

隐藏成就完成后可查看

图鉴新增

研究有新解锁 / 完成

个人资历升级

资历奖励可领取

历史战绩未查看

抽奖结果未查看

收藏 / 外观新增

仓库新增物品

```



\### 12.2 不建议红点



不建议红点的情况：



```text

仅仅金币足够消费

仅仅可以抽奖

仅仅商店刷新

仅仅存在可购买项

隐藏成就未完成

玩家已查看过的内容

重复提示已清除内容

```



\### 12.3 红点清除



红点可由以下行为清除：



```text

打开对应模块

查看新增条目

领取奖励

查看详情

批量标记已读

```



不同模块可以有不同清除粒度，但必须可被玩家理解。

\## 13. 跨模块跳转规则



长期系统需要跳转，但不能破坏功能边界。



\### 13.1 允许



```text

目标 → 仓库

目标 → 图鉴

目标 → 出发探索

图鉴 → 仓库

图鉴 → 历史战绩

个人资历 → 历史战绩详情

历史战绩 → 图鉴

历史战绩 → 仓库

抽奖 → 收藏 / 外观

抽奖 → 仓库

收藏 / 外观 → 图鉴

唯一藏品展示 → 仓库详情

```



\### 13.2 禁止



```text

在长期系统中直接选择本局委托

在图鉴中直接研究

在仓库中直接抽奖

在抽奖中配置完整外观

在历史战绩中重新领取物品

在个人资历中直接改仓库状态

在收藏 / 外观中出售藏品

```



\### 13.3 有限弹窗



允许有限弹窗，例如：



```text

查看物品简要详情

查看奖励预览

查看图鉴摘要

查看历史来源摘要

```



但完整功能应跳转至对应模块。



\---



\## 14. 与出发探索的关系



出发探索负责本局准备。



长期系统可以影响出发探索的方式：



```text

解锁地图

解锁难度

解锁作业许可

解锁申领项目

解锁服务接口

解锁委托类型

提示目标推荐

```



但长期系统不直接配置本局。



正确关系：



```text

长期系统 / 个人资历 / 研究 / 目标

↓

产生解锁状态

↓

出发探索读取可用项

↓

玩家选择本局配置

```



委托特别规则：



```text

长期系统可查看委托记录与委托类型。

本局委托选择必须在出发探索完成。

```



\---



\## 15. 与结算报告的关系



结算报告是当局结束后的即时结果页。



结算报告会产生或展示：



```text

物品变化

资源变化

图鉴新增

目标进度

委托完成 / 失败

成就完成

资历变化

历史战绩写入

```



长期系统通过红点和新增状态承接这些变化。



流程：



```text

本局结束

↓

结算报告

↓

资产事件写入

↓

历史战绩保存快照

↓

长期系统相关模块出现红点

```



结算报告不属于长期系统页面，但长期系统可以回看历史战绩。



\---



\## 16. 与物品系统的关系



长期系统不定义物品本体。



长期系统读取物品资产模型中的：



```text

item\_id

main\_type

rarity

sell\_policy

display\_policy

codex\_ref

source\_tag

asset\_event

```



长期系统可以触发奖励事件，但不直接创建仓库物品 UI。



例如：



```text

成就奖励唯一藏品

↓

ItemEvent：获得唯一藏品

↓

仓库显示新增藏品

↓

图鉴显示新增条目

↓

收藏展示显示新增展示内容

```



唯一仍是藏品，不因来自成就或抽奖而改变主类型。

\## 18. 最低验收标准



长期系统整合完成后，应满足：



```text

1\. 一级入口不超过合理数量。

2\. 玩家能清楚找到目标、图鉴、研究、个人资历、抽奖、收藏 / 外观。

3\. 任务、成就、委托归入目标系统框架。

4\. 委托仍在出发探索中选择。

5\. 历史战绩归入个人资历，并作为核心分组。

6\. 仓库保持独立资产页，不并入长期系统核心模块。

7\. 抽奖与收藏 / 外观并列。

8\. 唯一仍是藏品，但可在收藏展示中有特殊展示。

9\. 图鉴只查看，不提供能力。

10\. 研究只作为功能解锁接口，不承担仓库或图鉴功能。

11\. 所有奖励和资产变化通过事件流通。

12\. 红点提示统一、克制、可清除。

13\. 跨模块可以跳转，但不重复实现外部系统功能。

14\. 长期系统不直接修改当前局状态。

```

\## 19. 待确认事项



后续仍需确认：



```text

1\. 长期系统一级模块正式命名。

2\. “目标”是否作为正式名称，还是改为“委托与成就”“目标档案”等。

3\. “个人资历”正式名称。

4\. 历史战绩在个人资历中的默认显示优先级。

5\. 研究模块是否初期只占位。

6\. 研究是否需要隐藏到后期解锁。

7\. 抽奖模块正式名称。

8\. 收藏 / 外观模块正式名称。

9\. 仓库入口在主菜单、出发探索、长期系统中的出现方式。

10\. 目标系统奖励领取是否统一在目标页。

11\. 委托记录是否显示失败记录。

12\. 隐藏成就完成前的显示方式。

13\. 历史战绩保存数量上限。

14\. 战绩是否允许收藏 / 标记重点记录。

15\. 红点批量清除规则。

16\. 长期系统是否显示资源数量，若显示，应限制在哪些模块。

17\. 抽奖是否显示奖池中已拥有 / 未拥有内容。

18\. 收藏 / 外观是否显示唯一藏品来源。

19\. 资历奖励是否通过目标系统领取，还是个人资历内领取。

20\. 后续是否需要把研究从长期系统一级入口降为个人资历或图鉴下的子入口。

```

\## 20. 总结



长期系统的最终结构应做到：



```text

简洁

可查找

不混乱

不越界

可扩展

```



推荐一级结构：



```text

目标

图鉴

研究

个人资历

抽奖

收藏 / 外观

```



其中：



```text

目标 = 任务 / 成就 / 委托记录

个人资历 = 资历等级 / 历史战绩 / 数据统计 / 里程碑 / 称号

```



核心边界：



```text

仓库独立。

图鉴只查看。

研究只解锁。

抽奖只抽取。

收藏 / 外观只展示与配置。

个人资历记录长期履历。

目标系统管理行为驱动利益。

资产通过事件流通。

```



该结构能够在不破坏产品内容边界的前提下，让玩家更容易找到对应内容，并为后续资产管理、红点提示、抽奖产物、历史战绩、目标奖励和出发探索解锁提供统一接口。
