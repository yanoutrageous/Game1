# 《灰尾回收 / 五四三二一》出发探索界面与出勤准备规则策划案

## 修正版 v0.2

### 文档定位

本案用于定义“出发探索”系统的正式规则结构、页面职责、资产流向、目标选择、仓库与申领分工、出勤配置、进行中探索处理、放弃探索处理，以及后续扩展接口。

本案是对旧版《出发探索界面与出勤准备规则策划案 v0.1》的修订与补全。

若本案与旧版存在冲突，以本案明确写出的修正项为准。
未被本案修改的旧版规则继续沿用。

---

# 0. 相对旧版的主要修正

本案对旧版做出以下结构修正：

1. 旧版“作业许可”一级页签不再作为当前版本正式可玩页签。
2. 当前版本改为五个一级页签：地图、仓库、申领、目标、出勤配置。
3. “目标”页签用于承载本局目标 / 委托选择，替代旧版作业许可页签的当前可见位置。
4. “作业许可”降级为后续扩展接口，不设置当前版本的许可槽、许可容量、许可启用、许可消耗、许可互斥。
5. “申领”不再理解为临时补给直接加入本局配置，而是 catalog-first 的可购买、可领取、可回收目录。
6. “仓库”不再只是极窄的出勤物品查看页，而是 ownership-first 的已有资产管理页。
7. 仓库与申领共用同一套资产事件流，但页面视角不同。
8. 情报、服务不作为当前版本独立系统。相关效果优先作为消耗品标签、特殊物效果或后续接口处理。
9. 容量统一使用“背包容量”口径，不新增“补给容量”概念。
10. 藏品可出售，但局内普通背包不允许自由出售；出售只能在指定功能区发生。
11. 地图拓扑差异需要影响部分消耗品效果说明，例如矩形地图与蜂窝地图的相邻范围不同。
12. 基础装备默认进入长期仓库，除非明确标记为临时租借。
13. 放弃探索作为独立结果处理，不等同于成功撤离，也不完全等同于普通失败。
14. 出发探索结构必须预留后续修改接口，避免把物品、地图、目标、许可、交易规则写死在页面逻辑中。

# 1. 本阶段不讨论内容

本案不讨论以下内容：

1. 具体数值；
2. 具体价格；
3. 购买成本；
4. 出售倍率；
5. 掉率；
6. 收益倍率；
7. 容量具体数值；
8. 物品正式名称；
9. 地图正式名称；
10. 难度正式名称；
11. 按钮文案；
12. 描述文本；
13. 奖励具体数值；
14. 敌人具体数值；
15. 正式 UI 美术表现；
16. 具体动效参数。

本案只讨论：

1. 页面职责；
2. 功能边界；
3. 资产流向；
4. 购买、出售、领取、入仓、带入、结算之间的关系；
5. 当前版本开放范围；
6. 后续接口；
7. 系统之间的归属；
8. 可维护结构。

# 2. 出发探索系统定位

出发探索是局外系统中的本局准备中心。

它负责把玩家的局外资产、长期解锁、地图选择和本局目标转化为本局开局条件。

它回答以下问题：

1. 这一局去哪；
2. 这一局使用什么地图规则；
3. 这一局选择什么难度；
4. 这一局带哪些装备；
5. 这一局带哪些消耗品；
6. 这一局是否带入特殊物；
7. 这一局接取什么本局目标 / 委托；
8. 当前配置是否合法；
9. 背包是否超限；
10. 当前还有哪些风险；
11. 是否开始新探索；
12. 若已有进行中探索，是否继续或放弃。

一句话定位：

> 出发探索是把局外资产、长期解锁与本局目标整理为 RunStartConfig / DeployConfig 的准备系统。

# 3. 出发探索不负责内容

出发探索不负责：

1. 完整长期任务管理；
2. 完整成就系统；
3. 完整图鉴浏览；
4. 完整研究系统；
5. 完整抽奖系统；
6. 完整收藏 / 外观系统；
7. 局内真实地图生成；
8. 真实 Boss 信息生成；
9. 真实撤离点生成；
10. 真实房间内容生成；
11. 结算报告本体；
12. 历史战绩本体；
13. 长期奖励领取；
14. 复杂数值平衡展示；
15. 全部文案定稿。

# 4. 当前版本一级页签

当前版本出发探索采用五个一级页签：

1. 地图；
2. 仓库；
3. 申领；
4. 目标；
5. 出勤配置。

旧版“作业许可”不再作为当前版本一级页签。

# 5. 五个页签的核心分工

## 5.1 地图

地图页负责：

1. 地图模式选择；
2. 难度选择；
3. 区域或地图类别选择；
4. 解锁状态显示；
5. 模糊风险倾向显示；
6. 模糊收益倾向显示；
7. 当前配置适配提示；
8. 后续开放地图类型的锁定提示。

地图页不负责：

1. 显示真实地图布局；
2. 显示 Boss 位置；
3. 显示 Boss 类型；
4. 显示撤离点位置；
5. 显示具体怪物房；
6. 显示具体宝箱房；
7. 显示具体事件房；
8. 显示本局真实随机结果。

## 5.2 仓库

仓库页是 ownership-first 页面。

仓库页负责：

1. 查看当前已拥有物品；
2. 管理已有装备；
3. 管理已有消耗品；
4. 管理已有藏品；
5. 管理已有特殊物；
6. 查看是否可出勤；
7. 查看是否可出售；
8. 出售已有可出售物；
9. 将已有物品加入本次出勤；
10. 将已配置物品移出本次出勤；
11. 查看物品详情；
12. 跳转图鉴、收藏、目标或申领关联入口。

仓库页不负责：

1. 展示全部可购买目录；
2. 展示全部未解锁商品；
3. 管理完整申领目录；
4. 管理抽奖；
5. 管理研究；
6. 管理图鉴本体；
7. 管理外观配置本体；
8. 管理历史战绩；
9. 管理结算报告。

## 5.3 申领

申领页是 catalog-first 页面。

申领页负责：

1. 展示当前可购买内容；
2. 展示当前可领取内容；
3. 展示当前可回收内容；
4. 展示未解锁但允许预览条件的内容；
5. 展示与当前地图、目标、仓库状态相关的推荐内容；
6. 触发购买事件；
7. 触发领取事件；
8. 触发合法出售 / 回收事件；
9. 将购买或领取结果写入长期仓库。

申领页不负责：

1. 绕过仓库直接创建临时本局物资；
2. 管理完整已有物品列表；
3. 替代仓库的已有物管理；
4. 替代目标页；
5. 替代长期系统；
6. 替代抽奖；
7. 替代研究。

## 5.4 目标

目标页用于选择本局目标 / 委托。

目标页负责：

1. 显示当前可选本局目标；
2. 显示目标是否与当前地图匹配；
3. 显示目标是否与当前难度匹配；
4. 显示目标是否需要特定装备、消耗品、特殊物或长期解锁；
5. 显示目标完成条件；
6. 显示目标失败条件；
7. 显示目标奖励类型；
8. 将已选目标写入出勤配置。

目标页不负责：

1. 长期任务管理；
2. 成就领取；
3. 长期目标总览；
4. 研究管理；
5. 图鉴管理；
6. 历史战绩本体；
7. 抽奖；
8. 收藏 / 外观系统。

## 5.5 出勤配置

出勤配置页是最终收口页。

出勤配置页负责：

1. 汇总当前地图选择；
2. 汇总当前难度选择；
3. 汇总当前目标选择；
4. 汇总当前已带装备；
5. 汇总当前已带消耗品；
6. 汇总当前已带特殊物；
7. 显示背包容量；
8. 显示配置合法性；
9. 显示风险提示；
10. 显示开始探索；
11. 显示继续探索；
12. 显示放弃当前探索；
13. 输出本局启动配置。

出勤配置页不负责重新展开完整选择器。
每个配置块只显示摘要与修改入口，修改时回跳对应页签。

# 6. 地图页规则

## 6.1 已确定原则

地图页只决定本局地图相关参数。
真实地图内容在点击开始探索后生成。

地图页允许显示：

1. 地图模式；
2. 难度；
3. 区域主题；
4. 解锁状态；
5. 模糊风险倾向；
6. 模糊收益倾向；
7. 基础规则；
8. 是否支持特殊地图类型；
9. 当前配置适配提示；
10. 是否存在目标相关提示。

地图页禁止显示：

1. 真实地图布局；
2. Boss 房位置；
3. Boss 类型；
4. 撤离点位置；
5. 具体怪物房；
6. 具体宝箱房；
7. 具体事件房；
8. 具体房间分布；
9. 本局真实随机结果。

## 6.2 当前地图类型与后续扩展

当前版本以已确定的地图类型为准。

后续地图类型可以作为预留项存在，但必须明确状态：

1. 已开放；
2. 未解锁；
3. 后续开放；
4. 暂不显示。

未实装的地图类型不得伪装为当前可进入内容。

## 6.3 地图拓扑影响消耗品效果

部分消耗品效果会随地图类型变化。

例如探测类消耗品不应写死为“探测周围 8 格”，而应定义为：

> 探测当前房间周围相邻房间。

然后由地图拓扑决定实际范围：

1. 矩形地图：周围 8 邻域；
2. 蜂窝地图：周围 6 邻域；
3. 特殊地图：按该地图的邻接规则；
4. 多层地图：按该地图的层级与邻接规则。

出发探索在显示消耗品效果时，应允许根据当前地图类型生成说明。

示例结构：

1. 效果本体：探测相邻房间；
2. 当前地图类型：矩形；
3. 本局实际表现：探测周围 8 个相邻格；
4. 当前地图类型：蜂窝；
5. 本局实际表现：探测周围 6 个相邻格。

本阶段不讨论该效果的具体数值与文案，只规定接口必须存在。

## 6.4 地图与目标关系

地图页可以提示：

1. 当前地图支持哪些目标类型；
2. 当前地图是否存在推荐目标；
3. 当前地图是否与已选目标匹配；
4. 当前地图是否导致目标不可用；
5. 当前地图是否需要后续许可接口。

但地图页不执行目标接取。
目标选择在目标页完成。

# 7. 仓库页规则

## 7.1 仓库页定位

仓库页用于管理玩家当前已拥有资产。

它关注 ownership，即玩家已经拥有什么。

仓库页不是申领目录，也不是完整商城目录。

## 7.2 仓库主分类

仓库主分类为：

1. 装备；
2. 消耗品；
3. 藏品；
4. 特殊物。

不作为主分类的内容：

1. 外观；
2. 唯一；
3. 未判断价值；
4. 任务物；
5. 委托物；
6. 样本。

处理规则：

1. 唯一是藏品的一种特殊稀有档；
2. 外观是外观解锁，不是仓库物品；
3. 未判断价值是物品状态；
4. 任务物、委托物、样本归入特殊物，并通过标签表达。

## 7.3 仓库辅助标签

仓库可以使用以下辅助标签：

1. 可出勤；
2. 已配置；
3. 可出售；
4. 不可出售；
5. 唯一；
6. 委托相关；
7. 目标相关；
8. 图鉴关联；
9. 收藏关联；
10. 研究相关；
11. 未判断；
12. 已锁定；
13. 新获得。

辅助标签不能改变主类型。

## 7.4 仓库操作

仓库允许：

1. 查看物品；
2. 查看详情；
3. 装备；
4. 卸下；
5. 加入出勤；
6. 移出出勤；
7. 出售可出售物；
8. 查看出售价值；
9. 跳转申领来源；
10. 跳转图鉴；
11. 跳转收藏；
12. 跳转目标关联。

仓库不允许：

1. 展示全部未拥有商品目录；
2. 管理完整申领目录；
3. 管理抽奖；
4. 管理研究树；
5. 管理图鉴本体；
6. 管理外观配置本体；
7. 管理历史战绩；
8. 管理结算报告。

## 7.5 仓库购买行为

仓库可以提供与当前已拥有物品相关的购买入口，例如：

1. 补购同类消耗品；
2. 从物品详情跳转到申领来源；
3. 对当前物品显示可购买来源；
4. 对当前装备显示相关配套物品来源。

但完整可购买目录由申领页维护。

仓库不维护独立商品表。
仓库内的购买行为必须调用申领目录或统一购买事件。

## 7.6 仓库出售行为

仓库可以出售已有可出售物品。

出售前必须检查：

1. 玩家是否拥有该物品；
2. 该物品是否可出售；
3. 该物品是否唯一；
4. 该物品是否锁定；
5. 该物品是否与当前目标绑定；
6. 该物品是否已加入本次出勤；
7. 当前出售场景是否允许出售。

普通藏品可以出售。
唯一藏品不可通过常规出售逻辑出售。
特殊物是否可出售由 sell_policy 决定。
装备、消耗品是否可出售由各自 policy 决定。

## 7.7 已配置物品出售冲突

若物品已加入本次出勤配置，默认不能直接出售。

第一版规则：

1. 必须先从出勤配置中移除；
2. 移除后才能出售；
3. 出售后刷新仓库数量；
4. 出售后刷新出勤配置合法性；
5. 出售后刷新右侧摘要。

后续可以扩展为“出售时自动移出出勤并二次确认”，但当前版本不默认启用。

# 8. 申领页规则

## 8.1 申领页定位

申领页用于展示后勤当前可购买、可领取、可回收、可解锁的内容目录。

它关注 catalog，即当前系统能提供什么。

申领页不是仓库页。
申领页不是临时补给页。
申领页不是独立资产账本。

## 8.2 申领页可显示内容

申领页可以显示：

1. 可购买装备；
2. 可购买消耗品；
3. 可购买特殊物；
4. 可领取基础装备；
5. 可领取基础消耗品；
6. 可回收物品类型；
7. 已解锁但当前资源不足的内容；
8. 未解锁但允许预览条件的内容；
9. 与当前地图相关的推荐内容；
10. 与当前目标相关的推荐内容；
11. 与当前仓库缺口相关的推荐内容。

申领页不显示完整外观库。
申领页不承担抽奖。
申领页不承担长期奖励领取。
申领页不承担图鉴本体。
申领页不承担研究树。

## 8.3 申领与仓库关系

仓库与申领共用同一套资产事件流。

二者区别：

1. 仓库是 ownership-first 页面；
2. 申领是 catalog-first 页面；
3. 仓库从“我已经拥有什么”出发；
4. 申领从“现在能买、能领、能回收什么”出发；
5. 仓库可以出售已有物；
6. 申领可以展示可回收目录，并在玩家拥有对应物时触发出售；
7. 购买、领取、出售、入仓、带入都写入同一资产系统。

## 8.4 购买流程

申领购买流程：

1. 玩家在申领页选择可购买内容；
2. 系统检查是否已解锁；
3. 系统检查是否资源足够；
4. 执行购买事件；
5. 消耗通用资产；
6. 获得对应物品；
7. 物品进入长期仓库；
8. 仓库页刷新；
9. 该物品可从仓库加入本次出勤。

购买不直接绕过仓库创建临时本局物品。

## 8.5 领取流程

申领领取流程：

1. 玩家在申领页选择可领取内容；
2. 系统检查领取条件；
3. 执行领取事件；
4. 获得对应物品；
5. 物品进入长期仓库；
6. 仓库页刷新；
7. 该物品可从仓库加入本次出勤。

基础装备默认进入长期仓库。
基础消耗品默认进入长期仓库。
除非物品明确标记为临时租借，否则玩家有权保留和后续调用。

## 8.6 回收 / 出售目录

申领页可以显示后勤当前接受回收的内容类型。

申领页中的出售必须满足：

1. 玩家拥有该物品；
2. 该物品可出售；
3. 当前回收目录接受该物品；
4. 该物品未被锁定；
5. 该物品不是不可出售的唯一藏品；
6. 该物品未加入当前出勤配置，或已先移出配置。

申领页的回收目录不是“出售未拥有物品”。
它只是提供 catalog 视角下的可回收内容范围。

## 8.7 购买并加入出勤

申领页可以提供快捷操作：

1. 购买；
2. 购买并加入出勤；
3. 领取；
4. 领取并加入出勤。

但“购买并加入出勤”在规则上必须拆为两个事件：

1. PurchaseEvent / ClaimEvent；
2. AddToLoadoutEvent。

不得将其做成绕过仓库的临时物资。

## 8.8 情报与服务处理

当前版本不设置独立“情报系统”。
当前版本不设置独立“服务系统”。

原本可能属于情报或服务的效果，当前优先按以下方式处理：

1. 情报类效果：消耗品标签；
2. 探测类效果：消耗品标签；
3. 撤离类效果：消耗品标签；
4. 保障类效果：消耗品标签或后期接口；
5. 保险：后期接口；
6. 托运：后期接口；
7. Boss 侦察：后期接口；
8. 特殊后勤服务：后期接口。

申领页可以售卖带有“情报类”“探测类”“撤离类”“保障类”等标签的消耗品，但不建立独立情报 / 服务大类系统。

## 8.9 基础装备处理

基础装备默认属于装备。
基础装备默认进入长期仓库。

系统赠送、购买、领取得到的装备都属于玩家资产，除非明确标记为临时租借。

临时租借装备必须具备特殊 policy：

1. ownership_policy = 临时租借；
2. end_run_policy = 本局结束归还；
3. sell_policy = 不可出售；
4. warehouse_policy = 临时显示或不进入长期仓库。

没有特殊 policy 的基础装备，均可保留、调用、带入、查看、按规则出售或丢失。

# 9. 目标页规则

## 9.1 目标页定位

目标页用于本局目标 / 委托选择。

它替代旧版作业许可页签，成为出发探索中的第五个可见页签。

目标页只处理本局目标，不处理长期目标系统全貌。

## 9.2 目标页负责内容

目标页负责：

1. 显示当前可接本局目标；
2. 显示目标是否可接；
3. 显示目标锁定条件；
4. 显示目标与当前地图的关系；
5. 显示目标与当前难度的关系；
6. 显示目标与当前装备或消耗品的关系；
7. 显示目标与长期解锁的关系；
8. 显示目标完成条件；
9. 显示目标失败条件；
10. 显示目标奖励类型；
11. 选择本局目标；
12. 将目标写入出勤配置。

## 9.3 目标页不负责内容

目标页不负责：

1. 长期任务列表管理；
2. 长期成就领取；
3. 长期目标总览；
4. 历史战绩本体；
5. 图鉴管理；
6. 研究管理；
7. 抽奖；
8. 外观配置；
9. 结算报告本体。

## 9.4 目标来源

本局目标可以来自：

1. 常规委托池；
2. 地图关联目标池；
3. 难度关联目标池；
4. 教学目标池；
5. 长期系统提供的当前可用目标池；
6. 后续特殊接口提供的目标池。

接取动作发生在出发探索目标页中。
长期系统只记录、解锁、展示或汇总，不直接替玩家接取本局目标。

## 9.5 目标类型

目标类型可以包括：

1. 回收类；
2. 探索类；
3. 战斗类；
4. 事件类；
5. 撤离类；
6. 限制类；
7. 教学类；
8. 高危类。

本案不讨论具体目标名称、具体奖励、具体数值。

## 9.6 目标选择数量

当前版本建议一局默认选择 0 到 1 个本局目标。

后续可通过长期解锁或特殊机制扩展多目标，但本案不展开。

## 9.7 目标失败

目标失败不等同于探索失败。

目标失败可能导致：

1. 失去目标奖励；
2. 记录目标未完成；
3. 进入结算报告；
4. 进入历史战绩；
5. 推动长期目标或成就统计。

高危目标是否附带额外惩罚，由目标定义决定。
本案不讨论具体惩罚数值。

# 11. 出勤配置页规则

## 11.1 页面定位

出勤配置页是本局开始前的最终收口页面。

它展示：

1. 当前已选地图；
2. 当前已选难度；
3. 当前已选目标；
4. 当前已带装备；
5. 当前已带消耗品；
6. 当前已带特殊物；
7. 当前背包占用；
8. 当前配置是否合法；
9. 当前风险提示；
10. 是否可以开始探索。

## 11.2 出勤配置页不负责

出勤配置页不负责：

1. 展开完整地图选择器；
2. 展开完整仓库列表；
3. 展开完整申领目录；
4. 展开完整目标列表；
5. 管理长期系统；
6. 管理结算系统。

修改动作通过回跳对应页签完成。

## 11.3 出勤配置显示字段

出勤配置页应显示：

1. 地图摘要；
2. 难度摘要；
3. 目标摘要；
4. 装备摘要；
5. 消耗品摘要；
6. 特殊物摘要；
7. 背包：已用 / 上限；
8. 购买但未带入提示；
9. 配置缺口；
10. 风险提示；
11. 继续探索状态；
12. 放弃探索入口；
13. 开始探索入口。

## 11.4 背包容量规则

本案统一使用“背包容量”概念。

不新增“补给容量”。

背包容量用于表达：

1. 本次出勤携带物占用；
2. 局内拾取物占用；
3. 成功撤离带回物品；
4. 失败保底或抢救规则；
5. 放弃结算中的物品处理。

装备是否占背包、消耗品是否占背包、特殊物是否占背包，由物品 policy 决定。

仓库库存本身不占出勤背包容量。
购买后入仓的物品，只有加入本次出勤或进入局内背包时才参与容量计算。

## 11.5 配置合法性检查

开始探索前至少检查：

1. 是否选择地图；
2. 是否选择难度；
3. 是否存在进行中探索；
4. 是否超出背包容量；
5. 是否携带不可出勤物；
6. 是否选择不可用目标；
7. 是否缺少目标要求条件；
8. 是否资源不足；
9. 是否存在已出售但仍显示在出勤配置中的物品；
10. 是否存在未解锁内容；
11. 是否需要二次确认。

## 11.6 购买但未带入

如果玩家在申领页购买或领取物品，但未加入本次出勤：

1. 物品进入仓库；
2. 不进入本局启动配置；
3. 不显示在已携带列表；
4. 可在仓库页查看；
5. 可后续加入出勤；
6. 不影响本局配置合法性，除非目标或系统要求该物品必须带入。

# 13. 购买、出售、领取、带入统一流程

## 13.1 购买流程

1. 玩家在申领页或仓库关联购买入口选择商品；
2. 系统检查解锁条件；
3. 系统检查资源是否足够；
4. 执行购买事件；
5. 消耗通用资产；
6. 获得物品；
7. 物品进入长期仓库；
8. 仓库刷新；
9. 出勤配置刷新；
10. 玩家可选择是否加入本次出勤。

## 13.2 领取流程

1. 玩家在申领页选择可领取内容；
2. 系统检查领取条件；
3. 执行领取事件；
4. 获得物品；
5. 物品进入长期仓库；
6. 仓库刷新；
7. 玩家可选择是否加入本次出勤。

## 13.3 出售流程

1. 玩家在合法出售场景选择物品；
2. 系统检查玩家是否拥有；
3. 系统检查物品是否可出售；
4. 系统检查物品是否唯一；
5. 系统检查物品是否锁定；
6. 系统检查物品是否目标相关；
7. 系统检查物品是否已加入出勤；
8. 若已加入出勤，需先移出；
9. 执行出售事件；
10. 移除或减少物品；
11. 获得通用资产；
12. 刷新仓库、申领、出勤配置和右侧摘要。

## 13.4 加入出勤流程

1. 玩家从仓库选择可出勤物品；
2. 系统检查玩家是否拥有；
3. 系统检查物品是否可出勤；
4. 系统检查背包容量；
5. 系统检查目标或地图限制；
6. 加入本次出勤配置；
7. 更新背包已用；
8. 更新右侧摘要；
9. 更新出勤配置合法性。

## 13.5 移出出勤流程

1. 玩家从出勤配置或仓库页移出物品；
2. 物品回到仓库拥有状态；
3. 背包已用刷新；
4. 目标条件刷新；
5. 出勤配置合法性刷新。

## 13.6 开始探索流程

1. 玩家完成地图、仓库、申领、目标、出勤配置；
2. 系统检查配置合法性；
3. 系统生成本局启动配置；
4. 出发探索不提前生成真实地图内容；
5. RunBootstrapper 根据启动配置创建本局；
6. 本局创建后配置锁定；
7. 玩家进入局内探索。

# 14. 进行中探索与继续探索

## 14.1 有进行中探索时

当存在进行中探索：

8. 玩家可以继续探索；
9. 玩家可以放弃当前探索；
10. 放弃必须强确认。

## 14.2 主菜单不显示继续探索

主菜单仍显示“出发探索”。

开始、继续、放弃的判断发生在出发探索页内部。

# 15. 放弃探索

## 15.1 放弃入口

放弃探索应存在两个入口：

1. 出发探索页：放弃当前进行中探索；
2. 局内暂停 / 设置页：放弃当前探索。

只在出发探索页存在放弃入口是不完整的。

## 15.2 放弃定义

放弃探索是玩家主动中止当前探索。

放弃不等于成功撤离。
放弃也不完全等同普通失败。

## 15.3 成功、失败、放弃区别

成功撤离：

1. 通过撤离条件结束；
2. 物品按成功规则进入仓库；
3. 黑币或收益按成功规则处理；
4. 目标按完成情况结算；
5. 历史记录为成功。

普通失败：

1. 由局内风险导致；
2. 可触发失败保底或抢救；
3. 记录为失败；
4. 可计入失败类统计。

放弃 / 中止：

1. 由玩家主动触发；
2. 不算成功撤离；
3. 不触发成功撤离收益；
4. 不计入被击败 / 死亡类失败统计；
5. 局内物品默认不入仓；
6. 黑币默认不转化；
7. 消耗品按本局结束规则清空；
8. 图鉴发现和探索记录可按规则部分保留；
9. 目标一般视为失败或未完成；
10. 历史战绩记录为放弃 / 中止。

## 15.4 放弃后结算

放弃后仍进入本局结算报告。

结算报告应显示：

1. 本局结果：放弃 / 中止；
2. 未成功撤离；
3. 消耗品清空；
4. 未带回物品；
5. 目标失败或未完成；
6. 可保留的记录型内容；
7. 是否触发后期保险 / 托运 / 抢救接口。

本案不讨论放弃保留内容的具体数值。

# 16. 出售场景规则

## 16.1 允许出售的场景

允许出售的场景包括：

1. 局外仓库；
2. 申领页回收目录；
3. 局内指定功能区；
4. 后续商人、回收终端、特殊事件等合法交易节点。

## 16.2 不允许出售的场景

不允许出售的场景包括：

1. 局内普通背包界面；
2. 非交易型局内 UI；
3. 普通探索界面；
4. 临时弹窗；
5. 结算展示中未进入出售流程的普通结果页。

## 16.3 藏品出售

普通藏品可以出售。
唯一藏品不进入常规出售流程。
局内普通背包不允许直接出售藏品。
局内出售藏品必须通过指定功能区。

# 17. 消耗品规则

## 17.1 消耗品归属

消耗品是实体物品。

消耗品可以：

1. 进入仓库；
2. 在申领页购买或领取；
3. 从仓库加入出勤；
4. 在局内使用；
5. 按规则消耗；
6. 按本局结束规则清空或处理。

## 17.2 消耗品标签

消耗品可以拥有以下标签：

1. 情报类；
2. 探测类；
3. 撤离类；
4. 保障类；
5. 战斗类；
6. 搜索类；
7. 特殊类。

这些标签不构成独立系统。

## 17.3 消耗品与地图拓扑

消耗品效果可以读取当前地图拓扑。

例如：

1. 探测相邻房间；
2. 标记周边风险；
3. 影响邻接房间信息；
4. 读取特殊地图邻接规则。

效果描述不应硬编码为固定格数，而应允许由地图类型解释。

# 18. 基础装备规则

基础装备默认进入长期仓库。

基础装备可以来自：

1. 系统赠送；
2. 申领领取；
3. 申领购买；
4. 目标奖励；
5. 结算获得；
6. 其它合法资产事件。

基础装备默认属于玩家资产，除非被明确标记为临时租借。

临时租借装备必须有明确 policy，不得默认适用于所有基础装备。

# 19. 保险、托运与许可接口

## 19.1 当前版本处理

当前版本不开放完整保险系统。
当前版本不开放完整托运系统。
当前版本不开放完整作业许可系统。

## 19.2 后续接口

保险、托运、特殊准入、高级内容解锁可通过后续接口接入。

建议接口字段：

1. required_permission；
2. unlock_condition；
3. future_hook；
4. protection_policy；
5. settlement_policy；
6. rescue_policy。

当前版本只显示：

1. 后续开放；
2. 未解锁；
3. 需要条件；
4. 当前不可用。

不展开具体规则。

# 20. 与长期系统的关系

长期系统负责：

1. 长期目标；
2. 任务；
3. 成就；
4. 图鉴；
5. 研究；
6. 个人资历；
7. 抽奖；
8. 收藏 / 外观；
9. 长期记录；
10. 长期解锁。

出发探索只读取长期系统提供的可用项和解锁状态。

出发探索不直接管理长期系统本体。
长期系统不直接替玩家选择本局出勤配置。

目标页中的本局目标 / 委托可以来自长期系统提供的目标池，但选择动作发生在出发探索。

---

# 21. 与结算报告的关系

出发探索产生本局启动配置。
局内结束后由结算报告处理结果。
仓库、图鉴、目标、历史战绩、资历等通过结算事件更新。

出发探索不展示完整结算报告。
出发探索可以作为结算后可跳转目标之一。

放弃探索同样进入结算报告。

# 24. 最低验收标准

出发探索 v0.2 完成后，应满足：

1. 页面包含地图、仓库、申领、目标、出勤配置五个一级页签；
2. 作业许可不再作为当前玩家主动配置页签；
3. 地图页不提前生成真实地图内容；
4. 地图页能显示可用、锁定、后续开放状态；
5. 地图拓扑能影响部分消耗品效果说明；
6. 仓库页显示当前已拥有物；
7. 仓库页按装备、消耗品、藏品、特殊物分类；
8. 仓库页能出售已有可出售物；
9. 仓库页能将可出勤物加入本次配置；
10. 申领页显示可购买、可领取、可回收目录；
11. 申领页购买或领取后物品进入长期仓库；
12. 申领页不绕过仓库创建临时本局物资；
13. 目标页能选择本局目标 / 委托；
14. 出勤配置页能汇总地图、目标、装备、消耗品、特殊物与背包容量；
15. 出勤配置页能判断是否可开始探索；
16. 有进行中探索时，只能继续或放弃，不能直接开始新探索；
17. 放弃探索需要强确认；
18. 局内暂停 / 设置页存在放弃探索入口；
19. 成功、失败、放弃能进入不同结算结果；
20. 购买、出售、领取、带入、移出、结算均通过统一资产事件流。

# 26. 总结

出发探索 v0.2 的最终结构为：

1. 地图：选择本局地图、难度与地图规则，不提前生成真实内容；
2. 仓库：管理当前已拥有资产，支持出售、带入、装备、查看；
3. 申领：管理当前可购买、可领取、可回收目录；
4. 目标：选择本局目标 / 委托，替代旧版作业许可页；
5. 出勤配置：汇总本局最终配置，判断合法性，开始 / 继续 / 放弃探索。

核心修正是：

1. 目标替代许可；
2. 许可降级为后续接口；
3. 仓库与申领分离但共用资产流；
4. 情报 / 服务不作为当前独立系统；
5. 容量统一为背包容量；
6. 局内普通背包不允许自由出售；
7. 地图拓扑影响消耗品效果；
8. 购买 / 出售 / 领取 / 带入 / 结算全部通过统一事件流。

本案完成后，玩家在出发探索中应能清楚理解：

1. 我去哪；
2. 我带什么；
3. 我买了什么；
4. 我卖了什么；
5. 我当前拥有多少；
6. 我本局要做什么目标；
7. 我还有多少背包容量；
8. 我是否准备好开始探索；
9. 若已有探索，我是否继续或放弃。
