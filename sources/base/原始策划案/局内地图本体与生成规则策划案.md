# 《灰尾回收 / 五四三二一》局内地图本体与生成规则策划案

## 独立策划案

## 0. 文档定位

本案用于定义局内地图本体、地图生成规则、小地图 / 展开地图、地图信息层、房间身份、房间状态、地图事件变更、传送 / 回传、地图测试工具与后续扩展接口。

本案不是既有基础策划案的版本修订号，不命名为 v0.3、v0.4 或其它版本补丁。
本案作为独立策划案，用于承接和细化局内地图系统。

本案讨论范围包括：

1. 地图本体；
2. 地图生成规则；
3. 随机种子与规则管线；
4. 普通模式与评委模式的地图生成差异；
5. 地图真实层、玩家已知层、扫描层、标记层、污染 / 可信度层；
6. 房间类型；
7. 房间状态；
8. 房间内容与遭遇调用；
9. 小地图；
10. 展开地图；
11. 点击房间后的信息展示；
12. 已探索房间回传 / 传送；
13. 一次性事件与持续性事件对地图的影响；
14. 地图调试、测试、批量生成与规则版本管理。

本案不讨论：

1. 具体数值；
2. 正式 UI 美术；
3. 最终按钮文案；
4. 最终键鼠 / 手柄 / 移动端操作方案；
5. 具体房间奖励表；
6. 具体怪物数值；
7. 具体事件文本；
8. 具体地图尺寸；
9. 具体掉落概率。

---

# 1. 地图系统核心定位

地图不是单纯背景图，也不是单纯格子数组。

地图是本局探索的核心承载体，负责记录：

1. 本局空间结构；
2. 每个格子的基础房间类型；
3. 每个房间的真实状态；
4. 玩家当前已知的信息；
5. 玩家主动标记的信息；
6. 扫描、事件、道具等产生的额外信息；
7. 区域信息是否可信；
8. 房间是否已探索、已清理、已触发、已耗尽；
9. 地图级压力、污染、封锁、规则变化；
10. 本局结束后需要交给结算和历史战绩的地图相关数据。

一句话定位：

> 地图是局内空间结构、信息推理、风险分布、事件承载和探索记录的统一载体。

# 2. 已有规则前提

本案在以下已定规则基础上展开。

## 2.1 当前主地图类型

当前主地图类型为：

```text
经典矩形扫雷地图
```

后续可扩展：

1. 蜂窝地图；
2. 特殊规则地图；
3. 多层地图；
4. 节点式地图；
5. 混合拓扑地图。

当前版本不强制实现后续地图类型，但地图本体和生成系统必须为它们预留接口。

---

## 2.2 普通模式

普通模式规则：

1. 地图随机生成；
2. 出生点随机生成；
3. 撤离格随机生成；
4. 撤离格初始隐藏；
5. 不保证出生点到撤离格之间存在安全路径；
6. 不保证出生点周围安全；
7. 不保证撤离格周围安全；
8. 不追求传统扫雷意义上的全局“无猜”；
9. 普通模式只要求地图数据合法、规则可信、基础流程可运行；
10. 随机局失败由失败保底、局外成长、玩家带入物和风险判断共同承接。

---

## 2.3 评委模式

评委模式规则：

1. 地图完全手排；
2. 节点完全固定；
3. 出生点、雷房、怪物房、宝箱房、事件房、撤离格均由配置指定；
4. 可通过内部调试面板调整展示用数据；
5. 评委模式用于稳定展示一次完整局内与局外流程；
6. 评委模式不作为普通模式平衡依据；
7. 评委模式仍复用普通模式的房间、战斗、背包、事件、协议、结算和仓库系统。

---

## 2.4 房间类型互斥

当前版本中，每个格子只存在一个基础房间类型。

当前基础房间类型包括：

1. 出生点；
2. 普通房；
3. 雷房；
4. 怪物房；
5. 宝箱房；
6. 事件房；
7. 撤离格。

规则：

1. 一个格子不会同时是雷房和撤离格；
2. 一个格子不会同时是怪物房和事件房；
3. 一个格子不会同时是宝箱房和雷房；
4. 出生点不会与其它房型重叠；
5. 小地图当前不处理同格多基础房型叠加；
6. 房间触发逻辑当前不处理复合房型结算顺序。

允许在基础房型之外增加标签，但标签不能让一个格子同时成为两个基础房型。

示例：

```text
允许：
主类型 = 事件房
标签 = 高危 / 目标相关 / 已触发

不允许：
主类型 = 事件房 + 怪物房
```

复合房间可作为未来扩展，但不是当前基础规则。

---

## 2.5 扫雷数字规则

当前矩形地图采用经典 8 邻域雷数计算。

规则：

1. 当前格周围 8 格参与雷数计算；
2. 雷房计入数字；
3. 怪物房不计入数字；
4. 宝箱房不计入数字；
5. 事件房不计入数字；
6. 撤离格不计入数字；
7. 出生点不计入数字；
8. 普通房不计入数字；
9. 所有已探索非雷房仍应显示周围雷数；
10. 特殊房间图标不能遮挡雷数。

后续蜂窝地图、特殊地图、多层地图可以改变邻接规则，但不能让消耗品、地图 UI 或房间逻辑写死“8 格”。

---

## 2.6 小地图状态

地图格基础状态包括：

1. 未知；
2. 已扫描；
3. 已探索；
4. 已清理。

规则：

1. 未知格未被进入，也未被扫描；
2. 已扫描格只被道具、事件或系统揭示了有限信息；
3. 已扫描不等于已探索；
4. 已扫描格不能传送；
5. 已扫描格不能触发事件；
6. 已扫描格不增加协议压力；
7. 已探索格是玩家亲自进入过的格子；
8. 已清理格是已探索且主要特殊内容已处理完成的格子。

---

## 2.7 传送 / 回传基础规则

地图传送 / 回传是展开地图中的回访能力。

当前基础规则：

1. 只能传送到已探索或已清理房间；
2. 未知格不能传送；
3. 已扫描但未探索格不能传送；
4. 传送不揭示新房间；
5. 传送不触发新房间事件；
6. 传送不增加协议压力；
7. 战斗进行中不能传送；
8. 陷阱演出中不能传送；
9. 事件选择中不能传送；
10. 撤离确认中不能传送；
11. 结算中不能传送。

传送 / 回传默认不进行额外全局路径寻路校验。
“可传送”主要由目标房间状态和当前锁定状态决定。

未来特殊地图、高难规则、事件封锁可以限制传送。

# 3. 地图数据分层

地图系统至少拆成以下数据层。

## 3.1 TruthMap：真实地图层

TruthMap 是系统知道、玩家未必知道的真实地图。

TruthMap 包含：

1. 地图 ID；
2. 地图类型；
3. 地图拓扑；
4. 地图种子；
5. 房间坐标；
6. 房间唯一 ID；
7. 房间基础类型；
8. 房间内容种子；
9. 房间奖励种子；
10. 房间遭遇种子；
11. 房间真实危险状态；
12. 撤离格位置；
13. 目标房位置；
14. 事件房位置；
15. 宝箱房位置；
16. 怪物房位置；
17. 雷房位置；
18. 地图生成版本；
19. 内容池版本；
20. 规则集版本。

TruthMap 不直接暴露给玩家。

---

## 3.2 KnownMap：玩家已知层

KnownMap 是玩家已经知道的信息。

KnownMap 包含：

1. 已探索房间；
2. 已扫描房间；
3. 已发现房间类型；
4. 已知雷数；
5. 已发现撤离格；
6. 已发现宝箱；
7. 已发现事件；
8. 已发现怪物 / 异常；
9. 已发现目标房；
10. 已触发的地图提示；
11. 已被污染或失真的信息提示。

KnownMap 只记录玩家应当知道的信息，不等于 TruthMap。

---

## 3.3 ScanLayer：扫描信息层

ScanLayer 记录非探索行为揭示的信息。

来源包括：

1. 消耗品；
2. 事件；
3. 研究解锁；
4. 目标提示；
5. 特殊房间；
6. 后续情报类效果；
7. 地图规则效果。

扫描信息可以包括：

1. 是否为雷房；
2. 周围雷数；
3. 房间类型倾向；
4. 撤离方向；
5. 风险倾向；
6. 目标线索；
7. 信息可信度。

扫描不等于探索。
扫描信息可以被小地图记录，但不能使房间变为已探索。

---

## 3.4 MarkMap：玩家标记层

MarkMap 记录玩家主动标记。

标记可以包括：

1. 疑似雷险；
2. 疑似安全；
3. 疑似宝箱；
4. 疑似事件；
5. 疑似撤离；
6. 疑似目标；
7. 自定义标记；
8. 取消标记。

标记不改变 TruthMap。
标记不触发事件。
标记不增加协议压力。
标记可被玩家修改。

---

## 3.5 RunMapState：本局地图状态层

RunMapState 记录本局内每个房间的当前状态。

可包含：

1. 未发现；
2. 已扫描；
3. 已探索；
4. 已清理；
5. 已触发；
6. 已搜索；
7. 已开启；
8. 已耗尽；
9. 已锁定；
10. 已封锁；
11. 已污染；
12. 已校准；
13. 已撤离；
14. 已失败触发；
15. 已完成目标关联。

RunMapState 是流程状态，不等于房间基础类型。

---

## 3.6 InfoReliabilityLayer：信息可信度层

InfoReliabilityLayer 用于表示某一区域的信息是否可信。

状态可以包括：

1. 可信；
2. 不稳定；
3. 受污染；
4. 可能失真；
5. 已校准；
6. 已清除污染。

该层用于支持污染区、异常区域、特殊规则地图和部分事件效果。

普通地图中，已揭示雷数默认可信。
如果某区域信息不可信，必须以明确规则层显示告知玩家。
不得在普通规则下暗中让已知数字或已知信息失真。

信息污染可以在小地图或展开地图中用覆盖层、遮罩、边框、符号等方式显示。具体颜色和美术表现后续确定。

# 4. 地图生成总体原则

## 4.1 生成不是一次性纯随机

地图生成不应简单理解为“一次随机填房间”。

正式结构应为：

```text
Seed
+ MapGenProfile
+ RuleSet
+ ConstraintSet
+ ModifierList
+ Validation
+ Repair / Retry
+ FinalMapSnapshot
```

其中：

1. Seed 决定基础随机序列；
2. MapGenProfile 决定地图类型、难度、尺寸、内容池；
3. RuleSet 决定基础规则；
4. ConstraintSet 决定硬约束和软约束；
5. ModifierList 记录目标、高难委托、研究、事件等修正；
6. Validation 检查地图是否合法；
7. Repair / Retry 用于局部修复或重新生成；
8. FinalMapSnapshot 是本局最终地图快照。

---

## 4.2 生成流程

推荐生成流程：

1. 确定 seed；
2. 读取 RunStartConfig；
3. 读取地图类型；
4. 读取难度；
5. 读取本局目标；
6. 读取高难委托条件；
7. 读取研究和长期解锁；
8. 组合 MapGenProfile；
9. 执行基础随机生成；
10. 应用硬约束；
11. 应用软约束；
12. 应用目标 / 事件 / 高难委托等 modifier；
13. 校验地图合法性；
14. 必要时局部修复；
15. 必要时重新生成；
16. 保存最终 TruthMap 快照；
17. 初始化 KnownMap、ScanLayer、MarkMap、RunMapState 和 InfoReliabilityLayer。

---

## 4.3 硬约束

硬约束必须满足，否则地图不合法。

当前普通模式硬约束建议包括：

1. 地图尺寸合法；
2. 出生点合法；
3. 出生点不与其它房型重叠；
4. 撤离格合法；
5. 撤离格不与其它房型重叠；
6. 每个格子只有一个基础房型；
7. 房间数量不超出地图容量；
8. 目标所需基础结构存在；
9. 地图数据可存档；
10. 地图数据可恢复。

普通模式硬约束不包括：

1. 出生点周围一圈无雷；
2. 撤离点周围一圈无雷；
3. 出生点到撤离点存在安全路径；
4. 撤离点距离出生点不超过固定范围；
5. 全局无猜；
6. 玩家一定能成功撤离。

这些只能作为教学、评委模式、特殊地图、新手保护、调试地图或后续可选规则使用。

---

## 4.4 软约束

软约束尽量满足，但可以降级。

软约束可包括：

1. 危险分布不要极端集中；
2. 目标房不要完全偏离核心探索区域；
3. 撤离格不要全部贴近出生点；
4. 宝箱房不要全贴近出生点；
5. 怪物房不要全部堆在同一区域；
6. 事件房分布尽量有探索价值；
7. 地图早期尽量提供基础信息；
8. 高难委托可以放宽软约束。

软约束失败时不一定导致地图无效。

---

## 4.5 可选保护规则

以下规则作为可选保护规则存在，不作为普通模式默认规则：

1. 出生点周围一圈无雷；
2. 撤离点周围一圈无雷；
3. 出生点到撤离点距离限制；
4. 教学路线安全；
5. 指定关键节点安全；
6. 指定目标房不被高危包围；
7. 出生点附近保证扫描信息；
8. 起始若干房间降低危险密度。

可用于：

1. 新手教学；
2. 评委模式；
3. 手排展示地图；
4. 特殊低难地图；
5. 调试地图；
6. 剧情地图；
7. 后续保护型天赋或道具。

---

## 4.6 Modifier：规则修正器

Modifier 是来自目标、难度、高难委托、事件、研究、地图模式的规则修正。

Modifier 可影响：

1. 房型权重；
2. 事件池；
3. 怪物房倾向；
4. 宝箱房倾向；
5. 撤离提示；
6. 信息可信度；
7. 房间刷新策略；
8. 回传限制；
9. 扫描结果；
10. 奖励表；
11. 目标房生成；
12. 地图污染区。

Modifier 必须记录来源。

来源可以包括：

1. 地图难度；
2. 本局目标；
3. 高难委托；
4. 研究解锁；
5. 特殊物；
6. 消耗品；
7. 事件结果；
8. 后续许可接口；
9. 特殊地图规则。

---

## 4.7 规则优先级

当规则冲突时，建议优先级为：

1. 数据合法性硬约束；
2. 房型互斥；
3. 出生点 / 撤离格合法性；
4. 本局目标必要条件；
5. 地图类型基础规则；
6. 难度规则；
7. 高难委托 modifier；
8. 事件 modifier；
9. 奖励倾向；
10. 风味规则。

若低优先级规则与高优先级规则冲突，低优先级规则应被降级、忽略或改为提示。

---

## 4.8 生成失败处理

地图生成可能失败。

失败处理顺序建议：

1. 局部修复；
2. 替换局部房间；
3. 重新放置部分关键房；
4. 降级软约束；
5. 重新生成整张地图；
6. 判定当前目标 / 高难委托组合不可用；
7. 阻止开始探索；
8. 输出调试日志。

普通玩家不应看到底层生成错误。
测试模式可以显示详细失败原因。

---

## 4.9 加载速度要求

地图生成不能无限重试，不能导致明显卡死。

需要支持：

1. 最大生成尝试次数；
2. 最大局部修复次数；
3. 超时保护；
4. 生成失败回退；
5. 调试日志；
6. 批量生成测试；
7. 异步生成或加载界面；
8. 生成缓存或预生成接口。

当前不定义具体时间数值，但要求工程实现时必须有上限和回退策略。

# 5. 房间身份与内容调用

## 5.1 房间基础身份预生成

地图开始时应确定各格子的基础房间类型与位置。

至少包括：

1. 出生点；
2. 普通房；
3. 雷房；
4. 怪物房；
5. 宝箱房；
6. 事件房；
7. 撤离格；
8. 目标相关房间；
9. 后续特殊房间。

基础身份生成后应写入 TruthMap。

---

## 5.2 房间内容可上下文解析

房间基础类型确定，不代表房间内全部内容必须立即完整实例化。

建议：

1. 房间基础类型在开始探索时确定；
2. 房间内容种子在开始探索时确定；
3. 房间具体遭遇可在进入时根据当前 RunState、事件、目标、modifier 解析；
4. 解析结果必须可复现；
5. 解析后写入 RunMapState 或 EncounterLog。

例如：

```text
某格基础类型 = 怪物房
进入时根据地图难度、当前压力、目标、高难委托、事件 modifier 解析具体怪物遭遇。
```

或：

```text
某格基础类型 = 事件房
进入时根据事件池、目标状态、当前地图压力解析具体事件。
```

---

## 5.3 房间与 Encounter

房间是入口，Encounter 是内容。

一个基础房间可以调用不同 Encounter：

1. 战斗遭遇；
2. 宝箱遭遇；
3. 雷房危险遭遇；
4. 事件选择遭遇；
5. NPC 交易遭遇；
6. 撤离遭遇；
7. Boss 遭遇；
8. 特殊规则遭遇。

地图本体只负责房间身份与状态。
具体战斗、事件、宝箱、交易、撤离流程由对应 Encounter 处理。

---

## 5.4 “下一房间指定类型”规则

某些规则可能产生“下一个房间一定为某种房间”的效果。

建议分三种处理方式：

### 生成期预留

在地图生成时预留目标房、剧情房、撤离房或教学房。

适合：

1. 教学地图；
2. 目标房；
3. 剧情房；
4. 评委模式；
5. 固定流程展示。

### 运行期修改未揭示房间

事件发生后，将某个未揭示房间改为指定类型。

限制：

1. 只能修改未揭示房间；
2. 不能修改已探索房间；
3. 不能暗改已知数字；
4. 必须写入 MutationLog；
5. 必须重新校验局部合法性。

### Encounter 覆盖

不改变房间基础身份，只覆盖下一次进入或下一次搜索时的 Encounter。

适合：

1. 下一次进入必定伏击；
2. 下一次搜索必定事件；
3. 下一次宝箱触发特殊奖励；
4. 下一次回访触发特殊提示。

当前版本优先使用生成期预留和 Encounter 覆盖。
运行期修改房间基础身份作为后续接口保留。

# 6. 地图事件变更

## 6.1 地图可以被事件改变

地图本身可以因为一次性事件或持续性事件发生变化。

变化可以包括：

1. 解锁房间；
2. 封锁房间；
3. 改变未揭示房间内容；
4. 改变信息可信度；
5. 增加污染区；
6. 清除污染区；
7. 增加撤离线索；
8. 改变奖励表；
9. 改变 Encounter 权重；
10. 改变怪物房倾向；
11. 改变宝箱房倾向；
12. 改变事件房倾向。

---

## 6.2 一次性事件变更

一次性事件只发生一次，立即改变某个地图状态。

例如：

1. 某房间解除封锁；
2. 某片区域被污染；
3. 某个未揭示房间变为事件房；
4. 某个撤离信号被接入；
5. 某个目标房被标记；
6. 某个危险提示被清除。

一次性事件必须写入 MapMutationLog。

---

## 6.3 持续性事件变更

持续性事件在一定范围或一定时间内影响未来结果。

例如：

1. 接下来若干未揭示房间怪物倾向提高；
2. 某区域扫描结果不可信；
3. 宝箱奖励倾向提高；
4. 撤离线索出现率提高；
5. 事件房权重提高；
6. 回传暂时受限；
7. 某些数字提示受污染。

持续性事件应记录：

1. 来源；
2. 作用范围；
3. 持续时间；
4. 是否可见；
5. 是否影响已知信息；
6. 是否影响未来随机性；
7. 是否影响 Encounter；
8. 是否影响奖励。

---

## 6.4 MapMutationLog

所有运行期地图变化必须记录。

MutationLog 应记录：

1. mutation_id；
2. source_type；
3. source_id；
4. target_type；
5. target_cell；
6. before_state；
7. after_state；
8. affected_layers；
9. visible_to_player；
10. affects_known_info；
11. timestamp / step_index；
12. reason；
13. rollback_for_debug。

用途：

1. 存档恢复；
2. 战绩记录；
3. 调试复现；
4. 测试人员检查；
5. 玩家侧提示；
6. 后续复盘。

---

## 6.5 已知信息不可被暗改

普通规则下，已揭示信息默认可信。

不得暗改：

1. 已揭示数字；
2. 已确认房型；
3. 已确认雷险；
4. 已发现撤离格；
5. 已清理状态；
6. 已开启宝箱状态；
7. 已完成事件状态。

若特殊规则必须改变，必须：

1. 通过地图规则提前说明；
2. 通过污染层或异常层显示；
3. 提示玩家信息可信度变化；
4. 写入 MutationLog。

---

# 7. 信息可信度与污染区

## 7.1 污染区定义

污染区是地图信息可信度发生变化的区域。

污染区不等于雷区。
污染区不等于怪物区。
污染区是信息层规则。

污染区可以影响：

1. 数字提示可信度；
2. 扫描结果；
3. 房间类型提示；
4. 标记可靠性；
5. 探测类消耗品效果；
6. 撤离方向提示；
7. 目标线索提示。

---

## 7.2 污染区显示

污染区必须有地图层表现。

可以使用：

1. 覆盖层；
2. 遮罩；
3. 边框；
4. 图标；
5. 透明色块；
6. 闪烁提示；
7. 特殊纹理。

具体颜色、透明度和动效后续确定。

重要原则：

```text
污染不能暗中发生。
玩家必须知道某一区域信息不完全可信。
```

---

## 7.3 信息可信度状态

建议状态：

1. 可信；
2. 不稳定；
3. 受污染；
4. 可能失真；
5. 已校准；
6. 已清除污染。

---

## 7.4 污染区与普通地图

普通地图中，已揭示雷数默认可信。

污染区和信息失真属于：

1. 特殊规则地图；
2. 事件结果；
3. 高难委托；
4. 特殊房间；
5. 特殊消耗品副作用；
6. 后续异常系统。

普通地图不应默认存在暗中信息失真。

# 8. 小地图与展开地图

## 8.1 小地图定位

小地图是核心玩法系统，不是辅助 UI。

小地图负责：

1. 显示当前位置；
2. 显示未知 / 已扫描 / 已探索 / 已清理；

5. 显示玩家标记；
6. 显示撤离格；
7. 显示目标相关提示；

10. 支持进入展开地图。

---

## 8.2 小地图信息密度

小地图不应承载全部详细信息。

小地图优先显示：

1. 当前位置；
2. 未知 / 已知；
3. 数字；
4. 标记；
5. 撤离；
6. 目标；

展开地图负责：

1. 查看更大范围；
2. 查看房间摘要；
3. 查看房间状态；
4. 查看已搜索 / 未搜索；
5. 查看已清理 / 未清理；
6. 查看污染区；
7. 查看目标关联；
8. 查看撤离状态；
9. 查看商人 / 回收终端；
10. 进行标记；
11. 执行回传；
12. 打开格子详情。

---

## 8.4 点击格子后的信息展示

不同状态格子显示不同信息。

### 未知格

显示：

1. 未知区域；
2. 是否有玩家标记；
3. 相邻已知信息；
4. 是否可扫描；
5. 不显示真实房型。

允许操作：

1. 标记；
2. 取消标记；
3. 使用允许的扫描类效果。

不允许：

1. 回传；
2. 查看真实内容；
3. 触发事件；
4. 获得奖励。

### 已扫描格

显示：

1. 扫描得到的信息；
2. 扫描来源；
3. 信息可信度；
4. 是否被污染；
5. 是否可探索。

允许操作：

1. 标记；
2. 取消标记；
3. 查看扫描详情。

不允许：

1. 回传；
2. 触发事件；
3. 直接视为已探索。

### 已探索格

显示：

1. 房间类型；
2. 雷数；
3. 房间状态；
4. 是否可回传；
5. 是否已搜索；
6. 是否已清理；
7. 是否有未处理内容；
8. 是否关联目标；
9. 是否受污染。

允许操作：

1. 回传；
2. 标记；
3. 查看详情；
4. 查看关联目标；
5. 查看房间状态。

### 已清理格

显示：

1. 房间类型；
2. 雷数；
3. 清理状态；
4. 已处理内容；
5. 是否可回传；
6. 是否仍有功能；
7. 是否可作为商人 / 回收终端再次访问。

允许操作：

1. 回传；
2. 查看详情；
3. 重复访问可重复功能房。

# 9. 回传 / 快速回访

## 9.1 定义

回传 / 快速回访是展开地图中的便利操作。

它允许玩家快速返回已探索过的房间，减少重复跑图疲劳。

## 9.2 基础规则

1. 只能回传到已探索或已清理房间；
2. 未知格不能回传；
3. 已扫描但未探索格不能回传；
4. 回传不揭示新房间；
5. 回传不触发新事件；
6. 回传不增加协议压力；
7. 回传不默认执行全局路径寻路校验；
8. 回传检查目标房间是否允许回传；
9. 回传检查当前玩家状态是否允许回传。

## 9.3 禁止回传状态

以下状态禁止回传：

1. 战斗进行中；
2. 怪物攻击判定中；
3. 陷阱演出中；
4. 事件选择中；
5. 撤离确认中；
6. 结算中；
7. 当前地图规则禁用回传；
8. 目标房间被封锁；
9. 高难委托限制回传；
10. 特殊事件临时禁用回传。

## 9.4 可被规则改写

回传规则可被以下内容影响：

1. 特殊地图；
2. 高难委托；
3. 持续事件；
4. 污染区；
5. 特殊房间；
6. 特殊消耗品；
7. 后续移动能力。

当前基础版本不加入复杂成本。

---

# 10. 房间刷新与重复进入

## 10.1 默认规则

默认规则：

1. 普通房可重复进入；
2. 雷房触发后不重复扣血；
3. 宝箱房开启后耗尽；
4. 事件房处理后进入已触发或已完成状态；
5. 怪物房清理后不刷新怪物；
6. 商人 / 回收终端可重复访问；
7. 撤离格可重复进入，使用后结束本局。

---

## 10.2 刷新策略字段

房间应支持 refresh_policy。

可选策略：

1. none：不刷新；
2. once：一次性；
3. repeatable：可重复；
4. conditional：条件刷新；
5. event_driven：事件驱动刷新。

默认：

1. 普通房：none 或 repeatable，无额外收益；
2. 宝箱房：once；
3. 雷房：once；
4. 怪物房：once；
5. 事件房：once 或 conditional；
6. 商人 / 回收终端：repeatable；
7. 撤离格：repeatable，使用后结束本局。

## 10.3 规则改写

房间刷新规则允许被以下内容改写：

1. 特殊地图；
2. 事件；
3. 高难委托；
4. 研究解锁；
5. 特殊消耗品；
6. 后续规则房。

被改写时必须有明确提示或地图规则说明。

---

# 11. 协议 / 封锁压力与地图关系

协议 / 封锁压力是地图级全局状态。

它记录本局区域的危险推进状态。

可能受以下行为影响：

1. 首次探索未知房；
2. 触发事件；
3. 清理怪物；
4. 搜索房间；
5. 开启宝箱；
6. 接入撤离信标；
7. 完成目标；
8. 放弃探索；
9. 高难委托 modifier；
10. 特殊地图规则。

协议 / 封锁压力可能影响：

1. 撤离提示；
2. 怪物房倾向；
3. 事件风险；
4. 回收收益；
5. 结算记录；
6. 地图视觉状态；
7. 污染区；
8. 后续 Encounter 解析。

压力具体数值不在本案讨论。

---

# 12. 地图与背包 / 收益 / 结算接口

地图本体不直接把物品写入仓库。

流程应为：

```text
房间产生收益
↓
局内背包或临时收益记录
↓
撤离 / 失败 / 放弃
↓
结算报告
↓
仓库 / 通用资产 / 历史战绩 / 图鉴
```

地图应提供给结算的数据包括：

1. 已探索房间数；
2. 已扫描房间数；
3. 已清理房间数；
4. 触发事件；
5. 打开宝箱；
6. 击败怪物；
7. 触发雷房；
8. 发现撤离格；
9. 是否成功撤离；
10. 是否失败；
11. 是否放弃；
12. 获得物；
13. 丢失物；
14. 消耗品使用；
15. 目标完成情况；
16. 地图污染记录；
17. 地图 mutation log。

# 13. 地图与目标 / 高难委托接口

## 13.1 目标对地图的影响

目标可以影响地图生成或 Encounter 解析。

目标可能提供：

1. 目标房需求；
2. 目标物需求；
3. 目标事件需求；
4. 目标怪物需求；
5. 地图区域需求；
6. 撤离条件需求；
7. 目标提示需求。

地图生成器应读取目标需求，生成或预留必要内容。

## 13.2 高难委托对地图的影响

高难委托可以提供 map_modifier。

例如：

1. 提高危险房倾向；
2. 提高怪物房倾向；
3. 降低信息可信度；
4. 增加污染区；
5. 限制回传；
6. 增加撤离压力；
7. 限制扫描效果；
8. 改变奖励倾向。

高难委托 modifier 必须参与地图合法性校验。

如果某个高难委托组合会导致地图无法合法生成，应在出发探索阶段判定不可选或给出警告。

# 14. 地图存档与版本管理

## 14.1 只保存 seed 不够

正式 active run 不能只保存 seed。

因为地图生成规则、内容池、约束和事件逻辑会在开发中变化。
同一个 seed 在不同版本中可能生成不同地图。

必须保存最终地图快照。

---

## 14.2 active run 应保存内容

需要保存：

1. seed；
2. map_gen_profile_id；
3. map_gen_version；
4. rule_set_version；
5. content_pool_version；
6. constraint_version；
7. final_truth_map_snapshot；
8. KnownMap；
9. ScanLayer；
10. MarkMap；
11. RunMapState；
12. InfoReliabilityLayer；
13. 当前房间；
14. 已触发事件；
15. 已清理怪物；
16. 已开启宝箱；
17. 已发现撤离格；
18. 协议 / 压力状态；
19. 已应用 modifier；
20. MapMutationLog；
21. 本局目标状态；
22. 已获得但未结算收益。

---

## 14.3 老局恢复

老的 active run 恢复时应使用保存的地图快照，而不是用新版本生成器重新生成。

新版本生成器只影响新局。

# 17. 玩家侧解释层

1. 当前地图类型；

4. 当前信息是否可信；

9. 为什么某些信息被标记为受干扰；

# 21. 最低验收标准

本案完成后的地图系统最低验收标准：

1. 普通模式可随机生成合法矩形地图；
2. 普通模式不保证安全路径；
3. 普通模式不保证出生点和撤离点周围安全；
4. 评委模式可手排地图；
5. 每个格子只有一个基础房型；
6. 雷数只统计雷房；
7. 怪物房、宝箱房、事件房、撤离格、出生点、普通房不计入雷数；
8. 地图格状态支持未知、已扫描、已探索、已清理；
9. 扫描不等于探索；
10. 已扫描格不能传送；
11. 已探索格可以回传；
12. 回传不触发事件、不增加压力；
13. 小地图能显示当前位置、已探索、已扫描、雷数、标记和房型；
14. 展开地图能查看状态并进行回传；
15. 地图生成有 seed 和生成日志；
16. 地图 active run 保存最终快照；
17. 事件与规则变化可通过 modifier 或 mutation 记录；
18. 污染 / 不可信信息有接口；
19. 测试人员可以查看并修改地图状态；
20. 地图系统可支持后续蜂窝、多层、特殊规则扩展。

# 23. 总结

本案将局内地图系统定义为：

> seed 驱动、规则约束、状态分层、可被事件修正、可调试、可复现、可扩展的局内地图本体。

核心原则：

1. 当前普通模式随机生成；
2. 当前普通模式不追求无猜；
3. 当前普通模式不保证安全路径；
4. 房型互斥；
5. 雷数只统计雷房；
6. 已扫描不等于已探索；
7. 已探索房间可回传；
8. 回传不触发事件、不增加协议压力；
9. 地图生成支持 seed + profile + constraints + modifiers；
10. 已知信息默认可信；
11. 污染和失真必须明确显示；
12. 事件可以改变地图，但必须记录；
13. active run 必须保存地图快照；
14. 测试人员必须能查看、修改、复现和导出地图；
15. 地图 UI 操作方案可根据实机反馈调整；
16. 后续蜂窝、多层、特殊规则地图应通过拓扑与规则接口扩展，而不是推翻当前系统。
