## 7. Functional chain review

Equipment/consumables:

- Equipment purchase writes to `ownedItems`.
- Only `equippedItems` are read by `MetaProgress.GetEquipBonus()`.
- Consumable purchase writes to `consumables`.
- Loadout is stored in `data.loadout.consumables`.
- `ConfirmDeploy()` validates loadout, and `StartNewGame()` consumes it only when loadout is enabled.
- `RunInventory.SetConsumables()` receives the run consumables.
- `Q` calls `UseEmergencyBandage()`, which calls `RunInventory.UseConsumable("emergency_bandage")`, heals HP, and decrements count.

Recovered items / warehouse:

- Search/chest rewards add carried items through `RunInventory.AddCarriedItem()`.
- Successful extraction builds `RunInventory.GetExtractionReward()` and calls `MetaProgress.RecordExtractionReward()` only when warehouse rewards are enabled.
- `RecordExtractionReward()` adds carried items to recovery history and warehouse.
- Failure handling uses salvage logic; normal failure does not wholesale write carried items into warehouse.
- Tutorial disables both warehouse rewards and failure rewards.

Events / monsters / search:

- Monster rooms remain combat-only and not searchable.
- Event rooms open event flow and are not regular searchable rooms.
- Normal search can produce items.
- Chest rewards use the chest drop/gold path and self-test confirms chest reward beats normal search.
- Warehouse selling remains available through `MetaProgress.SellWarehouseItem()`.

Status: PASS

Most likely risk point: failure salvage can intentionally keep one carried item through formal failure handling; this is expected by current tests, but should not be confused with full warehouse extraction.

Systems not recommended to move now: warehouse, requisition, loadout, recovery, event panels, and combat/search reward logic.
