# ART24R2 初次 Computer Use 审计

- 采用标准：`ART24R2-INITIAL-CU-DIAG-FROZEN-1`
- 审计入口：Godot 4.6.3 生产 `project.godot` / `main.tscn`
- 审计路径：主菜单 → 出发探索 → 确认出发 → 普通房移动/跨门 → 搜索 → 世界掉落 → 地面回收 → 拾取 → 背包 → 大地图
- 禁止替代项：未使用 ART24 runner 或 Debug 状态注入。

## 结论

当前 ART24R1 的真实闭环可操作，但视觉、状态覆盖和战斗呈现不能作为 ART24 返工完成结果。总体结论：`FAIL / REWORK_REQUIRED`。

## A. 生产入口与主构图：FAIL

- `PASS`：生产主菜单和出发页可见按钮能够进入真实局内。
- `PASS`：基本形成左栏、中央房间、右上协议、底部按键条的固定结构，中央房间仍占最大面积。
- `FAIL`：角色相对中央房间的尺度明显大于 UE 原型；脚底阴影和角色外形在低分辨率下占据过多注意力。
- `FAIL`：左栏出现“区域扫描图”装饰字与内容字的重复叠层；低分辨率下状态、作业包和提示行过密。
- `FAIL`：右上协议区高度不足，压力、风险、房间与事件文字相互逼近；底栏文字在窗口模式下过小。
- `FAIL`：相邻普通房间仍使用近乎相同的中央场景观感，房型差异和危险氛围不足。

## B. 移动、动画与战斗房性能：FAIL

- `PASS`：Computer Use 单次 `D` 和 `S` 均产生可见位移与正确朝向。
- `PASS`：连续移动能从右侧门进入相邻房间，并从对应左侧入口出现；地图位置和压力同步变化。
- `FAIL`：当前可见步行动画的位移跨度与帧变化关系偏硬，idle、移动与脚底阴影的节奏仍像分离图层。
- `FAIL`：战斗显示层直接消费 60 Hz 离散状态，没有位置插值；模拟和显示每个渲染帧重复深拷贝战斗快照，角色视图重复写入静态属性。
- `MISSING`：旧最终审计没有进入真实战斗房，也没有记录战斗帧时间、追帧或输入迟滞；用户实际游玩已复现战斗房严重卡顿。本阶段必须补测。
- `FAIL`：G41 敌人当前仍以程序几何占位呈现，与正式玩家角色和房间美术不属于同一完成度。

## C. 掉落、拾取与背包：FAIL

- `PASS`：真实搜索显示暗场居中结果面板，具备结果摘要、物品行、数量和估值。
- `FAIL`：“断线螺丝”等回收物使用药瓶图标，说明当前 fallback 覆盖了错误语义而非仅承担缺图降级。
- `PASS`：关闭结果后，真实世界掉落实体、名称/估值及 `G` 提示可见。
- `FAIL`：世界掉落光束/稀有度反馈过弱，名称与场景缺少清晰的深度和焦点关系。
- `FAIL`：`G` 打开的固定大型“地面回收物”面板本身就是错误层级。目标应为靠近地面实体后出现、离开后消失的上下文悬浮窗；当前一件物品仍占据整块主画面并保留大量无意义空白。
- `PASS`：Computer Use 点击“拾取”后，地面计数从 1 变 0、背包从 0 变 1，世界实体消失，背包出现同一真实实例。
- `FAIL`：低分辨率背包标题、摘要、物品行及“使用/丢弃”按钮过度压缩；面板与右上协议区发生明显竞争。

## D. 地图与其他模态：FAIL

- `PASS`：大地图能打开和关闭，10×10 扫描格居中，模态期间背景压暗。
- `FAIL`：标题、说明、格子和外围留白在低分辨率下比例失衡，扫描信息辨识度仍依赖细线和小字。
- `FAIL`：背包和地面回收虽保留左栏，但没有稳定保留右上协议的可读面积；不同窗口尺寸的布局行为不一致。
- `MISSING`：本次未获得事件、撤离和三种结算的完整生产玩家路径证据，不能沿用旧 runner 截图判定。

## E. G41/M6 新状态准备度：MISSING

- 当前美术分支基线为 G41 `7fc32fe`，尚未包含 M6 `2fd9d4d`。
- 真实装备/消耗品区分、2 件装备/3 件补给限制、应急申领、活动局继续/放弃尚未进入本分支。
- 失败保全候选、重量选择、超重禁用和确认结算只有程序侧新实现，尚无合格 ART24 表现。

## 执行问题清单

1. 先合并 M6 并保留 ART24 样式契约，禁止在旧字段上继续补假状态。
2. 先修复战斗插值、快照复制和视图脏更新，再增加战斗动效，避免用更多动画掩盖性能问题。
3. 按 UE 空间权重收小角色相对尺度、清理左栏重复层、扩充右上信息高度并提高底栏识别度。
4. 建立 M6 全内容图标映射；fallback 只用于未知项，不得让已知回收物显示错误类别图标。
5. 移除固定地面回收大面板，改为感应范围驱动的场景悬浮窗；1 件、多件、满包和替换四种状态均不得遮蔽主房间。
6. 最终验收必须补齐真实战斗房、事件、撤离、成功/失败/放弃和失败保全路径。
7. 当前箱子 `opened` 后被永久禁用，无法重复打开/关闭查看剩余内容；需改为首次开箱仅结算一次、容器界面可重复开合的同一上下文交互。
