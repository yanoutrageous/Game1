# ART24R1 最终 Computer Use 验收标准

- 标准 ID：`ART24R1-FINAL-CU-FROZEN-1`
- 冻结时点：最终完成验收启动前，且早于最终验收结论。
- 视觉基准：`D:\AGAME1\external\ue_prototype\UE\Graytail\Graytail.uproject` 的实际 UE 运行画面。
- 事实基准：当前 Godot 生产代码中的 `RunContext`、`CommandBus`、快照、物品与房间状态。
- 明确排除：旧 Godot 局内界面和 `art24_in_run_art_preview_runner.gd` 只可用于操作/资产参考，不可作为任何视觉通过依据。
- 判定规则：下列阻断项全部通过才记 `PASS`；任一阻断项失败即返工，不允许以静态代码、测试 runner 或调试注入代替 Computer Use 玩家路径。

## A. 真实入口与主构图

1. 通过生产主菜单可见按钮进入“出发探索”，再通过“确认出发”进入真实局内；窗口不是 ART24 runner。
2. 局内稳定形成 UE 原型同类空间关系：左侧固定扫描/生命资源/当前作业/背包摘要；中央房间是绝对主视觉；右上只保留协议、压力和房间事件；底部是横向按键条。
3. 中央房间不因 HUD 拉伸变形；角色脚底与地面关系成立；右上状态和底栏不遮挡主要移动区域。
4. 文字只验收可读性、层级、行距、截断和对比度，不要求逐字复制 UE 文案；不允许出现文字压框、相互覆盖或不可辨按键。

## B. 移动、方向与房间切换

1. Computer Use 输入 `W/A/S/D` 至少验证一个水平方向和一个垂直方向；单次输入必须产生可见位移，角色不得固定在房间中心。
2. 移动时角色朝向与方向一致，使用不少于四段的移动循环组合；静止时恢复 idle 呼吸/帧变化，角色不滑行。
3. 连续移动到合法门边后必须切换到相邻房间，并从对应入口出现；地图当前位置、压力或房间状态至少有一项同步更新。
4. 无合法房间时必须停在边界并产生既有阻挡反馈，不允许穿出房间。

## C. 搜索、结果与世界掉落

1. 不使用 Debug，进入可搜索房间并按 `E`；成功搜索必须显示 UE 式暗场居中金属结果面板。
2. 结果面板同屏具备：标题、来源/结果说明、收益摘要、回收物数量、总估值、物品图标、名称、数量、类别/稀有度、描述、单项估值和确认提示。
3. 关闭结果面板后，未进入背包的真实地面物必须在房间中显示实体、光柱/标识、名称与估值，并出现 `G` 地面回收提示。
4. 世界掉落必须来自 `room_floor_items` 快照；不得由美术层伪造固定物品。

## D. 地面回收与背包闭环

1. `G` 打开宽幅地面回收面板；左栏和右上状态仍可辨；物品行的图标、名称、类别、稀有度、重量/估值及“拾取/替换”操作不得挤压或重叠。
2. 用 Computer Use 点击真实“拾取”后，地面数量减少、背包数量增加、命令结果更新；关闭面板后被拾取的世界实体与提示消失。
3. `Q` 打开背包后可看到同一真实物品；“使用/丢弃”的可用与禁用状态清楚；滚动区存在且不会把操作按钮挤出面板。
4. `Esc` 可关闭背包/地面回收并恢复局内输入。

## E. 大地图与连续界面

1. `M` 打开大幅全屏扫描层：背景明显压暗，10×10 地图保持居中，未知、已探索、玩家、选中等状态具有清晰差异。
2. 地图标题、选中详情、关闭/标记说明均位于各自区域，无旧 Godot 装饰框压字；`Esc` 可关闭。
3. 地图、背包、地面回收、回收结果互斥；打开模态时角色不得继续移动，关闭后重新可操作。
4. 搜索、拾取、背包和地图流程全程使用生产输入与生产状态，不依赖预览 runner 或 Debug 面板。

## F. 技术与污染守卫

1. Godot headless project-load/parser smoke 无 `SCRIPT ERROR`、`Parse Error`、`Compile Error`。
2. 相关物品掉落/拾取验证脚本与 ART24R1 结构验证通过。
3. 运行日志无新增脚本错误；生产脚本无 `D:\UE`、外部克隆或本地绝对素材路径。
4. 最终提交不得包含 Godot 自动生成的 `.translation`、`.import`、`.uid` 或 `.godot` 污染。

## 最终结论格式

最终报告必须逐项记录 `PASS/FAIL`、实际玩家路径、UE 对照结论、两轮优化事实、自动验证结果、提交与远端状态。只有总体 `PASS` 后才允许 commit/push。
