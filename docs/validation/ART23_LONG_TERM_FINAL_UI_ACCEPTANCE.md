本标准启用后不得根据验收结果降低门槛。任一页面、交互或动效失败，都必须停止当轮、返工，并按本文件从真实主菜单重新执行全量验收。只有所有项目均为 PASS，ART23 才能完成、提交与 push。

## 1. 固定结构

1. 左上“主菜单 / 出发探索”上下排列并由竖直锁链连接；不得出现斜链。
2. 顶部六个模块按钮共用轨道和同一木铜风格；研究、抽奖保持诚实锁定外观，但仍可进入只读说明页。
3. 中央根据模块显示对应打开的家具：目标桌、图鉴柜、研究柜、角色档案柜、抽奖柜、收藏展示柜；家具属于房间，而非独立海报。
4. 二级页签、羊皮纸详情和三槽深色卡片属于同一中央模块层，切换和收起时整体运动。
5. 极左下是小型机械拉杆，标签位于底座内；收起后中央层完全移出，露出完整档案室。
6. 最右侧始终固定为角色档案，显示同一游戏角色、等级、经验、探索/撤离/失败/长期金币和“设置外观”。

## 3. 每页共同合格条件

每切换到一个二级页，必须同时满足：

- 当前一级模块是青绿选中态，其余恢复木铜常态；研究/抽奖未开放状态仍明确可见。
- 当前二级页完整可见并处于选中态；图鉴末端可自动滚入，不能出现 Godot 原生灰色滚动轨道。
- 模块家具与当前一级模块匹配，未错误复用上一模块家具；家具边缘不越过右侧档案。
- 羊皮纸标题、只读/封存元信息、说明和三个深色卡槽均在边框内，无裁切、重叠或漂浮到复杂背景。
- 三张卡片状态与页面语义一致；真实数据存在时显示真实投影，不存在时使用“未发现/封存/未登记”，不得伪造后端成功。
- 右侧角色档案节点、角色身份、等级和统计在切页时保持固定，不跳位、不重建成另一套风格。
- 左上导航、顶部模块、左下拉杆、中央板块和右侧档案不互相遮挡。
- 与 ART22 出发探索共用同一套黑铁、深木、旧羊皮纸、暖金和青绿高亮语法；长期系统可使用档案室家具隐喻，但不得变成另一套明亮卡片、现代面板或写实角色风格。
- 页面标题、说明、元信息和右侧等级/统计必须使用清晰的正文中文字体；像素字体只用于短按钮、一级/二级页签和短卡片标签。不得出现缺字、挤压、锯齿发虚、文字独立悬浮或过量描边。

任一页不满足即为全量矩阵失败，禁止抽样替代 27 页逐项验收。

## 4. 交互与路由

- 必须从实际 `main.tscn` 的主菜单“长期系统”进入本页，宿主状态为 `long_term_shell`。
- 左上“主菜单”和“出发探索”沿用 AppShell 导航意图；不得直接篡改游戏状态。
- “设置外观”进入 `collection_appearance / appearance_config`，不伪造换装保存。
- 拉杆可用鼠标与键盘操作；收起后背景完整、顶部模块与右侧档案仍在，展开后精确恢复收起前的一级模块与二级页（包括从“设置外观”进入的外观配置页）。
- 快速连续切换一级模块时采用 latest-request-wins，最终家具和选中模块一致。
- 方向键焦点依次覆盖一级、二级和卡片；Esc 顺序回退卡片→二级→一级→主菜单，收起态 Esc 先展开。
- 研究/抽奖页面可读但不扣除资源、不生成结果、不写入进度。

## 5. 动效标准

- 一级切换约为关闭 0.24 s、空拍 0.10 s、打开 0.34 s；家具、页签、羊皮纸和卡片作为整体，缩放中心位于中央模块区。
- 二级切换约 0.16 s，羊皮纸底图、标题、说明、元信息和卡片同步淡入，不允许文字先漂浮、底板后出现。
- 收起/展开约 0.30 s；拉杆聚焦有青绿色/暖金反馈，不改变命中区。
- 角色加载 8 张资源级帧，0–5 形成约 0.34 s 的慢速呼吸/眨眼节奏，6–7 只参与约 5 s 后首次出现、随后约 10 s 间隔的观察动作；不得退化为机械两帧跳变。
- 环境至少有暖灯、蓝灯两组低透明呼吸和档案尘、蓝色微粒两组低密度粒子，粒子不得穿过右侧档案或遮挡文字。
- 连续观察至少 20 秒，必须能看到角色常态、观察动作和回归常态；阅读区不得因动效产生独立漂移。
- 减少动态效果时，角色与环境动态冻结，切换/收起立即完成，信息结构保持不变。

## 6. 分辨率、资产和回归

- 1280×720、1366×768、1600×900、1920×1080、2560×1440 五档均完成 27 页捕获，共 135 个唯一状态记录。
- 58 个运行资产必须由 manifest 解析；运行时哈希、源哈希、尺寸、加载组、默认挂载和解码预算完整。
- 默认保守解码不超过 8 MiB，总保守解码不超过 18 MiB。
- ART23 runner 必须报告 `primary_modules=6 secondary_pages=27 character_frames=8 states=OPEN,CLOSED,OPENING,CLOSING,SWITCHING`。
- 真实主线路由 runner、ART22 出发探索、ART21 主菜单、导航/层级和 I0 允许范围内回归不得失败。
- 不提交 Godot 生成 sidecar，不改变用户原 ART22 工作树。

## 7. Computer Use 最终验收顺序

1. 打开实际 Godot 项目，从主菜单点击“长期系统”，确认真实路由和默认目标/任务页。
2. 按第 2 节顺序逐一点击 6 个一级模块和全部 27 个二级页；每页按第 3 节记录 PASS / FAIL。
3. 在图鉴从地图连续到世界观，确认末端自动滚入且无原生灰色滚动条。
4. 点击右侧“设置外观”，确认进入收藏外观/外观配置；再返回其他模块确认右侧档案节点始终固定。
5. 操作收起与展开，检查完整背景、拉杆反馈和精确复位。
6. 快速切换至少三次一级模块，确认最后请求与家具/内容一致。
7. 用键盘检查一级、二级、卡片和 Esc 层级。
8. 连续观察至少 20 秒，确认八帧角色节奏、间歇观察、环境光和粒子，不出现文字独立漂浮。
9. 对照 ART22 出发探索确认材质、按钮状态、羊皮纸和角色来源连续；复查正文/数据字体与短标签像素字体分工。
10. 对照五档联系表、五张原尺寸代表图和 135 行哈希记录确认缩放。

最终记录必须列出 27 页，不能只写“全部抽查通过”。
