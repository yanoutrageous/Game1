# ART24R2：UE—Godot 代码与实机双证据差距审计

状态：已封存；最终 Computer Use 结论为 `FAIL / STAGE_ARCHIVED_BY_USER_DIRECTION`，详见 `ART24R2_FINAL_COMPUTER_USE_RESULTS.md`。

基准：`ART24R2-UE-LAYOUT-CU-FROZEN-1`。任何后续修改同时满足“代码契约正确”和“实机观感合格”才可收敛。

## 审计方法

1. 代码证据：读取 UE 的布局常量、缩放容器、输入状态和生产数据接口，再核对 Godot 的对应实现。
2. 实机证据：使用 Computer Use 在同一设备上观察 UE 与最新 Godot 生产场景；不以旧 Godot 或 ART24 preview 作为视觉标准。
3. 决策规则：实机指出问题，代码定位根因；参数相近但观感不符时不得判定通过；画面相似但依赖假数据或错误接口时同样不得判定通过。

## 当前结论

- 本轮按用户 2026-07-19 的明确指令停止继续扩大验收与返工，以未通过状态封存并 push；这不改变冻结标准，也不构成 ART24R2 完成。

- 用户截图中的“角色过小”不是单一素材问题，根因是房间 Cover 裁切、角色缩放和 HUD 尺寸约束共同造成；三项必须一起修正。
- 当前最新实机中，房间与角色比例已经进入 UE 合理区间，不应继续无依据放大角色。
- 背包四行在低分辨率下过重的问题已按 UE 四行模型收紧；空态已通过实机复验，真实物品与满载状态仍不得由空态代替。
- 展开地图此前“尺寸接近但状态表达不符”的根因已确认：Godot 额外加入常驻详情条并让通用选中态覆盖语义标记。现已按 UE 代码和实机共同证据移除详情条、恢复底部反馈，并完成标记/取消可逆验证。
- 世界交互悬浮窗证明单一代码探针不足：旧探针只检查了手写锚点，未覆盖生产房间的 ScaleToFit 变换，曾出现“测试通过、实机覆盖实体”。当前已把生产节点坐标转换纳入探针，并由实机重新验证宝箱与地面物焦点切换。
- 展开地图和结算不能只验一个截图；必须按冻结矩阵逐一覆盖选择、标记、回传、成功、失败保全、超重阻塞、失败最终和放弃。
- ART24 preview 只保留为资产/状态目录诊断，不得替代生产节点的 Computer Use 最终验收。
