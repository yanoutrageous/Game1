1. 主菜单、区域、难度到局内可由玩家可见入口连续进入。
2. 局内固定空间关系是：左侧约 24% 扫描/状态/资源/作业包；中央单房间绝对主视觉；右上仅协议与压力窄条；底部横向键位条。
3. `M` 打开大幅区域扫描图，背景整体压暗，仍能辨认左栏、协议与房间。
4. 宝箱房搜索后显示居中金属结果框：遮罩压暗、标题/来源、结算币、回收物数量、估值、56px 级图标、名称、类别/稀有度、描述、单项价值与确认提示完整同屏。
5. UE 运行时冒烟为 `268/269`，唯一失败是 `GameDataMissingMoveSpeedPath`；该缺陷属于参考原型自身，不转嫁为 Godot 的完成项。

## Godot 当前生产流事实

1. 首次检出后未导入资源时出现纯灰窗口；完成 Godot 资源导入并重启后，主菜单可用。
2. 主菜单 -> 出发探索 -> 确认出发 -> 局内可连续进入，入口本身 `PASS`。
3. 局内虽有左栏/中央房间/右上协议/底栏，但主要问题如下：
   - 左栏文字尺寸、分组和密度远低于 UE；扫描图与状态信息没有形成清晰主次。
   - 中央房间被 UI 叠压，协议条和底栏的材质、比例、留白与 UE 差距明显。
   - 角色输入代码使用固定 `Rect2(420,220,440,360)`，只覆盖房间中央一小块，造成“固定在中心附近”的实际感受；短按也没有可见位移反馈。
   - 角色仍由旧单帧资产路径呈现，ART24 多方向 idle/walk/action 帧未接入生产控制器。
   - `G` 地面回收和 `Q` 背包面板出现明显文字挤压、行高不足、操作按钮不可辨；不具备 UE 掉落卡的字段层级。
   - 搜索结果仍是旧 `430x300` 文本框，没有 UE 的遮罩、640px 金属框、物品卡、估值/类别/稀有度/描述和确认脚注层级。
   - 地面物品没有在房间中形成可辨认的实体、光束或靠近提示，拾取前后缺少世界侧反馈。
   - 大地图虽能打开，但只是既有 Godot 框体，不作为合格基准；后续需按 UE 的大图层级和暗场关系重排。
