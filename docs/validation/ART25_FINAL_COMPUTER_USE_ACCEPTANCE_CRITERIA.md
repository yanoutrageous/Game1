# ART25 最终 Computer Use 验收标准

- 标准 ID：`ART25-FINAL-CU-FROZEN-1`
- 冻结时点：实现开始前
- 事实入口：当前分支生产 `project.godot` / `main.tscn`
- 禁止替代：旧截图、概念图、preview runner、仅代码存在或仅自动化通过均不能替代最终视觉验收。

## 1. 验收方法

1. 最终审计必须由 Computer Use 操作独立 Godot 游戏窗口。
2. 从主菜单进入真实出发页、长期页和真实局内。
3. QA 路由只允许播种真实快照或稳定进入真实场景；被检查的控件、动画和实体必须是生产节点。
4. ART22/ART23 的每个一级、二级页签，以及 ART24 的全部 61 个二级状态逐项记录 PASS/FAIL。
5. 动效、靠近/离开、开关箱子、打开/关闭地图和结算返回必须现场操作，不能只看静态截图。
6. 任意必需项 FAIL 均阻止完成；返工后沿用同一冻结标准重新验收。

## 2. 全局视觉标准

- 1280×720 下没有裁切、互相遮挡、点击区漂移或不可读文本。
- FusionPixel 仅用于短标签、标题、按钮和页签；正文、说明、档案和数值使用 NotoSansCJK。
- ART22/23/24 使用一致的深青、黄铜、皮革/金属边框语言，但保持各页面自身结构。
- 已知物品、地图、怪物、事件不得显示错误类别图标或程序几何占位。
- 选中、焦点、锁定、禁用、危险和可领取状态必须可区分，且不只依赖文字。

## 3. ART22 出发探索

- 五个一级页签和全部二级筛选可进入、可返回、焦点正确。
- 8 张 M7 地图均解析到非 fallback 的地图美术；尺寸和难度视觉可区分。
- 10 个商店条目使用对应真实物品图标；6 个委托使用对应语义图标。
- 选中、可用、锁定、推荐、滚动、折叠、活动探索、取消确认和确认出发均不回归。
- 右侧摘要和实际选中数据一致，不显示内部 ID。

## 4. ART23 长期系统

- 全部 27 个一级/二级页面可见且具备合格内容卡。
- 内容卡保留 3 卡/页、分页、选择、焦点、领取/研究动作和状态显示。
- 右侧角色档案始终固定并显示角色、等级、经验、探索、撤离、失败和货币数据。
- 左下拉杆可收起/恢复档案，恢复后回到原页面、分页和焦点。
- 任务、成就、委托、研究、资历、收藏、图鉴绑定真实 ID；未知条目使用统一未知态。
- 抽奖和实际时装保持锁定/预览，不出现伪造的可用内容。

## 5. ART24 局内

- 左栏宽度处于画面宽度约 20%–24%；底栏高度处于画面高度约 5%–7%；中央房间始终为最大视觉主体。
- 玩家透明实画高度处于 560 逻辑房间高度的 11%–15%，脚底、阴影、血条和攻击特效锚定可信；碰撞不随贴图尺寸变化。
- 地图按“标题—大网格—底部操作”呈现，7×7、10×10、13×13 均不溢出；位置、危险、标记、探索语义互不覆盖。
- 地面物先作为世界实体出现，靠近才显示悬浮窗，离开自动隐藏；不得打开固定全屏拾取页。
- 箱子靠近后可打开、关闭、重开、部分拾取、保留剩余和显示空箱。
- 成功、失败、放弃、失败保全候选/选择/容量阻塞均使用真实数据和真实按钮。
- 玩家每方向至少四个视觉上可区分的移动姿态；攻击为四阶段；怪物具备出现、待机、攻击、受击、死亡。
- 减弱动效停止装饰性循环但保留危险、受击、拾取和关键状态信息。
- 局内无可见周期性停顿、追帧跳跃或输入锁死；固定步长、碰撞和结算回归门禁通过。
