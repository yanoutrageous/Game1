# ART22 出发探索最终美术 UI 验收标准（冻结版）

状态：**2026-07-18 在用户扩充动画范围后修订，并在最终 Computer Use 验收前重新冻结**。

```text
Acceptance-Version: ART22-CU-FROZEN-2
Pass-Policy: ALL_34_STATES_AND_MOTION_OR_FAIL
Rework-Policy: SAME_CRITERIA_FULL_RESTART
Motion-Watch-Seconds: 12
```

本标准一经用于最终验收，不允许根据验收结果降低门槛。若任一项目失败，必须在不改变核心内容结构的前提下返工，并使用本文件中的同一套标准从头复验。只有所有项目均为 PASS，ART22 才可关闭、提交和 push；不存在“有条件通过”。

## 1. 核心结构边界

以下结构在 ART22 中固定，不因优化轮次改变：

1. 左侧是环境中的角色、上下直链连接的“返回主菜单 / 长期系统”和角色脚下“外观 / 时装”。
2. 中央是可整体收起的羊皮纸，包含 5 个一级页签、二级筛选、固定高度卡片列表和底部收起 / 展开入口。
3. 右侧是短锁链悬挂的四页摘要告示牌。
4. 右下是指示牌式主操作；存在进行中的探索时，同时显示“继续探索”和“取消当前探索”。
5. 取消行为必须经过阻断式强确认弹窗；真实放弃接口未接入时不得伪造成功或删除进度。

## 3. 每个一级 / 二级状态的共同合格条件

每切换到一个二级状态，必须同时看到并确认：

- 对应一级页签为青绿色选中态，其他一级页签回到羊皮纸常态。
- 对应二级状态为青绿色选中态并完整可见；长列表可通过左右入口、鼠标或键盘到达，当前状态会自动滚入可视区。
- 卡片区至少有 1 个真实可见条目；单结果页显示有底板的结果数量提示，不得呈现为加载失败。
- 卡片保持 112 px 逻辑高度；缩略图、标题、摘要、分类 / 模式标签、状态区均留在各自列内，不重叠、不漂浮、不越界。
- 卡片标题和状态不截断关键语义；摘要可换行且不压入底部标签。所有玩家可见分类标签使用中文。
- 卡片选中反馈、右侧“当前选择”和所属页签语义同步更新。
- 切换时角色、中央羊皮纸、右侧告示牌和右下操作牌不得跳位；滚动位置仅按页签内约定保存或复位。
- 未开放内容只能显示锁定 / 后续开放状态，不得伪装成已实现功能。

只要上述任一条件在 34 个状态中的任一状态失败，该矩阵即失败。

## 4. 全局视觉与排版标准

- 1280×720 逻辑画布中，角色为环境组成部分，不使用独立人物海报式框体；角色占比不得侵占中央羊皮纸。
- 地牢背景同时具备蓝色纵深、暖色工作区和危险暗示；展开态仍能看到左右环境，收起态能看到完整背景主体。
- 左上两个跳转按钮采用上下交替、竖直锁链关系，不使用斜链；右侧锁链短于告示牌高度，不挤压信息区。
- 羊皮纸覆盖中央主要可读区域并延伸到接近上下边缘；一级、二级页签和卡片共享同一信息层级。
- 深色卡片、青绿描边、金色标题与羊皮纸形成足够反差；文字必须依附于按钮、卡片、摘要行或提示底板，不得直接漂浮在复杂纹理上。
- 右侧四个摘要标签和四行内容有独立承载底板；标题、状态消息和正文均不重叠。
- 指示牌主操作清晰；进行时的红色取消按钮与主操作有明确层级和间距。
- 取消弹窗遮罩阻断背景交互，标题、正文、禁用确认和返回按钮均完整；底部装饰不得遮挡按钮文本或命中区。

## 5. 交互、状态与衔接标准

- 从主菜单“出发探索”进入本页面的真实路由可用；“返回主菜单”“长期系统”“外观 / 时装”保持既有路由意图。
- “确认出发”发出既有真实探索路由，payload 不得是 `preview_only`。
- 有进行中探索时，主操作显示“继续探索”，并显示“取消当前探索”；继续接口未持久化时必须诚实提示，不伪造跳转。
- 取消弹窗的真实确认在接口未接入时保持禁用；返回或 Esc 只关闭弹窗，不修改当前运行。
- 中央内容可收起和展开；收起后背景、角色、左侧跳转、右侧摘要和右下操作仍可见，展开后布局精确复位。
- 鼠标、键盘焦点、方向键邻接、Esc 和减少动态效果模式均可用；焦点态不得改变控件尺寸。
- 角色加载 8 张资源级唯一帧，不得用 0.18 s 等间隔机械轮播制造“两帧跳变”观感。0–5 帧用于较慢呼吸 / 眨眼循环（约 0.34 s 节拍），6–7 帧只用于约 5 s 后出现、随后约 10 s 间隔的观察动作（约 0.42 s 节拍）。
- 背景至少有 8 组贴合真实灯具 / 蓝焰 / 烟源的低透明帧动画和 2 组低密度尘粒 / 火星粒子；不得出现悬空光球、遮挡角色或穿过 UI 面板。
- 右侧悬牌可有不超过约 1.2 px 横向、0.7 px 纵向的轻摆；文字必须随底板整体移动，不得产生独立漂浮或模糊。
- 羊皮纸收起 / 展开使用约 0.28 s 的短缓动。减少动态效果时，角色固定首帧、帧动画冻结、粒子停止、悬牌归零，收起 / 展开立即完成。

## 6. 分辨率、资产与回归标准

- 1280×720、1366×768、1600×900、1920×1080、2560×1440 五个 16:9 尺寸均生成新鲜截图；不得拉伸出画布、裁掉操作入口或产生布局漂移。
- 运行时资产必须全部由 manifest 解析；构建报告、源哈希、运行时哈希、尺寸、挂载组与消费者记录完整。
- ART22 运行时 runner 必须报告：`tabs=5 secondary_states=34 summary_pages=4 states=expanded,collapsed,active_run,cancel_modal`。
- 基线导航、UI 层级、ART21 主菜单和 I0 头部模式回归不得因 ART22 失败。
- 不提交 Godot 编辑器生成的 `.translation` / `.import` 副作用，不修改用户原工作树。

## 7. Computer Use 最终验收流程

1. 启动实际 Godot 项目并从主菜单点击“出发探索”，确认真实页面路由。
2. 在 1280×720 窗口逐一点击 5 个一级页签和表中全部 34 个二级状态；每项按第 3 节判定并记录 PASS / FAIL。
3. 对“出勤配置”使用左右入口到达最后两个长标签，确认自动滚入可见区、标签完整和返回前端可用。
4. 逐一点击右侧“摘要 / 配置 / 效果 / 风险”，确认四行内容和状态消息均在底板内。
5. 操作收起与展开，确认背景、布局复位和主要入口的可见性。
6. 在可见的进行时测试状态中检查“继续探索 / 取消当前探索”和取消弹窗；确认返回与 Esc 不修改运行。
7. 连续观察至少 12 秒：确认角色依次出现呼吸、眨眼和间歇侧看，而非快速跳帧；确认灯火 / 蓝焰 / 烟尘附着于环境光源，粒子低密度且不干扰阅读，悬牌轻摆不造成文字漂移。
8. 检查键盘焦点路径和至少一个卡片滚动末端。
9. 对照五个分辨率及动作时序的新鲜静态证据检查缩放与动效关键帧。

最终记录必须列出 34 个状态，不能只写“抽查通过”。Computer Use 发现任何失败后，停止完成流程，返工并从步骤 1 重新执行同一标准。
