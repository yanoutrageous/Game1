# ART24R1 生产流程诊断标准

- 标准 ID：`ART24R1-PRODUCTION-DIAG-FROZEN-1`
- 冻结时点：本轮 Computer Use 诊断之前。
- 目标：证明当前生产游戏哪些环节真实可用、哪些与 UE 原型或用户目标冲突；不以隔离 runner 作为通过证据。
- 判定：每项只记 `PASS`、`FAIL` 或 `UNAVAILABLE`，并保存实际窗口截图/标题与输入结果。

## 入口与流程

1. 启动命令只指向 `project.godot`/`main.tscn`，窗口标题不得含 `ART24` 测试 runner 标记。
2. 主菜单可见，能够通过玩家可见按钮进入出发探索/部署并确认进入局内。
3. 进入局内后不存在挡住全屏且无法关闭的残留模态；游戏焦点仍可接收输入。

## 真实移动

1. 局内角色由生产 `PlayerController` 呈现，不是 `TextureRect` 静态角色层。
2. 分别输入 W/A/S/D 后角色屏幕位置必须发生可见变化，松键后停止；不得始终固定在中心。
3. 角色到达房间门口时，合法方向产生房间切换或明确阻挡反馈；不得无反馈穿墙或永久卡边。
4. 角色朝向/步行动画与移动方向一致，静止后回到正确 idle。

## UE 原型布局对照

1. 左侧固定区域依次包含区域扫描图、生命/战力/资源、当前状态、作业包摘要。
2. 中央房间为主视觉区，背景不变形，角色脚底落在场景地面。
3. 协议/压力固定右上，不吞掉主房间；底部真实按键栏与当前 Godot 输入映射一致。
4. 地图全屏阻断；背包/地面掉落面板不得错误覆盖左侧扫描栏与协议信息。

## 掉落与拾取

1. 搜索成功后必须产生玩家可理解的结果反馈，而不是只更新调试文本。
2. 掉落界面至少显示标题、来源/结果摘要、图标、物品名、数量、类别/稀有度、估值或效果，以及关闭/拾取操作提示。
3. G 打开当前房间地面掉落；Q 打开背包；二者互斥且 Esc 可返回局内。
4. 拾取成功后背包/地面快照同步，世界掉落实体或提示消失；容量不足显示单一明确结论，并提供可理解的替换路径。

## 其他连续流程

1. M/Tab 打开地图并可关闭；Space/J 触发战斗动作或给出合法禁用反馈；T 只在可撤离时进入确认。
2. 暂停、事件、结算等模态出现时停止角色移动，关闭后恢复焦点与移动。
3. 关键流程不得依赖 Debug 面板或 runner 状态切换。

- Computer Use 必须实际启动 `D:\AGAME1\external\ue_prototype\UE\Graytail\Graytail.uproject`，记录可见玩家路径、局内布局、移动与掉落结果界面；源码尺寸、原生资产与官方截图继续作为辅助对照证据。
