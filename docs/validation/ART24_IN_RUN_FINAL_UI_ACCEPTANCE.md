# ART24 局内最终美术 UI 验收标准

## 冻结声明

- 标准 ID：`ART24-ARTPACK-CU-FROZEN-1`
- 冻结时点：最终 Computer Use 验收之前。
- 适用对象：`art/art24-in-run-final-ui` 分支的局内美术资产包、表现接口、隔离 Godot 预览。
- 判定：只允许 `PASS` 或 `FAIL`，禁止条件通过。任何一项失败都必须返工，并按同一标准从 54 个状态起点重新验收。
- 非声明：本标准不验收程序线程的真实玩法接线、数据持久化或自然玩法路线。

## 固定库存

- 一级模块：8 个。
- 二级状态：54 个，唯一事实源为 `docs/art/validation/art24/art24_acceptance_state_matrix.csv`。
- 分辨率：1280×720、1366×768、1600×900、1920×1080、2560×1440。
- 自动截图：54×5＝270 张，不得缺失或以同图冒充。
- 动作观察：真实 Godot 窗口连续 60 秒；同时检查减少动态静态 fallback。

## Computer Use 验收顺序

1. 启动真实 Godot ART24 预览，确认窗口标题含 `Graytail ART24`，不是概念图查看器或普通图片窗口。
2. 以 CSV 顺序用左右键逐一经过全部 54 个二级状态；用 PageUp/PageDown 核对八个一级模块跳转。
3. 在五档分辨率分别核对模块边界；每档必须与对应自动截图尺寸一致。
4. 回到 `room.normal.idle`，连续观察 60 秒，再查看 `motion.reduced`。
5. 任何一项失败立即记录、停止本轮、返工；修正后重新从步骤 1 开始。

## 逐屏硬标准

### 全局布局

- 左栏宽 300 逻辑像素；中央房间占剩余主区；右上协议牌不遮挡主角/关键道具；底栏高 72 逻辑像素。
- 五档分辨率均不得裁边、溢出、出现黑边或非等比拉伸；安全边距至少 8 逻辑像素。
- 现有房间背景采用等比 cover，不得变形；主角脚底落在场景地面，不能表现成脱离环境的立绘。
- 正文统一使用项目 Noto Sans CJK；无乱码、截断、重叠、内部键名或占位符。

### HUD 与协议

- 左栏小地图、生命、战力、黑币、零件、安全收益、探索格、雷险与当前房间均可辨认。
- 协议牌固定显示 `安全 5 → 1 危险`，等级 5/4/3/2/1 的色彩、标题与压力条必须同步。
- 底栏固定显示真实键位：WASD、M/Tab、E、Q、G、Space/J、T、Esc；禁止以错误键位替代。

### 房间、角色与反馈

- normal/mine/chest/event/monster/exit 六房型与各自状态道具一致，无跨房型错误回退。
- 主角、铁背怪物、道具不出现空纹理、房间缩略图 fallback 或洋红抠图底。
- 主角基础 24 帧、战斗 16 帧、怪物 8 帧可解析；战斗态可看到蓄力/挥击/命中/收势和弧光反馈。
- 世界掉落至少 8 类可解析；生成、悬浮、拾取飞行、容量阻塞和替换预览语义不同。

### 模态层级

- 地图是全屏阻断层；背包与地面物品仅覆盖中央局内区，左栏保持可见，协议牌可见且不被面板吞没。
- 背包空/有物/选中/tooltip/满载五态均有明确差异；地面物品七态均有明确差异。
- 容量不足只能出现一次主结论，不得用重复 toast 堆叠同一句警告。
- 教程、事件、暂停、撤离确认、成功/失败/放弃结算保持各自标题、危险色和返回层级。

### 动效与减少动态

- 60 秒内可见环境尘埃、扫描环、角色呼吸/眨眼、怪物呼吸、协议/拾取/房间反馈中的适用项；不得出现卡死、闪屏或大图错误回退。
- `motion.reduced` 禁用循环尘埃和扫描动画，攻击/爆炸/拾取保留可理解的静态结果帧。
- 动效不得改变真实玩法事实；丢失表现事件后，静态快照仍能恢复正确画面。
