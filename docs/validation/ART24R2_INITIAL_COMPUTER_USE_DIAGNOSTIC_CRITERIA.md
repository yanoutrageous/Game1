# ART24R2 初次 Computer Use 诊断标准

- 标准 ID：`ART24R2-INITIAL-CU-DIAG-FROZEN-1`
- 冻结时点：ART24R2 初次 Computer Use 启动前。
- 事实基准：当前 Godot 生产入口及当前分支代码。
- 视觉基准：实际 UE 原型与 `game_material/screenshot_gameplay.png`、`screenshot_map.png`。
- 排除项：ART24 预览 runner 和旧 Godot 画面不得作为视觉通过依据。
- 本次目的：记录返工前事实；不是最终完成验收。

## A. 生产入口与主构图

1. 从生产主菜单和出发页进入真实局内，不使用 runner 或 Debug 注入。
2. 检查左栏、中央房间、右上协议层和底栏的面积、遮挡、角色尺度、地面关系及文字可读性。
3. 检查中央房间是否仍是绝对主视觉，HUD 是否存在重复装饰、无效留白或信息错层。

## B. 移动、动画与战斗房性能

1. 至少验证水平和垂直移动、静止 idle、攻击及受击状态。
2. 进入真实战斗房，记录玩家、敌人和弹射物是否出现固定步长跳动、周期性停顿、追帧或输入迟滞。
3. 检查角色和敌人的尺度、脚底锚点、遮挡、动画帧数及风格一致性。
4. 记录战斗房相对普通房间的卡顿差异，不以主观“能动”替代连贯性判断。

## C. 掉落、拾取与背包

1. 通过真实搜索/战斗产生地面物品，检查实体、光柱、名称、稀有度和接近提示。
2. 玩家进入感应范围后检查非固定的地面物品悬浮窗；离开范围后必须自动消失，且不得成为暂停移动的一级模态。
3. 检查悬浮窗中的物品行、选中/禁用/容量阻塞和拾取/替换入口；检查拾取后地面实体、悬浮窗和背包内容是否同步。
4. 靠近箱子时才显示打开悬浮窗；首次打开生成一次真实内容，关闭再打开时内容不得复制，部分拾取和空箱状态必须保持。

## D. 地图与其他模态

1. 检查放大地图的居中、压暗、格状态、详情和关闭恢复。
2. 检查事件、暂停、撤离和结果面板是否保持主构图层级，是否存在文本压框或按钮错位。

## E. G41/M6 新状态准备度

1. 记录当前界面是否能容纳装备/消耗品区分、2 件装备/3 件补给限制、容量和临时申领。
2. 记录成功、失败、放弃和失败保全候选/选择/超重/确认是否有正式 ART24 表现。
3. 若当前分支尚未合并最新 M6，相关项记为 `MISSING`，不得误判为通过。

## 记录规则

每项记 `PASS`、`FAIL`、`MISSING` 或 `UNAVAILABLE`，并保存可见窗口事实。初次诊断结束后形成问题清单，执行阶段不得改变固定核心结构来规避问题。固定的“地面回收物”整屏面板明确不属于目标结构。
