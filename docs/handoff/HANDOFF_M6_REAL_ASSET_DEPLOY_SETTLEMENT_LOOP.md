# HANDOFF M6 真实资产、出勤与结算闭环

状态：已关闭（2026-07-19）

## 中文摘要

M6 将 M5/G41 已有的局内物品与战斗运行时接到真实局外资产：玩家从仓库实例中手动选择两件以内装备和三件以内消耗品，可申领一份只存在于本局的应急压缩饼；成功、失败手动保全和放弃都通过同一结算权威写回仓库、金色资源与历史记录。

## 程序侧交付

- 新档固定初始库存，旧档按版本最多补发一次；默认金色资源为 0。
- 出发页不再自动选择仓库前若干项，仓库卡片会真实增删出勤草案。
- 六件装备的容量、保全容量、触雷减伤、搜索收益、扫描提示和协议压力缓冲进入运行态。
- 所有携入或局内获得的消耗品在成功、失败或放弃时清除，不返还仓库、不进入失败保全池。
- 失败先显示只读候选池，玩家按重量选择并确认后才允许提交 MetaProgress。
- 放弃需要强确认，保全容量为 0，黑色资源失去，已直接获得的金色资源保留。
- 当前进程内可从局内返回出发页并继续同一 `run_id`；不会创建第二局。
- 每个最终结果只提交一次，并在局外保留最多 50 条独立历史快照。
- 普通实体物品均有搜索、宝箱、战斗、事件或祭坛来源；旅商收据改为虚拟记录，唯一占位仍锁定。

## 未包含

- 完整仓库买卖、堆叠、整理与扩容经济；
- 保险、托运、耐久、随机词条与装备强化；
- 研究、抽奖、收藏奖励和完整任务/目标奖励；
- 退出 Godot 进程后的局内检查点恢复；
- ART24 代码或资源；
- 最终美术验收、完整人工长时间游玩、性能、CI 和发布。

## 美术并行接口

程序继续使用现有 `display_name`、`short_description`、`icon_fallback`、稀有度、物品类型和稳定卡片标识。美术侧可以替换图标、面板和动效，但不应把贴图尺寸反向作为容量、碰撞、装备槽或结算规则。
