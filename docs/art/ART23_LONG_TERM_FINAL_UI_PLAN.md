# ART23 长期系统可交付最终美术 UI 计划

状态：已完成；`ART23-CU-FROZEN-2` Computer Use 全量验收、两轮优化、自动回归与 I0 污染守卫均已通过。

## 目标

以当前 Godot 代码、真实路由和现有数据边界为准，把“长期系统”建设为可交付的最终美术 UI。页面保留项目既有的六个一级模块和二十七个二级页签，不复用 ART22 的出发探索结构；视觉主体是长期驻留的档案室，模块切换表现为对应箱柜、陈列柜或工作台打开，右侧角色档案始终固定。

## 固定流程

1. 计划：读取策划、代码、既有概念图与 ART22 基线，冻结范围和不可伪造边界。
2. 审计：核对真实 AppShell 路由、六个模块、二十七个二级页、角色资源、manifest、分辨率和维护成本。
3. 执行：建立独立 ART23 工作树，生产干净房间与六套模块家具，落地布局、交互、状态机、焦点和动效。
4. 完成审计：先生成全量静态矩阵和运行时检查，再进行问题驱动的两轮优化。
5. 最终验收：先冻结验收标准，再用 Computer Use 从真实主菜单逐项验收；任何失败均按同一标准全量重启。
6. Push：只有自动化、Computer Use、文档、diff 与回归全部通过后才提交并推送 `art/art23-long-term-final-ui`。

## 两轮优化约束

核心内容结构在优化轮次中不得改变：房间为背景、顶部六模块、中央对应家具与内容板、右侧固定角色档案、左下收起拉杆保持不变。

- 首次审计：发现说明文字承载区发糊、底部元信息越出羊皮纸、拉杆标签悬空、切换缩放中心偏移。
- 优化一：重排标题/元信息/正文/卡片，清除正文阴影，重画拉杆底座并把标签纳入底座，修正模块缩放中心。
- 优化二：二级页切换时羊皮纸、文字、元信息和卡片同步淡入；拉杆增加焦点反馈；五分辨率复查后隐藏图鉴末端的原生灰色滚动条，同时保留自动滚入。

## 可维护性边界

- 坐标集中在 `long_term_layout_contract.gd`，业务模型不散落硬编码矩形。
- 运行资产由 `art23_long_term_asset_contract.gd` 与 manifest 解析，生成脚本可重复运行。
- 家具、背景、按钮、框体、角色和文字相互分层；新增二级页不要求重绘整屏。
- 右侧数值只读取既有 snapshot；研究、抽奖和换装保存未接入时只能显示封存/只读，不伪造扣费、解锁或持久化成功。
- 不提交 `.godot`、`.import`、`.translation` 等编辑器副作用，不修改 ART22 用户工作树。
