# ART23 长期系统最终美术 UI 收口

## 收口结论

ART23 已在不改变六大模块核心内容结构的前提下完成美术、排版、资源落地、切换衔接、动效、字体分工和可维护契约。最终结果不是概念图复刻：所有页面均在真实 Godot 主线中运行，并以代码现状为真源。

## 本阶段完成内容

- 六种家具隐喻：目标桌、图鉴柜、研究柜、角色档案柜、抽奖柜、收藏展示柜。
- 六个一级模块与 27 个二级页面完整落地；每页有对应家具、羊皮纸信息区和三槽深色卡片。
- 右侧固定角色档案显示同一游戏角色、身份、等级、经验、探索/撤离/失败/长期金币与外观入口。
- 极左下机械拉杆负责收起/展开，中间家具和内容作为整体移出，背景成为完整档案室。
- 一级切换使用关闭→空档→打开流程并采用 latest-request-wins；二级页面整体淡入，避免文字独立浮动。
- 角色由两帧临时表现提升为八张资源级帧，并加入低干扰环境光、尘粒和蓝色微粒。
- 字体分层完成：像素字体承担短控件语言，Noto Sans CJK SC Regular 承担正文和数据阅读。
- 58 个 ART23 纹理、正文字体、来源、许可、加载组、哈希和解码预算纳入 manifest/合同。

## 美术来源与风格处理

统一档案室源图通过 imagegen 生成，提示约束以当前长期系统版式、ART22 黑铁/深木/暖金/青绿语法、同一角色风格为依据，并明确不在源图内生成 UI、文字或角色。运行时再由代码和切割资产填充六种家具、控件、角色档案与交互状态，因此后续可以独立替换背景、家具、页签或字体，不必重做整张界面。

## 客观验收结果

- Computer Use：`ART23-CU-FROZEN-2`，27/27 PASS；连续动效观察 60 秒 PASS。
- 分辨率矩阵：5×27=135/135 PASS，135 个状态哈希唯一。
- 运行时资产：58；默认/总解码 6.86/16.27 MiB，满足 8/18 MiB 门槛。
- 回归边界：真实主线入口、ART22 出发探索、ART21 主菜单、导航边界与 I0 允许范围均需保持通过。

## 后续阶段边界

本收口只确认长期系统“最终美术 UI”可交付，不声称长期玩法逻辑已经完成。后续程序接入真实数据时，应保持现有视觉/布局契约，通过模型层替换投影数据；若需要改变六模块信息架构，应作为新阶段重新计划和冻结验收标准。
