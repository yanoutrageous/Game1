# ART25 两轮问题驱动优化记录

- 冻结标准：`ART25-FINAL-CU-FROZEN-1`
- 约束：不改变 ART22 五页签结构、ART23 六模块/27 页/右侧档案/左下拉杆结构、ART24 8 模块/61 状态与程序规则。
- 防循环规则：同一根因最多处理两轮；每轮同时检查相邻状态和保护集，不以单张截图作为完成依据。

## 初始审计

### 长期系统

真实运行截图暴露了三项排版根因：

1. 内容图占卡片比例过大，视觉重心挤压标题和状态，连续三卡形成“图标墙”。
2. 图、标题、状态之间的水平留白不足，皮革/深青底与文字层级没有充分拉开。
3. 地图缩略图是宽源图，沿用方形图标布局时会在首次 minimum-size 计算中保持源宽，产生裁切而非正确缩放。

### 局内

对照 UE 实际布局和 Godot 生产截图后，确认玩家当前透明实画约占 560 逻辑房间高度的 13.4%，已位于冻结的 11%–15% 区间；旧截图中的“人物过小”不能继续作为当前事实。因此没有再次放大角色或改变碰撞锚点。

实际需要修正的是：

1. 560×560 房间外侧使用 Godot 默认灰/黑清屏色，视觉上像未完成空区，削弱房间主体与 UE 空间连续性。
2. 世界悬浮窗、失败保全和结算说明中的中文正文没有显式继承长期页已验收的 NotoSansCJK 正文字体规则。
3. 旧概念/预览中的四块额外结算指标卡与 UE 生产原型不一致；UE 的实际结构是约 448 外框、300×130 横幅、居中正文和双操作，因此不应为了“信息更多”启用隐藏实验卡。

## 第一轮优化

### 修改

- 长期内容卡的图像井从 54 px 级别收敛为 45×52，文字区左边界移到 59 px，保留 3 卡/页和原分页逻辑。
- 提升选中、普通、锁定三态的标题/状态对比，并保留底部非文字状态条。
- 为世界悬浮窗正文、状态、物品信息和结算摘要/指标/保全列表显式指定 NotoSansCJK；短标题、页签和按钮继续使用像素字体。
- 保持玩家比例、房间 560 逻辑尺寸、左栏与底栏、锚点、碰撞和交互命令不变。

### 相邻状态复验

- ART23：任务、研究、收藏代表页及 27 页 1280×720 矩阵通过。
- ART24：普通房、地面物、成功结算、失败保全代表生产截图通过；结果、悬浮窗和锚点探针通过。
- ART22/23 主路由和运行回归通过。

## 第二轮优化

### 修改

- 长期内容卡开启 `clip_contents`，宽地图图源统一装入固定图像井。
- TextureRect 加入父节点后重新应用 `PRESET_FULL_RECT` 与 3/4 px 内边距，确保宽图执行居中等比缩放，不覆盖正文。
- 新增无逻辑、无 process 的 `Art25GameplayBackdrop`：只在完整 560 房间后方以低亮度、低 alpha 延展当前房间纹理，随房间类型更新；不复制交互物、不改变房间节点、碰撞或世界坐标。
- 将项目默认清屏色改为近黑深青，消除无法被背景覆盖时的 Godot 默认灰缝。

### 相邻状态复验

- ART23 图鉴地图修正前后截图核对通过；27 页、5 分辨率共 135 张全部可渲染。
- ART24 普通房、箱子、地面物、成功结算生产截图核对通过；8 模块/61 状态在 5 分辨率共 305 张全部通过。
- G41 固定调度、怪物视觉契约、世界悬浮窗、目标避让、地图、背包和结算探针全部通过。
- ART25 资产预算仍为出发 0.721 MiB、长期 0.993 MiB；局内只复用已有房间纹理，FX 净增为 0。

## 两轮后结论

两轮分别解决了“内容卡视觉/可读性”和“宽图适配/房间外空区”两个根因，没有修改核心内容结构，也没有继续以角色大小或结算实验卡做无边界调参。剩余的 Godot 退出资源警告与历史封存验证器哈希/分支护栏被单独记录，不在美术层伪造修复。下一步只允许按冻结标准进行最终 Computer Use 生产态验收；若出现 FAIL，按同一标准返工，不另起第三轮主观美化。
