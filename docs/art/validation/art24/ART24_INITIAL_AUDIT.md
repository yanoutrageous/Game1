# ART24 初始审计

## 结论

当前局内玩法接口不是空壳，但现有画面仍停留在 ART21R2 的结构性 UI：中央房间虽有可用底图，角色只有四个静态方向帧；没有怪物演员动画；地面物品只在列表中存在，没有世界生成、悬浮、拾取飞行与移除表现；背包、地面物品、地图和结算仍使用偏诊断式的密集黑框。ART24 必须补足表现层，不能用概念图或静态整屏替代。

## 代码事实

- `RunRuleService`、`RunAssetLedger`、`RunScene`、`InventoryPanel` 与 `GroundLootPanel` 已形成真实的生成、地面存放、拾取、丢弃和自动替换接口。
- UI 已能发出 pickup / replace / drop / use 请求；本美术分支不修改其语义。
- `run_surface.gd` 在程序工作树存在未提交修改，属于并行开发冲突面。
- `project.godot` 和多份翻译副作用在其他工作树为 dirty，不能带入 ART24。

## 资产事实

- 六类现有房间底图质量与项目风格合格，优先复用；运行时采用 cover 裁切而非拉伸。
- 现有宝箱、陷阱、异常核心、撤离装置和地图图标可以复用。
- 现有玩家角色身份和体形合格，但帧数不足。
- 当前缺少同风格怪物动作、世界掉落、拾取反馈和 ART24 专用状态 UI。

## 初始风险

1. 直接修改生产 UI 会与程序线程冲突。
2. 方形房间底图若直接拉伸到宽屏中央区会造成比例失真。
3. 角色/怪物图集若未统一基线，会在动作切换时抖动。
4. 生成素材色键边缘、透明像素和尺寸若不验证，会出现紫边或导入空白。
5. 只验收正常 HUD 会漏掉地图、背包、地面物品、协议、确认和结算状态。
6. 自动截图不是 Computer Use，不能替代最后人工可见验收。

## 决策

- 从已推送的 ART23 提交建立独立 ART24 工作树。
- 用隔离 Godot 预览消费与生产侧相同语义槽，但不调用玩法命令。
- 程序只依赖 `visual_key` 与表现快照，不依赖文件名。
- 复用和新制资产统一进入独立 manifest fragment。
- 先冻结 `ART24-ARTPACK-CU-FROZEN-1`，再进行任何最终验收。
