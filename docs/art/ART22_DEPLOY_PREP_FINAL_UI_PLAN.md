# ART22 出发探索可交付最终美术 UI 计划

状态：已完成；冻结标准 `ART22-CU-FROZEN-2` 的 Computer Use 全量审计已通过。

## 目标

在保留现有代码真实路由、运行边界和动态数据来源的前提下，把“出发探索”建设为可交付的最终美术 UI：背景有吸引力但透露危险，角色属于环境，中央羊皮纸可收起，右侧摘要悬挂展示，主操作为指示牌；五个一级页签及全部二级状态都具备稳定排版、素材填充和交互反馈。

## 固定流程

1. 计划：核对策划、代码、资产、路由和前一阶段基线，冻结范围与不可伪造边界。
2. 审计：检查现有实现、真实数据、素材来源、分辨率、性能和后续可维护性。
3. 执行：建立布局 / 资产契约，生成并接入素材，完成所有页签和运行状态。
4. 问题驱动优化：在不改变核心结构的前提下执行两轮优化，每轮均重新截图和审查。
5. 完成审计：先冻结验收标准，再用 Computer Use 逐项验收 5 个一级页签和 34 个二级状态；失败则按相同标准返工。
6. Push：自动化、Computer Use、文档、diff 审计全部通过后，才提交并推送 ART22 分支。

## 实现切片

- A. 1280×720 逻辑布局契约与 UI 分层。
- B. 干净地牢背景、羊皮纸、告示牌、锁链、按钮、卡片、路线缩略图和语义图标资产。
- C. 五个一级页签、动态二级筛选、固定高度卡片和右侧四页摘要。
- D. 角色 idle、收起 / 展开、焦点态、滚动与减少动态效果。
- E. 确认出发、进行时继续 / 取消、强确认弹窗和真实 / 未接入边界。
- F. 34 状态矩阵、五种分辨率、回归、Computer Use 与交付文档。

## 可维护性约束

- 布局矩形集中在 `deploy_prep_layout_contract.gd`，不把坐标散落到业务模型。
- 运行时资产由 `art22_deploy_prep_asset_contract.gd` 和 manifest 解析；生成器可重复运行并记录哈希。
- 卡片通过单一 `deploy_prep_card_view.gd` 渲染；新增数据不需要重画整张界面。
- 文本、数据、路由和图片分离；概念图不直接挂载为运行时整屏。
- 未接入的持久化继续 / 放弃、完整目标奖励、许可消耗等功能保持诚实的 locked / disabled 边界。
