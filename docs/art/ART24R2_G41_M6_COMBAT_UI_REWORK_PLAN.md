# ART24R2：G41/M6 局内美术返工计划

状态：执行中。

## 中文摘要

本阶段返工 ART24 的真实局内美术表现。以当前 Godot 生产代码为玩法和状态事实源，以 `D:\AGAME1\external\ue_prototype` 的实际 UE 原型与官方截图为空间层级、角色尺度、场景氛围和反馈顺序基准。旧 Godot 局内画面及 ART24 预览 runner 不作为视觉验收标准。

最新 G41/M6 提供真实仓库出勤、局内物品、背包、失败保全与结算接口；它没有提供正式美术贴图。本阶段需要把这些真实状态接入可维护的 ART24 表现，同时修复战斗房固定步长直出、快照重复深拷贝和逐帧重复配置造成的卡顿。

## 固定核心结构

返工不改变以下主构图：

1. 左侧固定区域扫描、生命/资源、当前房间/目标与背包摘要；左下优先呈现真实背包内容与容量。
2. 中央房间为绝对主视觉，角色、敌人、掉落和交互物属于场景，不是悬浮展示图。
3. 右上固定协议、压力与当前房间危险反馈，不堆放背包或无关信息。
4. 底部为横向生产按键条；地图、背包、事件、暂停、撤离和结算保持既有互斥关系。地面物品悬浮窗属于房间上下文，不是一级模态。

## 返工范围

### 1. G41/M6 同步

- 合并远端 `godot/g41-in-run-core-gameplay-runtime` 最新 M6 提交。
- 保留 ART24 布局与样式契约，接入真实装备、消耗品、容量、金币/黑色资源、局内继续、放弃和失败保全字段。
- 只由快照和稳定实例 ID 驱动世界掉落、背包、出勤与结算，不在美术脚本中伪造物品。

### 2. 战斗房和角色表现

- 对 G41 固定 60 Hz 模拟增加显示插值，不改变权威模拟结果。
- 去除战斗快照的重复深拷贝和每帧无条件节点重建/静态属性写入。
- 玩家维持四方向 idle、移动、攻击、受击；战斗敌人不得继续使用与正式角色风格不一致的纯程序几何占位。
- 战斗警戒、受击、攻击命中、掉落生成、拾取和协议变化均提供克制且可关闭的表现反馈。

### 3. 地面物品上下文交互

- 地面物品始终以房间实体、稀有度光束和落地点关系呈现，不通过固定 HUD 或整屏列表代替。
- 玩家进入物品感应范围后才显示上下文悬浮窗；离开范围自动淡出，不暂停局内移动。
- 悬浮窗包含当前聚焦物的图标、名称、类别、稀有度、重量、价值/效果、容量结论及拾取操作。
- 同一感应范围存在多件物品时，悬浮窗显示紧凑列表并突出当前聚焦项，不把所有房间物品升级为全屏仓库。
- 容量不足在悬浮窗内明确阻塞；需要替换时才进入背包的局部替换状态，确认或取消后返回原地面物上下文。
- 箱子复用同一上下文骨架：进入感应范围后才显示“打开”，离开范围后自动收起悬浮窗。
- 箱子首次打开只生成一次权威内容；箱盖与容器悬浮窗可以重复打开/关闭，重复开合不得复制奖励。
- 已打开箱子再次查看时显示真实剩余内容；部分取走后保留剩余实例，全部取走后显示空箱，已开封的箱体视觉状态保持。

### 4. 局内一级模块

- 常态 HUD、放大地图、背包、普通搜索结果、事件/暂停/撤离、成功/失败/放弃结算。
- 每个一级模块均从生产入口进入并通过布局、互斥、关闭恢复和真实状态验证。

### 5. 二级状态

- 房型、协议等级、角色动作、物品稀有度、选中/禁用/容量阻塞、拾取成功/失败、地图格状态和三种结算结果。
- 新增 M6 的装备/消耗品区别、临时申领、失败保全候选/选中/超重/确认、活动局继续/放弃状态。
- 未知状态必须回退到统一 fallback，不显示内部 ID 或破坏布局。

### 6. 可维护性

- 布局尺寸集中在 ART24 布局契约；视觉资源通过稳定键解析；状态映射和动效时序独立。
- 节点结构只在创建时建立，静态视觉属性只在脏状态变化时更新；位置插值只负责呈现。
- 允许替换贴图、图标和动效而无需修改容量、碰撞、装备槽或结算规则。

### 7. 素材选择顺序

每个新增视觉项在制作前必须按以下顺序检索并记录结论：

1. 当前 Godot 工程已导入且通过清单门禁的素材。
2. 项目素材库 `D:\AGAME1\sources\art` 与 `D:\AGAME1\sources\draw\30_game_ready`，必要时再查 `sources\draw` 的已处理目录和清单。
3. UE 原型 `D:\AGAME1\external\ue_prototype` 的同项目素材与规格文档。UE 可以作为造型、帧序和空间表现参考；只有来源提交、哈希和复制边界均可审计时，二进制素材才允许迁入 Godot。
4. 前三层不存在语义匹配、质量达标且授权明确的候选时，才允许新制或生成；新制素材仍须保留来源图、提示词/制作说明、透明处理过程与输出哈希。

判断“可复用”不能只看文件名：还要比较角色比例、像素颗粒、轮廓、视角、动作覆盖、透明边缘、运行时尺寸与当前生产代码状态。发现更高优先级候选后，不得以已经完成新制为由跳过客观对比。
