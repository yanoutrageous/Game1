# ART24R1 — UE 原型对齐的真实局内返工计划

状态：最终 Computer Use 与自动验证 PASS，等待审计提交及远端推送封口。上一轮 ART24 的“隔离状态预览 PASS”不再作为真实游戏流程完成证据。

## 返工原因

上一轮启动入口是 `art24_in_run_art_preview_runner.gd`。该脚本把角色锚定在房间中心，只能左右切换展示状态，没有接入移动、碰撞、房间切换、搜索、拾取、战斗或撤离状态机。它可用于资产检查，但不能代表玩家可玩的生产流程。

本轮以 `yanoutrageous/Game.git` 的 UE 原型为局内体验基准，以当前 Godot 生产代码为事实源。完成定义从“隔离预览可看”改为“从主菜单进入真实局内后可连续操作并呈现 UE 原型的视觉与反馈层级”。

## 固定目标结构

1. 生产入口：只从 `project.godot` 的 `main.tscn` 进入，不再以测试 runner 代替游戏。
2. 局内主体：左侧区域扫描/状态/作业包，中央为可移动的真实房间，右上为协议与压力，底部为生产按键提示。
3. 角色：使用生产 `PlayerController`；WASD/方向键改变房间内坐标，走到门边触发房间切换，动画跟随移动/朝向。
4. 掉落闭环：世界掉落标识与靠近提示、搜索结果、地面掉落列表、物品卡、稀有度/估值/数量、拾取成功、容量阻塞、替换预览、拾取后世界物体移除。
5. 模态：地图为全屏阻断；背包和地面掉落覆盖中央区域但保留左栏/协议；结果框对齐 UE 640px 居中金属面板语法。
6. 流程：主菜单 → 出发探索/部署 → 局内移动 → 搜索/拾取 → 地图/背包 → 战斗或事件 → 撤离 → 结算 → 返回菜单。
7. 可修改性：布局尺寸、资产键、状态映射和动效时序继续分离；生产事实来自现有快照/命令，不在美术脚本中伪造。

## 执行流程

1. 计划：冻结真实流程、UE 对齐项、掉落状态和验收路径。
2. 审计：Computer Use 运行当前生产入口，同时打开 UE 原型证据并记录逐屏差异。
3. 执行：修复生产接线，重做局内布局与掉落表现；隔离预览降级为资产工具。
4. 完成审计：程序测试、污染守卫、分辨率矩阵与真实流程冒烟。
5. 两轮优化：只围绕已记录差异迭代，不再次更换核心结构。
6. 最终验收：先冻结最终标准，再用 Computer Use 从主菜单完成真实玩家路径。
7. Push：只有真实流程、视觉对齐、两轮优化和最终 Computer Use 均 PASS 后推送。

## 非声明边界

本轮可以修改完成真实流程所必需的 Godot 生产接线，但不得把测试 runner 的假状态写入生产。UE 原型不是逐像素照搬尺寸的许可证；分辨率、按键和已有 Godot 领域规则仍以当前生产代码为准，视觉层级、交互反馈与空间关系以 UE 原型为基准。
