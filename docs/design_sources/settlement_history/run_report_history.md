\# 新增章节：本局结算报告与历史战绩系统



\## 1. 系统定位



本局结算报告与历史战绩系统用于承接一局探索结束后的结果反馈与长期记录。



它不属于仓库界面，也不属于图鉴界面。它是局内到局外之间的结果确认层。



本系统负责回答：



```text

这一局发生了什么？

这一局是否成功撤离？

这一局带回了什么？

这一局丢失了什么？

哪些资源发生了变化？

哪些内容进入仓库？

哪些内容解锁图鉴？

哪些任务 / 成就 / 研究 / 资历发生了变化？

之后我可以去哪里处理这些变化？

```



一句话定位：



> 本局结算报告负责“立即告知本局结果”；历史战绩负责“长期保存每局结果快照”。



\---



\## 2. 与仓库的关系



本局结算报告不放在仓库界面内。



仓库只负责管理当前已拥有物品，不负责展示当局完整结果。



正确关系如下：



```text

本局结算报告：展示这一局新增、丢失、转化、清空、解锁、完成的结果

仓库：展示当前玩家已拥有的物品

图鉴：展示已发现 / 已拥有 / 已触发内容的记录

研究：展示可解锁功能

任务 / 成就：展示长期目标完成状态

历史战绩：保存每一局的结果快照

```



本局结束后，如果有新增物品、图鉴、研究、任务、成就等变化，对应系统应通过红点、角标或“新增”筛选体现，而不是在仓库界面弹出完整结算结果。



例如：



```text

本局带回新装备

↓

结算报告中立即展示

↓

仓库出现新增红点

↓

仓库内该装备带有“新”标记

```



```text

本局首次遇到某怪物

↓

结算报告中提示“图鉴新增”

↓

图鉴出现新增红点

↓

图鉴内对应条目解锁

```



\---



\## 3. 与历史战绩的关系



本局结算报告是当局结束后的即时页面。



历史战绩是长期保存的战绩查询系统。



本局结算报告确认后，应写入历史战绩。之后玩家可以在历史战绩中回看该局内容。



历史战绩记录的是当时的结果快照，不随当前仓库变化而改变。



例如：



```text

某局带回“旧怀表”

之后玩家出售了“旧怀表”

历史战绩中仍显示该局曾带回“旧怀表”

仓库中则不再显示该物品

```



\---



\## 4. 本局结算报告显示内容



本局结算报告应显示本局关键结果，而不是展示完整仓库。



建议分为以下区域：



```text

基础结果

资源结算

物品流向

委托 / 任务 / 成就变化

图鉴 / 研究 / 资历变化

丢失 / 清空 / 抢救结果

后续跳转

```



\### 4.1 基础结果



显示：



```text

地图模式

难度

区域

探索结果：成功撤离 / 失败 / 放弃 / 特殊结束

探索时间

探索步数或房间数

打开房间数

触发事件数

击败怪物数

是否完成委托

```



\### 4.2 资源结算



显示本局资源变化：



```text

带出黑币

黑币转金币

获得金币

消耗金币

抽奖券 / 凭证变化

其它通用货币变化

```



黑币转金币应在本局结算报告中明确展示。



示例：



```text

黑币：126

成功带出 → 转化金币：126

```



若失败导致黑币丢失，也应明确展示：



```text

黑币：126

撤离失败 → 已丢失

```



\### 4.3 物品流向



显示本局物品结果：



```text

成功带回物品

新增装备

新增藏品

新增唯一藏品

新增特殊物

局内获得但未带出的物品

失败丢失物品

抢救保留物品

被清空的消耗品

```



物品流向需要清楚标记：



```text

进入仓库

进入图鉴

已丢失

已清空

已转化

已抢救

重复获得

首次获得

```



\### 4.4 委托 / 任务 / 成就变化



显示：



```text

本局委托是否完成

委托奖励

未完成委托是否消失

任务进度变化

任务完成提示

成就完成提示

隐藏成就完成提示

```



委托是单局目标，未完成则消失。历史战绩中可以记录该局曾选择过该委托以及完成状态，但委托本体不进入长期任务列表。



\### 4.5 图鉴 / 研究 / 资历变化



显示：



```text

新增图鉴条目

图鉴条目补全

新增研究解锁条件

研究完成提示

回收资历经验或进度变化

回收资历升级

新增可用功能提示

```



图鉴、研究、资历的完整查看应跳转到对应系统，不在结算报告中展开全部详情。



\### 4.6 丢失 / 清空 / 抢救结果



显示：



```text

失败时丢失的装备

失败时丢失的背包物品

失败抢救保留物

本局消耗品清空

特殊规则保护的物品

保险 / 托运 / 保护类规则结果

```



消耗品清空需要提示，但不应过度打断玩家。



示例：



```text

本局携带消耗品已清空

局内获得消耗品已清空

特殊保留规则：无

```



\---



\## 5. 唯一藏品在结算报告中的展示



唯一仍然是藏品的一种。



但唯一藏品可以拥有特殊展示规则。



当玩家首次获得唯一藏品时，本局结算报告可以触发更高规格展示，例如：



```text

特殊获得演出

特殊边框

特殊音效

特殊展示页入口

收藏展示入口

图鉴新增提示

```



唯一藏品的性质不变：



```text

大类：藏品

稀有档：唯一

可进入仓库

可进入图鉴

可进入收藏展示

不可出售

不提供局内数值收益

不作为主线必需内容

```



若唯一藏品附带外观、展示、特效等内容，应在结算报告中提示：



```text

已解锁附属展示内容

前往外观 / 展示配置

```



但外观配置不在仓库内处理。

\## 6. 历史战绩系统



\### 6.1 系统定位



历史战绩用于长期保存玩家每一局探索记录。



它负责：



```text

记录过往探索

查看每局结算结果

回顾带回 / 丢失 / 完成 / 解锁内容

支持按条件筛选历史记录

为成就、任务、资历、统计提供查询依据

```



历史战绩不负责：



```text

修改仓库

修改图鉴

修改研究

重新领取奖励

重新结算资源

修改当前局状态

```



\### 6.2 历史战绩入口



历史战绩可以放在长期系统中。



建议位置：



```text

长期系统 → 回收资历 / 战绩记录

```



或：



```text

长期系统 → 档案 / 历史战绩

```



不建议作为主菜单大入口。



\### 6.3 历史战绩列表



历史战绩列表应显示：



```text

探索编号

日期 / 时间

地图模式

难度

区域

成功 / 失败 / 放弃

带回价值摘要

委托完成状态

击败怪物数

发现内容数

获得藏品数

是否有唯一藏品

```



\### 6.4 历史战绩详情



点击某条历史战绩后显示详情。



详情可包含：



```text

基础结果

地图与难度

出勤配置摘要

委托状态

资源变化

物品带回

物品丢失

黑币转金币

消耗品清空

怪物击败

事件触发

宝箱开启

搜索次数

新增图鉴

任务 / 成就变化

资历变化

结算跳转记录

```



历史战绩详情只读，不允许重新操作物品或重新领取奖励。

\## 7. 排序与筛选



历史战绩应支持基础排序与筛选。



\### 7.1 排序



可按以下规则排序：



```text

时间

成功 / 失败

地图模式

难度

带回价值

探索时长

击败怪物数

获得藏品数

获得唯一藏品

委托完成状态

```



\### 7.2 筛选



可按以下条件筛选：



```text

成功撤离

失败

放弃

指定地图

指定难度

完成委托

未完成委托

获得唯一藏品

新增图鉴

击败 Boss

高价值回收

特殊事件

```

\## 8. 红点与新增提示



本局结算报告确认后，相关系统通过红点或角标提示新增内容。



允许出现红点的系统：



```text

仓库：新增物品

图鉴：新增条目

研究：新增可解锁 / 研究完成

任务：可领取

成就：新完成

回收资历：升级 / 奖励可领取

收藏 / 外观：新展示内容

历史战绩：新战绩未查看

```



不建议出现红点的情况：



```text

仅仅可以消费金币

仅仅可以抽奖

没有实际新增内容

玩家已经查看过的内容

隐藏成就未完成

```



红点应可清除。

\## 9. 事件驱动资产流通原则



通用资源与物品应通过统一事件流通。



各系统可以产出、消耗、读取资产变化，但不应越权执行其它系统功能。



推荐原则：



```text

结算系统负责生成本局结果

仓库系统负责显示当前拥有物

图鉴系统负责显示记录与文案

研究系统负责功能解锁

任务系统负责长期目标

委托系统负责单局目标

抽奖系统负责抽取行为

历史战绩负责保存结果快照

```



系统之间可以通过事件和跳转连接。



例如：



```text

抽奖获得唯一藏品

↓

发出获得物品事件

↓

仓库显示唯一藏品

↓

图鉴解锁条目

↓

收藏展示解锁展示入口

↓

历史记录保存获得来源

```



但仓库不执行抽奖，图鉴不执行研究，历史战绩不修改物品。

\## 10. 与其它系统的边界



\### 10.1 与仓库



仓库显示当前拥有物。

结算报告显示本局变化。

历史战绩显示过去结果快照。



\### 10.2 与图鉴



图鉴显示已发现 / 已拥有 / 已触发的内容。

结算报告只提示新增图鉴，不展开完整图鉴。



\### 10.3 与研究



研究管理功能解锁。

结算报告只提示新增研究条件或研究完成，不展开完整研究系统。



\### 10.4 与任务 / 成就



任务 / 成就管理长期目标。

结算报告只提示进度、完成、可领取状态。



\### 10.5 与委托



委托是本局目标。

结算报告显示本局委托完成或失败。

历史战绩保留该局委托记录。



\### 10.6 与抽奖



抽奖是独立功能。

抽奖产物可以进入仓库、图鉴、收藏展示。

历史战绩可以记录获得来源，但不负责抽奖行为。



\### 10.7 与收藏 / 外观



收藏 / 外观负责展示和配置。

唯一藏品可以解锁特殊展示或附属外观，但仓库不负责外观配置。

\## 11. 推荐流程



\### 11.1 成功撤离流程



```text

局内成功撤离

↓

结算摘要

↓

本局结算报告

↓

写入历史战绩

↓

写入仓库 / 图鉴 / 任务 / 成就 / 研究 / 资历变化

↓

对应系统显示红点

↓

玩家选择：

\- 返回主菜单

\- 前往出发探索

\- 前往仓库

\- 前往图鉴

\- 前往研究

\- 查看历史战绩

```



\### 11.2 失败流程



```text

局内失败

↓

失败结算

↓

失败抢救

↓

本局结算报告

↓

显示丢失 / 抢救 / 清空 / 保护结果

↓

写入历史战绩

↓

对应系统显示红点

↓

玩家选择后续去向

```



\### 11.3 放弃探索流程



```text

玩家放弃当前探索

↓

放弃确认

↓

按放弃规则结算

↓

本局结算报告

↓

写入历史战绩

↓

玩家选择后续去向

```

\## 12. 最低验收标准



该系统完成后，应满足：



```text

1\. 局内结束后能立即展示本局结算报告。

2\. 本局结算报告不属于仓库界面。

3\. 本局结算报告能显示成功 / 失败 / 放弃结果。

4\. 本局结算报告能显示黑币转金币或黑币丢失。

5\. 本局结算报告能显示带回物品、丢失物品、抢救物品。

6\. 本局结算报告能显示消耗品清空。

7\. 本局结算报告能提示仓库新增。

8\. 本局结算报告能提示图鉴新增。

9\. 本局结算报告能提示任务 / 成就 / 研究 / 资历变化。

10\. 本局结算报告能记录唯一藏品获得。

11\. 历史战绩能保存每局结果快照。

12\. 历史战绩不随当前仓库变化而改变。

13\. 历史战绩支持基础筛选和排序。

14\. 仓库通过红点和新增标记显示新增内容，而不是弹出结算报告。

15\. 结算报告允许跳转相关系统，但不重复实现相关系统功能。

```

\## 13. 待确认事项



后续仍需确认：



```text

1\. 本局结算报告正式名称。

2\. 历史战绩正式名称。

3\. 历史战绩放在长期系统哪个模块下。

4\. 历史战绩是否需要作为独立一级标签。

5\. 本局结算报告与结算摘要是否合并。

6\. 失败抢救流程是否在结算报告前还是报告内完成。

7\. 唯一藏品获得展示规格。

8\. 历史战绩保留数量上限。

9\. 历史战绩是否支持收藏 / 标记重点记录。

10\. 历史战绩是否显示完整行动日志。

11\. 红点清除规则。

12\. 战绩详情是否允许导出或分享。

13\. 放弃探索的结算规则。

14\. 委托失败后历史战绩如何显示。

15\. 是否显示物品后来是否仍在仓库中。

```
