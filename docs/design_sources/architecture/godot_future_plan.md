# 《灰尾回收 / 五四三二一》Godot 正式独立版未来策划案

> 文档定位：Godot 正式独立游戏版本的未来拓展策划案
> 适用范围：原 Lua 原型后续重构、Godot 独立版开发、正式版内容扩展
> 核心方向：扫雷式情报判断 + 房间探索 + 搜打撤撤离 + 肉鸽规则变异 + 局外长期成长
> 技术定位：以 Godot 作为正式独立版主要开发引擎，采用像素风 2D / 2.5D 表现

---

## 1. 项目定位

《灰尾回收 / 五四三二一》Godot 正式版是一款以**扫雷式情报推理**为核心的撤离型肉鸽探索游戏。

玩家在一张由房间组成的地图中探索。每个房间对应小地图上的一个格子，玩家需要根据小地图数字判断周围雷房分布，在有限生命、压力、背包容量和撤离机会下，选择继续探索、收集物资，或在找到撤离点后及时撤离。

本作的长期目标不是单纯做“地牢 + 扫雷 + 背包”的拼接，而是围绕以下核心体验建立完整游戏循环：

```text
读取情报
判断风险
选择路线
处理房间
积累物资
承受压力
获得撤离权
决定撤离或继续贪
将收益转化为局外成长
```

---

## 2. 核心玩法循环

### 2.1 单局循环

一局游戏的基础流程如下：

```text
选择地图 / 难度 / 带入物
↓
生成地图、雷房、事件、宝箱、怪物、撤离点
↓
玩家从起点开始探索
↓
通过小地图数字判断风险
↓
进入房间并处理房间内容
↓
积累物资、BUFF、藏品、金币、任务进度
↓
找到撤离点，获得撤离权
↓
选择立即撤离或继续探索
↓
成功撤离 / 撤离失败
↓
结算物资、图鉴、任务、成就、金币、研究进度
```

---

### 2.2 长期循环

局外长期循环如下：

```text
撤离带出资源
↓
出售 / 存入仓库 / 图鉴收录 / 研究
↓
购买带入物 / 解锁局外天赋 / 遗物修复 / 接取委托
↓
解锁新地图、新事件、新藏品池、新难度
↓
挑战更高风险地图
↓
获得更稀有藏品与成就
```

正式版应让玩家始终有以下几类目标：

| 目标类型     | 对应系统            |
| -------- | --------------- |
| 我想赚更多资源  | 撤离、宝箱、怪物、事件     |
| 我想补全收藏   | 藏品、图鉴、遗物修复      |
| 我想挑战高难   | 地图难度、委托、成就      |
| 我想尝试新构筑  | 技能、道具、局外天赋      |
| 我想理解更多规则 | 图鉴、研究、任务引导      |
| 我想消耗多余金币 | 遗物修复、高难门票、研究、黑市 |

## 3. Godot 版本表现方向

### 3.1 美术风格

Godot 正式版建议采用：

```text
像素风 2D / 2.5D 俯视角
```

表现特征：

* 角色使用像素风 Sprite；
* 怪物、NPC、宝箱、撤离装置使用 Sprite 或 AnimatedSprite2D；
* 房间使用 TileMap、Sprite2D、Parallax、简单 2.5D 层级表现；
* 小地图、背包、图鉴、任务、结算使用 Godot Control UI；
* 场景氛围通过光照、屏幕震动、粒子、Shader、音效强化；
* 不要求完整 3D 化；
* 不追求写实，而追求清晰、稳定、可读、可扩展。

---

### 3.2 Godot 场景结构方向

Godot 版建议以 Scene / Node 组合组织内容。

基础场景建议：

```text
Main.tscn
RunScene.tscn
RoomScene.tscn
MiniMap.tscn
HUD.tscn
InventoryPanel.tscn
CodexPanel.tscn
TaskPanel.tscn
RelicRepairPanel.tscn
ResultPanel.tscn
```

核心原则：

> 玩法数据与表现节点分离。
> 地图真相、玩家情报、背包、压力等核心状态不直接写在 UI 节点中。

## 5. 地图与难度体系

### 5.1 地图尺寸

正式版可采用三档基础地图尺寸：

| 地图尺寸  | 定位      | 作用              |
| ----- | ------- | --------------- |
| 7×7   | 教学 / 入门 | 低压体验，帮助玩家理解基础机制 |
| 10×10 | 标准局     | 正式版核心玩法展示       |
| 13×13 | 中后期     | 高复杂度、高信息量、高风险挑战 |

---

### 5.2 撤离点数量

撤离点是玩家获得成功撤离权的关键。不同地图和难度可通过撤离点数量控制强制探索长度。

建议配置：

| 地图       | 难度    | 撤离点配置     |
| -------- | ----- | --------- |
| 7×7 简单   | 教学    | 1 个可见撤离点  |
| 7×7 普通   | 入门    | 1 个不可见撤离点 |
| 10×10 简单 | 低压标准局 | 3 个不可见撤离点 |
| 10×10 标准 | 主展示   | 2 个不可见撤离点 |
| 10×10 困难 | 高压标准局 | 1 个不可见撤离点 |
| 13×13 普通 | 大图普通  | 4 个不可见撤离点 |
| 13×13 困难 | 大图高压  | 2 个不可见撤离点 |
| 13×13 地狱 | 高失败挑战 | 1 个不可见撤离点 |

---

### 5.3 标准局建议配置

Godot 正式版早期标准局可采用：

```text
地图：10×10
雷房：20
事件房：10
宝箱房：10
怪物房：10
不可见撤离点：2
起点：1
普通房：47
```

该配置定位为：

> 标准偏难，但适合展示本作完整核心循环。

其特点：

* 玩家不能盲走；
* 玩家必须理解小地图数字；
* 玩家大概率能在一局内遇到宝箱、怪物、事件；
* 玩家较大概率能在死亡前发现撤离点；
* 玩家能体验到“发现撤离点后是否继续探索”的搜打撤张力。

---

## 6. 撤离权系统

### 6.1 撤离点的核心定位

撤离点不是普通终点，而是：

> 成功撤离权的解锁事件。

在发现撤离点前，玩家不能主动成功撤离。
发现撤离点后，玩家才可以选择：

```text
立即撤离
或
继续探索
```

---

### 6.2 两阶段体验

#### 阶段一：撤离点未发现

玩家处于强制探索阶段。

核心问题：

```text
我能否活着找到撤离点？
```

玩家需要：

* 解读雷数；
* 控制血量；
* 避开雷房；
* 处理房间收益；
* 尽快发现撤离点。

#### 阶段二：撤离点已发现

玩家进入撤离决策阶段。

核心问题：

```text
我现在撤，还是继续贪？
```

玩家需要评估：

* 当前背包价值；
* 剩余生命值；
* 压力等级；
* 周围未知风险；
* 是否还有任务目标；
* 是否值得继续探索。

---

### 6.3 撤离点扩展类型

未来可扩展：

| 撤离点类型 | 特点              |
| ----- | --------------- |
| 普通撤离点 | 发现后可直接撤离        |
| 可见撤离点 | 教学模式中提前显示       |
| 条件撤离点 | 需要钥匙、事件、物品或击败守卫 |
| 临时撤离点 | 由技能、道具或事件生成     |
| 污染撤离点 | 需要净化后使用         |
| 守卫撤离点 | 撤离前触发战斗或逃跑      |
| 延迟撤离点 | 启动后等待倒计时        |

## 7. 小地图与情报系统

### 7.1 基础规则

玩家房间移动为四向移动，但小地图雷数按 8 邻域计算。

```text
玩家可移动方向：上、下、左、右
雷数统计方向：左上、上、右上、左、右、左下、下、右下
```

只有雷房计入雷数。

不计入雷数：

* 怪物房；
* 宝箱房；
* 事件房；
* 撤离房；
* 普通房；
* NPC 房。

---

### 7.2 TruthMap 与 IntelMap

Godot 正式版必须保持：

| 层          | 含义                     |
| ---------- | ---------------------- |
| TruthMap   | 真实地图，记录真实房间、雷、撤离点、状态   |
| IntelMap   | 玩家已知情报，记录数字、标记、可见性、可靠性 |
| MiniMap UI | 根据 IntelMap 展示给玩家      |

UI 不应直接读取 TruthMap。

该设计可支持未来：

* 欺骗数字；
* 过期情报；
* 移动雷；
* 多人信息差；
* 扫描与校准。

---

### 7.3 情报可靠性

未来可加入：

| 情报状态 | 含义           |
| ---- | ------------ |
| 准确   | 显示数字等于真实雷数   |
| 偏移   | 数字可能 +1 或 -1 |
| 失真   | 数字受区域规则影响    |
| 过期   | 雷场变化后旧情报失效   |
| 未确认  | 需要校准         |
| 隐藏   | 暂时不可见        |
| 污染   | 受特殊地图规则影响    |

示例：

```text
污染区中，所有数字可能 +1。
```

```text
移动雷触发后，旧数字显示为过期。
```

---

### 7.4 标记系统

基础标记：

* 疑似雷；
* 安全；
* 待探索；
* 撤离方向；
* 宝箱目标；
* 怪物警告；
* 自定义标记。

标记系统可通过局外成长扩展：

* 增加标记数量；
* 解锁高级标记；
* 自动提示冲突标记；
* 多人共享标记；
* 情报可靠性标记。

## 8. 雷房与雷场系统

### 8.1 基础雷房

基础雷房规则：

* 雷房计入雷数；
* 首次进入扣除生命；
* 雷房触发后显示在小地图；
* 已触发雷房不再重复造成伤害；
* 雷房不与怪物房、宝箱房、事件房、撤离房重叠。

雷房是确定风险。

怪物房是可被战斗力转化为收益的风险。

二者应保持设计区分。

---

### 8.2 特殊雷房

未来可扩展：

* 毒气雷房；
* 电流雷房；
* 爆炸雷房；
* 连锁雷房；
* 黑暗雷房；
* 伪装雷房；
* 延迟触发雷房；
* 压力雷房；
* 可拆解雷房；
* 高收益雷房。

Godot 版可通过 RoomDef + HazardTag 实现：

```text
Room.Mine + Hazard.Poison
Room.Mine + Hazard.Dark
Room.Mine + Hazard.Explosive
```

---

### 8.3 真扫雷雷房

部分雷房进入后不直接扣血，而是触发房间内小型扫雷挑战。

规则示例：

```text
进入特殊雷房
↓
房间内部出现小型拆雷谜题
↓
成功则安全通过或获得奖励
↓
失败则受到雷伤
```

该系统可作为正式版中后期内容。

---

### 8.4 动作躲避雷房

部分雷房可变成动作挑战：

* 爆炸倒计时；
* 毒雾扩散；
* 机关躲避；
* 黑暗追逐；
* 限时逃脱；
* 移动危险区。

这类房间适合 Godot 2D / 2.5D 表现。

---

### 8.5 移动雷

未来高级地图可引入移动雷。

移动雷触发条件：

* 每探索若干未知房；
* 压力等级降低；
* 事件房触发；
* 特殊地图模式；
* 玩家主动技能。

移动雷必须与情报可靠性绑定。
否则玩家会觉得信息失真是不公平的。

Godot 正式版应逐步深挖房间内部布局。

* 宝箱位置；
* 怪物出生点；
* NPC 位置；
* 陷阱；
* 机关；
* 互动终端；
* 撤离装置；
* 光照；
* 迷雾；
* 房间尺寸差异；
* 特殊地形。

房间布局影响：

* 怪物逃跑难度；
* 宝箱获取路线；
* 雷房操作挑战；
* 战斗站位；
* 撤离安全性；
* 技能使用空间。

## 10. 怪物、逃跑与战斗系统

### 10.1 基础怪物规则

怪物房不计入雷数。

基础规则：

```text
进入怪物房
↓
显示怪物强度
↓
玩家可选择逃跑或战斗
↓
逃跑成功：返回上一房间，不获得奖励
↓
逃跑失败：进入战斗
↓
战斗力 ≥ 怪物强度：击败怪物
↓
战斗力 < 怪物强度：扣除差值生命
```

---

### 10.2 逃跑机制

怪物房逃跑是本作很有潜力的动作元素。

可设计为：

```text
玩家进入怪物房后，需要在怪物接近前回到来时门并交互。
```

影响逃跑的因素：

* 怪物速度；
* 房间布局；
* 玩家移动速度；
* 压力等级；
* 道具效果；
* 技能效果；
* 房间障碍。

---

### 10.3 正式战斗扩展

未来可加入：

* 主动技能；
* 敌人机制；
* 状态效果；
* 冷却；
* 闪避；
* 控制；
* 精英怪；
* Boss；
* 怪物图鉴弱点；
* 战斗奖励池。

战斗系统定位：

> 将部分风险转化为收益的房间处理方式。

战斗不应取代小地图推理。

## 11. 技能与能力系统

技能应服务整个探索循环，而不只是战斗。

### 11.1 情报技能

* 扫描一个格子；
* 校准一个数字；
* 显示某格是否为雷；
* 显示撤离方向；
* 清除数字失真；
* 标记推荐；
* 显示情报可靠性。

### 11.2 雷场技能

* 移动一个雷；
* 拆除一个雷；
* 提前引爆；
* 交换两个格子；
* 雷伤免疫一次；
* 将雷房转化为普通房。

### 11.3 移动技能

* 跳格移动；
* 斜向移动；
* 传送；
* 回撤；
* 穿越危险房；
* 临时开门。

### 11.4 战斗技能

* 提升战斗力；
* 临时护盾；
* 眩晕怪物；
* 降低怪物强度；
* 反击；
* 短时间免伤。

### 11.5 撤离与背包技能

* 紧急托运；
* 保护一个物品；
* 失败多保留一件；
* 临时扩大背包；
* 撤离点感应；
* 降低高价值物资压力。

---

## 12. 移动规则系统

### 12.1 基础移动

基础规则：

```text
房间内自由移动；
房间之间通过上下左右四门移动。
```

---

### 12.2 已探索区域快速通行

Godot 正式版应保留快速通行机制。

规则：

```text
玩家可在已探索且可通行房间之间快速移动；
不能直接传送到未知房间；
不能绕过未知风险；
主要用于减少重复跑图疲劳。
```

---

### 12.3 扩展移动规则

未来可加入：

* 跳格移动；
* 斜向移动；
* 蜂窝六向移动；
* 回撤；
* 传送信标；
* 相位移动；
* 钩索；
* 冲刺。

移动规则变化会直接改变扫雷判断和撤离路线，因此应作为构筑系统的重要组成。

---

## 13. 五四三二一协议与压力系统

### 13.1 压力来源

压力可来自：

* 探索未知房；
* 踩雷；
* 击败或处理怪物；
* 开启宝箱；
* 触发事件；
* 使用强力技能；
* 携带高价值藏品；
* 长时间未撤离；
* 高难地图规则。

---

### 13.2 压力影响

压力可影响：

* 雷房伤害；
* 怪物强度；
* 宝箱收益；
* 事件风险；
* 情报可靠性；
* 撤离点可用性；
* 移动雷出现；
* 房间光照；
* 追击强度。

示例：

```text
Pressure ≥ 80 后，继续探索未知房额外扣除生命。
```

未来可扩展为：

```text
压力越高，宝箱收益越高，但小地图数字越不稳定。
```

```text
协议 1 状态下，移动雷开始出现。
```

---

### 13.3 压力系统定位

压力系统不应只是倒计时惩罚，而应是风险收益调节器。

低压力：

* 适合探索；
* 信息稳定；
* 风险较低。

高压力：

* 奖励可能更高；
* 环境更不稳定；
* 玩家更需要考虑撤离。

---

## 14. 事件房与规则变异

### 14.1 普通事件

事件可包括：

* 治疗；
* 交易；
* 修理；
* 购买情报；
* 托运；
* 换金币；
* 增减压力；
* 获得 BUFF；
* 牺牲物品换奖励。

---

### 14.2 规则变异事件

事件房可以改变本局规则。

示例：

```text
普通房增加压力，踩雷减少压力。
```

```text
宝箱奖励翻倍，但开宝箱增加压力。
```

```text
怪物掉落提高，但怪物强度提高。
```

```text
小地图数字可能 +1。
```

```text
每次快速通行都会增加压力。
```

这类事件能提供肉鸽变化，使每局节奏不同。

---

## 15. 物资、背包与搜打撤经济

### 15.1 物资分类

| 类型       | 作用           |
| -------- | ------------ |
| 局内 BUFF  | 当局有效         |
| 消耗品      | 局内使用         |
| 可带出物     | 撤离后转化为收益     |
| 藏品       | 出售、图鉴、研究     |
| 初始带入物    | 开局提供基础属性或能力  |
| 高价值负面物   | 高收益，但增加压力或风险 |
| 任务物 / 样本 | 解锁研究、地图或事件   |

---

### 15.2 背包系统

正式版可加入：

* 背包容量；
* 物品大小；
* 安全箱；
* 托运；
* 物品保护；
* 丢弃；
* 分解；
* 高价值物资压力。

背包系统的目标是：

> 让玩家在“继续装更多东西”与“及时撤离保住已有收益”之间做取舍。

---

### 15.3 成功撤离

成功撤离时：

* 初始带入物不损失；
* 本局获得物全部带出；
* 局内 BUFF 清除；
* 藏品进入图鉴或仓库；
* 可出售物转化为金币；
* 任务与成就进度结算。

---

### 15.4 撤离失败与保底

失败时，玩家从：

```text
初始带入物 + 本局获得物
```

中选择部分保留。

可扩展：

* 安全箱保留；
* 失败多保留一件；
* 保险；
* 托运；
* 指定物品保护；
* 局外天赋强化保底。

失败保底应保持搜打撤风险感，但避免完全挫败。

---

## 17. 遗物修复 / 黑市回收系统

### 17.1 系统定位

遗物修复系统用于：

* 消耗后期金币；
* 提供长期收集目标；
* 补充特殊藏品来源；
* 连接图鉴、任务、成就和高难地图。

该系统不建议直接包装成“抽卡”，而应使用世界观表达：

```text
遗物修复
黑市回收
异常藏品解码
封存物资开封
```

---

### 17.2 基础规则

```text
玩家消耗金币购买修复次数；
每次修复从对应藏品池中随机获得奖励；
获得重复藏品时，转化为修复残片；
修复残片可兑换指定藏品或研究材料；
部分特殊藏品仅能通过遗物修复获得；
抽取专属藏品不阻断主线进度；
抽取专属藏品不提供过强数值优势。
```

---

### 17.3 奖励类型

* 普通藏品；
* 稀有藏品；
* 遗物修复专属藏品；
* 藏品碎片；
* 图鉴研究材料；
* 高难地图线索；
* 外观奖励；
* 轻量机制类局外藏品；
* 修复券；
* 黑市凭证。

---

### 17.4 遗物池类型

| 池类型   | 作用             |
| ----- | -------------- |
| 基础回收池 | 消耗少，产出普通藏品和碎片  |
| 主题藏品池 | 对应不同场景主题       |
| 高级异常池 | 后期高金币消耗，产出稀有藏品 |
| 保底兑换池 | 使用碎片兑换指定藏品     |

---

### 17.5 设计限制

遗物修复不得成为核心通关门槛。

禁止方向：

* 抽取强力永久战斗属性；
* 抽取通关必要道具；
* 抽取关键剧情道具；
* 让核心系统只能通过随机获得；
* 出售真实货币随机资源。

推荐原则：

```text
遗物修复影响收集深度和局外目标，不决定玩家能否正常通关。
```

## 18. 任务与成就系统

### 18.1 系统定位

任务与成就系统用于：

* 前期引导；
* 中期目标；
* 后期挑战；
* 长期收集；
* 玩法精通记录。

关系：

| 系统   | 作用              |
| ---- | --------------- |
| 任务   | 引导玩家尝试机制，提供每局目标 |
| 成就   | 记录玩家精通程度，提供长期挑战 |
| 图鉴   | 记录发现与世界观        |
| 遗物修复 | 金币消耗与收集补完       |

---

### 18.2 任务类型

任务可包装为：

```text
回收委托
协议委托
调查指令
黑市订单
研究请求
```

类型：

| 类型   | 作用          |
| ---- | ----------- |
| 新手委托 | 教学与系统引导     |
| 常规委托 | 给每局提供目标     |
| 研究任务 | 推动图鉴与研究     |
| 高难挑战 | 引导玩家尝试高压玩法  |
| 黑市委托 | 连接遗物修复和稀有藏品 |
| 地图委托 | 引导玩家挑战不同地图  |

---

### 18.3 新手任务链

建议新手任务链：

```text
进入 3 个房间
查看小地图数字
标记 1 个疑似雷房
开启 1 个宝箱
找到撤离点
成功撤离 1 次
失败后保留 1 件物品
带出 1 件藏品
使用 1 次遗物修复
```

任务系统应承担自然教学功能，减少硬教程文本。

---

### 18.4 常规委托

示例：

* 本局带出 3 件物资；
* 打开 2 个宝箱；
* 击败 2 个怪物；
* 触发 1 个事件房；
* 在压力低于 60 时撤离；
* 在踩雷后仍然撤离；
* 找到撤离点后继续探索 5 个房间；
* 从 10×10 标准图带出稀有藏品。

---

### 18.5 成就类型

| 类型   | 示例              |
| ---- | --------------- |
| 进度成就 | 第一次撤离、累计撤离 10 次 |
| 技术成就 | 一局中正确标记 5 个雷房   |
| 撤离成就 | 只剩 1 HP 时撤离     |
| 收藏成就 | 完成一组藏品套装        |
| 压力成就 | 协议 1 状态下成功撤离    |
| 挑战成就 | 13×13 地狱成功撤离    |
| 遗物成就 | 通过修复获得传说藏品      |

---

### 18.6 ObjectiveSystem

Godot 正式版可统一任务和成就为 ObjectiveSystem。

监听事件：

* 进入房间；
* 踩雷；
* 开宝箱；
* 击败怪物；
* 触发事件；
* 找到撤离点；
* 成功撤离；
* 撤离失败；
* 获得藏品；
* 使用遗物修复；
* 解锁图鉴；
* 达到压力等级。

结构：

```text
ObjectiveSystem
├─ TaskDef
├─ AchievementDef
├─ ObjectiveCondition
├─ ObjectiveReward
└─ ObjectiveProgress
```

任务与成就共享条件系统，但表现和奖励不同。

## 23. 主要风险与控制

* P0 只做核心闭环；
* P1 再做局外系统；
* P2 才做复杂房间与技能；
* P3 才做大型模式扩展。

---

### 23.2 金币系统后期疲软

控制方式：

* 遗物修复；
* 高难地图门票；
* 黑市委托；
* 图鉴研究；
* 外观收集；
* 藏品套装；
* 稀有池保底兑换。

---

### 23.3 抽取系统喧宾夺主

控制方式：

* 不出售真实货币随机资源；
* 抽取专属内容不阻断主线；
* 抽取内容偏收藏和轻机制；
* 核心玩法收益仍来自局内探索。

---

### 23.4 规则复杂导致玩家看不懂

控制方式：

* 任务系统承担前期引导；
* 图鉴解释规则；
* 小地图 UI 强调可靠性；
* 行动日志解释伤害和压力来源；
* 低难地图逐步引入机制。

---

### 23.5 Godot 工程逐渐耦合

控制方式：

* TruthMap / IntelMap 分离；
* UI 只读 ViewModel；
* 内容使用 Resource / JSON；
* 任务成就统一 ObjectiveSystem；
* 事件、技能、道具统一通过 EffectSystem；
* 长期规则变化通过 ModifierSystem。

---

## 24. 总结

Godot 正式版的长期方向是：

> 用轻量、清晰、可数据化的 2D / 2.5D 架构，承载一个以扫雷情报推理为核心的撤离型肉鸽独立游戏。

未来所有扩展都应围绕六条主线：

| 主线    | 核心问题           |
| ----- | -------------- |
| 情报线   | 我看到的信息是否可信？    |
| 风险线   | 我愿意承担多大风险？     |
| 撤离线   | 我何时获得退路，何时收手？  |
| 构筑线   | 我用什么能力解决问题？    |
| 经济线   | 我带什么出去，失败损失什么？ |
| 长期目标线 | 我下一局为什么还想继续玩？  |

Godot 版的开发重点不应是堆砌复杂系统，而应逐步建立：

```text
核心闭环
↓
数据化内容
↓
局外成长
↓
规则变异
↓
高难地图
↓
长期收集与挑战
```

最终目标是让玩家在每一局中都围绕：

```text
看懂信息
承担风险
获得收益
发现撤离
选择是否继续贪
带出长期价值
```

形成稳定而持续变化的决策体验。
