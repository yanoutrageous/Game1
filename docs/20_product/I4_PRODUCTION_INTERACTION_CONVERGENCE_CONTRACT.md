# I4 生产交互收敛与可复现验证基线契约

文档状态：`ACTIVE / PLAN_AUDIT`

授权时间：2026-07-30

授权来源：用户明确要求完成“计划审计 → 计划执行 → 完成测试 → 阶段审计 → PUSH”全过程。

## 1. 阶段定位

I4 继续属于 I 线。它不扩充地图、物品、怪物、委托或长期成长内容，而是把当前
生产内容收敛成操作自然、信息语义一致、调试不污染正式档、失败可重复复现的稳定基线。
I4 关闭后，新增内容应另行授权为 M 线或其他增量阶段。

I4 的单一目标是：

> 在不改写实例级物品、结算与保存权威的前提下，让玩家以最少必要操作完成出发、
> 携带、购买、出售、长期系统与局内物品管理，并让每一次调试和生产验证都具有隔离、
> 确定性和可审计证据。

## 2. 入口冻结

```text
i4_entry_commit=4127bd27a05b75cb5e3071cf6dc87d9287f679a9
i4_entry_tree=e1455ffd8c7a754c63eb2141a47e41f8fe5cdf3a
i4_branch=codex/i4-production-interaction-convergence
i4_remote=origin
godot=4.6.3.stable.official.7d41c59c4
```

I3R 的机器证据和未完成外部验收保持历史原义。用户在实际生产画面上继续提出了
字体模糊、框体遮挡、摘要截断、信息错栏、数量交互缺失和操作链过长等反馈，因此 I3R
不得被回写为全面玩家验收通过。I4 明确接管这些开放反馈。

入口审计发现三份 Base 治理 CSV 在 Windows `core.autocrlf=true` 工作树中只因 CRLF
物化而触发 byte drift。I4.0 允许修复验证器的跨平台换行归一化，但仍必须对真实字段
差异 fail closed。

入口前已有 Godot 导入缓存和 `project.godot` 换行脏状态已保存到可恢复的 Git stash，
不得并入 I4 生产提交。

## 3. 冻结不变量

1. 当前 Godot 生产代码、数据和真实运行行为优先于旧截图、旧原型和旧文档。
2. 地图继续是 Deploy 同页双栏；不得退回“区域 → 难度”的分步页。
3. 普通 Deploy 页允许重新等分左右工作区；地图页保持自己的特殊比例。
4. 仓库、携带、局内物品与结算继续以精确实例 ID 为权威。
5. 数量聚合只属于展示与操作投影，不把存档迁移为单个 `quantity=N` 对象。
6. UI 不得成为金币、实例、结算、保存或运行阶段的第二权威。
7. 可撤销选择立即生效；不可逆交易只做一次最终确认。
8. 品质不能只靠颜色表达；颜色必须与边框、形状或自然语言冗余。
9. 调试入口只在 debug/editor 环境出现；修改状态的调试不得写入默认生产档。
10. 当前 6 个长期系统模块、25 个生产页面和 58 个运行资产保持内容冻结。
11. `project.godot`、scene、resource、`.uid`、`.translation` 和 import metadata
    只有在具体门登记后才允许修改或暂存。

## 5. 数量交互合同

| 上下文 | 卡片数量 | 生效方式 |
| --- | --- | --- |
| 携带 | `− 已携带/持有 +` | 立即修改可撤销的出发草稿 |
| 购买 | `− 本次购买 +` | 一次确认后原子生成 N 个实例并保存一次 |
| 出售 | `− 待出售/可售 +` | 一次确认后原子出售精确实例集合 |
| 固定 0/1 申领 | 状态文案 | 不显示无意义步进器 |

同一张卡片一次只能显示一种数量含义。购买和出售卡片可以显示单价，但余额、总价和
交易后余额只在当前交易上下文的汇总/动作区域显示。

## 6. Deploy 信息合同

- 普通物品卡只保留两行：名称；类别/单价/当前上下文数量。
- 玩家层不显示 `T1/T2`；详情允许显示“普通、优良、稀有、史诗”等自然语言。
- 普通页面在 632 宽工作区内使用 310 / 12 / 310；地图页保留 198 / 424。
- 详情正文和右侧摘要均必须可滚动，不得固定截断为四行。
- 摘要语义固定为：
  - 速览：地图、难度、目标、容量、出发阻塞；
  - 携带：全部装备、消耗品、数量和容量；
  - 本局：当前装备、天赋、协议和补给效果；
  - 目标：条件、奖励、进度和适用性。
- 金币仅在购买、出售等交易上下文出现。
- 快速出售保留“全选可售 / 清空 / 一次确认”，不得逐件确认。

## 7. 调试与可复现合同

- 设置中提供 debug/editor-only 的“开发与测试 → 进入测试场”。
- 只能从主菜单进入，强制使用独立 `dev_sandbox` profile。
- 测试场复用真实 `RunScene`、真实命令、真实 UI 和真实结算边界。
- 第一个修改状态的调试命令将会话标记为 `TAINTED`。
- `TAINTED` 会话禁止向默认 profile 提交结算。
- 可见标识必须包含 debug、taint、profile、scenario、seed 和 save target。
- 失败包必须包含 commit、场景、种子、输入索引、焦点、模态栈、前后保存、日志、
  截图和精确复现命令。
- 关键 runner 等待语义状态或信号，不使用固定帧数替代状态成立。

## 8. 字体与可访问性合同

- 像素字体只用于短标题、短按钮和 HUD 数字，并使用验证过的原生字号/整数栅格。
- 正文、详情、帮助和 tooltip 使用可读 CJK 字体及正文抗锯齿。
- 字号来自语义 token；不得由单页任意指定。
- 品质、焦点、选中和危险状态使用不同视觉通道。
- 文本必须处于纹理安全内容区；大型与紧凑按钮使用不同九宫格合同。
- 1280×720、1366×768、1600×900、1920×1080 与 UI 100/125/150%
  均不得出现遮挡、裁切、不可达滚动或焦点丢失。

## 9. 验证与关闭

I4 只有同时满足下列条件才能关闭：

1. 需求矩阵每项均为 `IMPLEMENTED_AND_VERIFIED`、`REJECTED_WITH_EVIDENCE`
   或 `EXPLICITLY_DEFERRED`，且本契约硬要求不得 defer。
2. 定向交易、保存隔离、Deploy、局内、长期系统、字体和输入门通过。
3. 每个关键确定性场景连续通过 10 次，其中至少 3 次来自新进程。
4. 完整局外生产旅程连续通过 3 次。
5. 默认生产档在全部 sandbox 调试前后语义哈希一致。
6. 旧存档可读；购买/出售/结算失败均精确回滚。
7. 视觉矩阵完成自动几何检查和动态人工复核。
8. 鼠标键盘、物理手柄、音频、目标 GPU 和长局边界分别记录。
9. worktree full、提交后的 exact-head/full 和远端 SHA 一致。
10. 最终 diff 不含未知 dirty 或未授权 Godot metadata。

## 10. 停止条件

- 调试写入默认生产档或 tainted 结算穿透。
- 批量购买/出售出现部分扣款、部分实例或无法回滚。
- 同名但不同语义实例被错误聚合。
- UI 绕过领域权威直接修改金币、实例或保存。
- 固定帧等待继续承担关键状态正确性的证明。
- 可见文本仍发生遮挡、不可滚动截断或仅靠颜色传达关键品质。
- 未经门登记修改受保护的 Godot scene/resource/project/import/translation 文件。

## 11. 非目标

- 新增玩法内容、完整经济重平衡或新的美术阶段。
- 重写 RunScene、迁移 UE、运行时骨骼生成或全项目 UI 推倒重做。
- active-run 跨进程恢复、导出、商店上架和正式发行认证。
- 用截图数量、静态 probe 或 headless PASS 代替动态玩家签收。
